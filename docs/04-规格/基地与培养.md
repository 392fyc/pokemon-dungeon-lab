# 基地与培养（阶段6.5 执行规格）

> **已取代**：现行内容见[游戏规则](../01-现行规则/游戏规则.md)（2026-10-31，#85）。细节公式、用户原话与当时依据仍以本页为准。

本页把[新伙伴入队状态与基地培养](../06-研究/玩法研究/新伙伴入队状态与基地培养.md)中"基地培养先用一条完整路径"一节，落成阶段6.5 可以直接实现和检查的规格。里程碑与通过条件见[阶段6计划](../02-进度/计划/阶段6—完整首版最小循环计划.md)。

本页只适用于远征模式；固定主图与各检查初态保持原样。所有数值和具体选择都是 Claude 主会话的**工作候选**，可以按试玩结果修改，不是最终玩法裁决。

## 要成立的循环

**出发 → 远征 → 正常撤离或全灭 → 回到基地 → 学习招式机、调整配招、选择队伍 → 再出发。**

判断它是否成立，看三件事：

1. 带回的招式机能让某只伙伴永久学会一招；
2. 下一局出发时，这一招确实可以使用；
3. 换下的伙伴保留自己学过的招式。

## 基地档案

基地档案（下称"档案"）跨局保存，和单局的 `World` 分开。它放在现有外层存档记录里，与当前试验、最近结束记录**在同一次写入中**更新。这样，结算和出发都不会只完成一半。

| 内容 | 规格 |
| --- | --- |
| 名册 | 每只伙伴一个实例：实例编号、物种、已学招式清单（招式、行为、最大 PP）、当前携带的招式。同一物种可以有多只，各自独立 |
| 携带上限 | 每只最多携带 **2 招**，且两招行为不同（工作候选）。研究原文写的是"最多四招"；本作的动作模型以行为区分招式，而现有画面与平衡都按两招设计，所以先取 2，并把这一处收窄记为待复盘项 |
| 仓库 | 招式机按招式计数，例如 `protect: 1` |
| 统计 | 已完成的远征次数，只作展示 |
| 初始档案 | 小火龙、杰尼龟、妙蛙种子三只御三家，按 roster 的初始招式组合（kit）学会并携带；仓库为空 |

## 招式机从哪里来

- 远征第 2 层的成果 T 改为"一张招式机"，招式从下表中抽取，用存档里的随机状态抽，恢复存档后不重抽：

  | 招式 | 本作行为 | 能学的首批物种（来自 roster 的可学清单） |
  | --- | --- | --- |
  | protect | 保护 | 9 种都能学 |
  | whirlwind | 推退 | pidgey、spearow、zubat |
  | roar | 推退 | charmander |

- 这样选的理由：6.2 已经确认，首批物种的升级招式里凑不出"牵制"和"调位"，御三家也都没有保护。上面三张招式机正好补上这两个缺口。
- 带出规则沿用现有终局记录：正常撤离时，取得的招式机进入仓库；全灭时显示"已取得、未带出"，不进仓库。

## 结算：回到基地

终局保存成功后，结果画面上原来的"开始独立试验"按钮改为"回到基地"，按下即完成一次写入：

1. **正常撤离**：把终局时仍在同行名单里的伙伴（包括倒下的）和本局此前回营的伙伴并入名册。
   - 新招募的伙伴成为新实例，按 roster 的初始组合登记已学与携带的招式。
   - 老伙伴保留原有的已学招式与携带配置，本局里的 HP、PP 和等级都不带回（方案 B：本局等级不转成永久成长）。
   - 带出的招式机进入仓库。
2. **全灭**：同行和此前回营的伙伴都按原有记录回到名册，不判走失，不扣伙伴；本局取得的东西全部不进仓库。走失、救援和失败经济留给阶段7。
3. 远征次数加 1；当前试验清空，最近结束记录换成这一局；进入基地画面。

## 基地画面上能做什么

| 操作 | 规格 |
| --- | --- |
| 查看名册 | 每只伙伴显示物种、已学招式与携带招式 |
| 学习招式机 | 选择一张招式机和一只**兼容**的伙伴（该招式在其物种的可学清单里），确认后这只伙伴永久学会，招式机减 1。已经学会的不能重复学；不兼容时说明原因，不消耗招式机 |
| 调整配招 | 免费、可反复调整。从已学招式中选最多 2 招，两招行为不同。换下的招式不删除，也不返还招式机 |
| 选择队伍 | 从名册中选 1 到 3 只出发，并指定其中一只为主控；队列顺序就是选择顺序 |
| 出发 | 免费的基本出发整备：所有出发成员的 HP、PP 全满。然后用这支队伍创建新远征（新种子），本局等级从 1 开始 |

基地画面里的每一次改动都要保存成功，才能继续下一步操作；保存失败的处理沿用现有的冻结与重试规则。

## 局内一次性休整

- 第 2 层入口附近放一个"休整点"，每局只能用一次。
- 主控在休整点上交互即生效，占一次行动：当前在场且未倒下的成员，每人选剩余比例最低的一招，恢复 2 PP，不超过上限。这里采用的是研究里"整理招式补给"那个选项。
- 如果没有任何可以恢复的 PP，就拒绝交互并说明原因，休整机会不会被消耗。
- "整理伤势"那个选项暂不提供，因为局内已经有橙橙果可以回复 HP。

## 存档与兼容

- 外层记录新增 `profile`，结构校验要覆盖：实例编号不重复，物种存在于 roster，已学招式都在该物种的可学清单里，携带的招式是已学招式的子集、最多 2 招且行为不同，招式机计数是非负整数。
- 没有 `profile` 的旧记录，第一次回到基地时从初始档案开始，不报错。
- 固定主图和检查初态的记录不会出现 `profile`，"开始独立试验"的行为保持不变。

## 验收

1. **规则测试**（字面预期）：
   - 正常撤离后，名册新增新人，招式机进入仓库；全灭时招式机不进仓库，伙伴都还在；
   - 学习招式机：兼容时成功并减少招式机；不兼容或已学时被拒绝且不消耗；
   - 调整配招：两招行为相同或选了未学的招式，都被拒绝；
   - 出发：成员 HP、PP 全满，并使用携带的招式；
   - 休整点只能用一次；PP 已满时拒绝且不消耗机会；
   - 档案在存档中往返后一致，篡改后被拒绝。
2. **浏览器检查**：用真实键鼠走完"远征 → 撤离 → 回到基地 → 学习招式机 → 配招 → 出发 → 新一局能用这一招"。为了测试稳定，允许用固定种子或检查入口把招式机直接放进仓库。
3. **玩家证据**：本阶段没有。这一步培养是否值得玩，留待体验者验证。

### 数据怎么存

- `Envelope.profile` 与 `current`、`recent` 在同一条记录里。`current` 在基地时为空；有 `profile` 时 `current` 只能是空或远征局。
- 档案：`expeditions`（远征次数）、`next`（下一个实例编号）、`roster`（实例：编号 `P1`…、物种、已学招式含行为与最大 PP、携带招式名）、`vault`（招式机计数）、`team`（出发顺序）、`leader`。
- 局内单位新增可选字段 `inst`（名册实例编号）与 `moves`（携带招式名，与 `learned` 对齐）。局内新招募的伙伴没有这两个字段，结算时成为新实例。
- `World.tm` 是 T 抽到的招式机；终局记录 `end.tm` 为 `{move, brought}`。无 `tm` 的旧记录照常读取。
- `dungeon.base: true` 标记“从基地出发的远征”。

### 工作候选（规格未定或需要补充处）

1. **队伍也进存档**：规格把“选择队伍”列为基地操作，且“每次改动都要保存成功”，所以 `team`、`leader` 存在档案里，每次加入、移出、改主控各写一次。初始队伍为 P1小火龙、P2杰尼龟、P3妙蛙种子，P3主控（与 6.4 的 A/B/C、C 主控一致）。
2. **携带可以为 0 招**：规格写“最多 2 招”，没有写下限，按字面允许 0 到 2 招；0 招的伙伴只用普攻。
3. **局内编号**：从基地出发时，局内编号仍按顺序用 A、B、C，主控由档案决定，队列顺序即选择顺序；实例编号只在 `inst` 里。
4. **招式机抽取**：T 被取得时用 `prog.rng` 抽一次，三种等概率；抽取结果写入 `World.tm`，恢复不重抽。它与招募抽取共用同一个随机流，因此同一种子里“取得 T”之后的招募结果与 6.4 不同。
5. **全灭时的新伙伴**：规格写“同行和此前回营的伙伴都按原有记录回到名册”。实现为：全灭时仍在同行或回营名单里的新招募伙伴也登记为新实例（倒下的也算）；与正常撤离的唯一区别是招式机不进仓库。
6. **旧记录**：没有 `profile` 的已结束远征，回基地时从初始档案开始；其 A/B/C 视为初始三只御三家（不重复登记），只有 N 编号的招募伙伴成为新实例。
7. **学习与配招的入口**：不兼容和已学会的招式机按钮仍可点击，由规则层拒绝并说明原因；招式机不消耗。配招用“携带／卸下”切换，要换同行为的招式须先卸下一招。
8. **休整点位置**：第 2 层出生房间里，离上楼梯最近的空格（并列取上方、再取左方）。休整只处理“在场且未倒下”的成员；没有可恢复时拒绝，说明原因，不消耗机会。占主控一次行动，敌方阶段照常进行。
9. **招式机显示名**：`保护`、`旋风（推退）`、`吼叫（推退）`，仅用于画面。

### 规格内的矛盾与保守处理

- **休整点与既有测试**：规格要求第 2 层有休整点，但既有测试 P8e 逐项固定了不经基地的远征第 2 层的点位（不含休整点），且不得改断言。保守处理：只有从基地出发的远征（`dungeon.base`）才生成休整点；用“开始探索 → 远征”直接开局的远征没有休整点。如果希望所有远征都有，需要同步修改该测试。
- **休整发生在哪里**：阶段6计划的 6.5 行写“回营时的一次性小额休整”，本页正文写成局内一次性休整。实现按本页正文（局内休整点）；基地里的出发整备只做 HP、PP 全满。

### 未验证项

- 没有用真实键鼠从零走完一整局到 T 再撤离（终局记录由检查入口预置；T 的抽取和终局字段由规则测试覆盖）。
- 未验证 Windows 原生应用，只验证了浏览器页面。
- 休整点没有动画（动画推断只识别既有日志行，不会误播）；休整点用几何占位绘制，没有专用素材。
- 基地画面是功能性占位，没有做小屏和视觉打磨；未做玩家试玩，培养是否值得玩仍待体验者验证。
- 同一种子下，取得 T 之后的招募抽取与 6.4 不同（见工作候选 4），未评估对平衡的影响。

**负责人决定（Claude 主会话，2026-10-30）**：接受“休整点只出现在从基地出发的远征里”。EA 的正式流程是从基地出发；开始页的直接远征入口在阶段7 的新游戏流程中移除或改造，届时再统一。审查另提的两点已处理：基地改动写失败时返回“已接受但未保存”（界面提示重试，不执行后续回调）；固定主图带档案的篡改用例改用真实的固定主图记录。
