# 决策登记

本页只登记现行的决策，一条一行：什么时候、谁决定、决定了什么、原文在哪里。被推翻的决策直接删除，以前的版本在 Git 历史里。[游戏规则](../01-现行规则/游戏规则.md)里每条规则末尾的编号（例如 D-20261030-31）指向这里。

**怎样读：**

- **编号**：`D-日期-序号`，序号在同一天内连续，跨主题表编号。编号一经登记不再改动，也不复用；删掉的编号空着。
- **决定者**：“用户”指用户本人的决定（原话、选项按钮或明确批准，原文见来源）；“main（工作值，用户可改）”指代理（主会话或 main lane）按授权自行定的取值或做法。代理的推导、对用户话的理解和补充细节都算 main，不写成用户决定。
- **现行不等于已实现**：尚未实现的在“决定”栏注明。
- **来源**：链接指向原文所在的 Issue、PR 或现行文档，后面写节号；原文所在文档已删除时，链接指向固定提交的永久链接。用户原话、选项说明和理由都留在来源里，本页不引用。仓库 `docs/` 以外的文件写代码路径。

**怎样维护：**

1. 有新决策时，在对应主题表里按日期追加一行，编号取当天下一个序号。
2. 新决策推翻旧决策时，在同一个 PR 里删除旧行，新行不写旧编号。只推翻一部分时，改写旧行，删掉被推翻的那部分。
3. 同时更新[游戏规则](../01-现行规则/游戏规则.md)中引用该编号的条目。
4. 用户原话写进对应 Issue 或 PR 正文，本页只写一句话的结论。

日期带 `*` 的条目：来源没有写具体决定日期，取最早记录它的文档日期，待确认。
