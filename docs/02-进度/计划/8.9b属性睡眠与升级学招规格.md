# 8.9b 属性相性、睡眠与升级学招式规格

## 1. 为什么做

属性克制和抵抗是宝可梦的底层逻辑，本作现在完全没有；异常状态里也缺睡眠。两件事都依赖招式真的进到敌我手里，而本作只有招式机一条学招路线，升级只加最大 HP（G6.5），每只伙伴又只带 2 招。所以这四件事一起做：属性相性、睡眠、升级学招式、携带上限 4 招。

平衡仍然暂缓（D-20261104-01），长测只记录，不作调整依据。蛋招式和招式教学放入 v0.2，本规格不做。

原版依据（Bulbapedia，2026-11-04 main 在浏览器核对）：[Status condition (Mystery Dungeon)](https://bulbapedia.bulbagarden.net/wiki/Status_condition_(Mystery_Dungeon))、[Rest](https://bulbapedia.bulbagarden.net/wiki/Rest_(move))、[Snore](https://bulbapedia.bulbagarden.net/wiki/Snore_(move))、[Sleep Talk](https://bulbapedia.bulbagarden.net/wiki/Sleep_Talk_(move))、[Damage modification (Mystery Dungeon)](https://bulbapedia.bulbagarden.net/wiki/Damage_modification_(Mystery_Dungeon))、[探险队招式机表](https://bulbapedia.bulbagarden.net/wiki/List_of_TM_and_HM_locations_in_the_Pok%C3%A9mon_Mystery_Dungeon_series)。

## 2. 属性相性

用户决定倍率按本传，不用探险队的 1.4／0.7。

- **倍率**：克制 ×2，抵抗 ×0.5，无效 ×0，双属性相乘（最高 ×4，最低 ×0.25，含无效则为 0）。
- **属性表**：现代 18 属性。本地快照没有属性表，要新增固定快照：取 Showdown 提交 `ccfaa20f` 的 `data/typechart.ts`，记 SHA，同步导入器固定哈希和[数据快照登记](../../05-制作流程/数据快照登记.md)。招式属性从 `src/render/move-types.json` 移到 `src/core` 也能读的位置。
- **本系加成**：招式属性是使用者属性之一时伤害 ×1.5（本传与探险队都是这个数；用户未给数值，先按 1.5）。
- **普攻**：没有属性，不吃相性和本系。没有属性数据的单位（`friend()` 夹具）或招式按 ×1。
- **G5.3 位置**：第 5 步之后新增一步：结果 × 本系 × 相性，四舍五入，结果大于 0 时最少 1；进入这一步时已经是 0 的不抬，相性为 0 时结果为 0。第 6 步的“否则最少 1”不把相性 0 抬回 1。G5.3 的例子按新公式重算。
- **判定次序**：先看相性和免疫，再判命中。伤害招式相性为 0，或纯变化招式的主效果被属性免疫、粉末、电磁波规则挡下，都算“无效”：不抽命中随机数，提示“没有效果”。
- **无效时**：不造成伤害，不触发附加效果、吸取、反作用、吹飞，不算受到伤害（不醒、不触发打鼾），也不算“命中目标”：所有目标都无效时，自降代价和“提高自己能力”的效果都不发生。PP 照扣。
- **变化招式**：不看相性（本传规则）。唯一例外是电磁波，打不中地面系（Showdown 里变化招式只有它 `ignoreImmunity:false`）。
- **粉末招式**：草系免疫 `flags.powder` 的招式，本作涉及催眠粉、麻痹粉、毒粉、蘑菇孢子。
- **属性免疫异常**（与本传一致，招式主效果和附加效果都算）：毒系、钢系不中毒和剧毒；火系不灼伤；冰系不冰冻；电系不麻痹。纯变化招式按上面的“无效”处理。伤害招式的附加效果被挡下时，伤害和命中不受影响，概率照抽（G5.15），只跳过这个异常并写日志，不提示“没有效果”。
- **不做的特例**：冷冻干燥对水系克制这类写在函数里的本传特例不做，按属性表算。
- **自动选招**：G4.6 的伤害估算用同一公式。相性为 0 的组合不进候选，撞墙加分（`engine.ts` 伤害候选里的 `score+=5`）也不能把它带回来。变化招式的“目标合法”要排除：属性免疫、已有该异常、粉末对草系、电磁波对地面系；睡眠招式再排除已在睡眠、打盹或出生睡着的目标。
- **提示**：攻击后写“效果绝佳”“效果不好”“没有效果”。招式说明里的“约 N 点”对当前目标要含相性。

## 3. 睡眠

- **新异常 `slp`**：3—6 轮，按 G5.13 的“被施加者自己的行动机会”递减。不能移动、攻击、用招式、用道具。已在睡眠或打盹时再中无效，不重新抽。其余异常可以共存。首领同样会中；G7.7 的“不睡”收窄为“不会出生睡着”。
- **被攻击醒来**：对方招式或普攻让 HP 真的减少时 25% 醒来（工作值，原版只写“有几率”）。中毒、灼伤掉血、同行误伤、吹飞撞击、反击反弹都不算，吹飞没撞墙、对方贴身也不醒（与出生睡着不同，这是有意的）。醒来后下一次行动照常。抽取用 G5.1 第 5 项的战斗随机流。
- **与出生睡着的关系**：“敌人出生时 25% 睡着”（G7）规则不变。出生睡着的敌人中了睡眠招式，转成 `slp`，清掉 `asleep` 与 `wakeSkip`，之后只按 `slp` 规则。
- **主控睡着**（规则层，`slp` 和打盹都算）：每轮仍是一条 `round` 命令，主控的动作固定为等待：收到其他动作一律按等待处理，G4.2 的“唯一伙伴干预”被拒绝。
- **主控睡着**（界面层，`slp` 和打盹都算）：底栏显示主控在睡觉，停留 0.6 秒后自动推进一轮；这段时间玩家可以按 Tab 切换操控。切到醒着的成员后恢复等待输入。全员睡着时同样自动推进。开发者和测试可以关掉自动推进。
- **解除道具**：新增零余果（治睡眠），治愈之种也治睡眠。打盹不是坏状态，这两样都不解除它。
- **伙伴优先解除**（用户决定）：当前主控在 `slp` 中且背包有零余果或治愈之种时，伙伴把这件事放在自己行动的最高优先级：相邻就用，优先零余果；不相邻就走向主控。伙伴自己不能行动时跳过。玩家切换主控后，对象也跟着变，只看当前主控。
- **换位**：睡着的同行可以被换位，与现行一致（G5.12）。
- **让对方睡着的招式**：催眠术、催眠粉、唱歌、蘑菇孢子、恶魔之吻。走 8.9 的 A3 模板，命中、PP、射程取探险队行。催眠粉、恶魔之吻是 `around` 射程；伙伴用 `around` 变化招式的目标错误由 PR #192 修复（bus #340 第 1 项），本规格依赖这个修复。
- **睡觉**：
  - 对自己使用，进入打盹 2—3 轮（`status` 里的 `nap`，不算坏状态，不在任何道具的解除清单里）。打盹期间不能行动，受伤不醒。
  - 结束时回满 HP、解除全部异常。换层清除时中止，不回复。本作没有强制叫醒的来源，不写这条分支。
  - HP 已满且没有异常时拒绝使用，不扣 PP。AI 把它归入 A7：自身 HP 不到一半或有坏异常时才用。
- **打鼾、梦话**：
  - 手动使用被 `invalid` 拒绝，不扣 PP。AI 的所有候选都排除这两招。
  - 触发条件：睡眠或打盹中的单位被对方招式或普攻让 HP 真的减少，先判醒来，没醒且还活着才触发。同时带着时只用打鼾（原版）。PP 为 0 不触发。带麻痹、畏缩时不触发（G5.13 这两种不能用招式）；混乱不影响，目标仍是攻击者。
  - 打鼾：对攻击者造成伤害，不看距离（原版“攻击者不在射程内也触发”），命中照常判定，扣 1 PP。原版的畏缩不做：触发发生在攻击者自己的行动里，畏缩会在这次行动结束时就解除，没有意义。
  - 梦话：从自身其余 PP 大于 0 的招式里随机选一招，排除睡觉、打鼾、梦话和以队友或全队为目标的招式；没有候选时不触发、不扣 PP。目标是攻击者，以自己为目标的招式对自己用，不看射程，命中照常判定。只扣梦话 1 PP，被调用的招式不扣。
  - 触发出来的招式不会再触发打鼾或梦话。随机用战斗随机流。
- **招式机池**：加入睡觉（TM44）和梦话（TM82），池版本升到 5，共十七种。打鼾只能靠升级学到。

## 4. 携带 4 招

取代 D-20261030-44 的 2 招上限（用户 2026-11-04 决定）。

- `src/core/base.ts` 的 `MAX_CARRY` 改为 4（`setCarry`、`instProblem` 都用它）。`save.ts` 的 `m.length>2` 属旧版世界校验，不改。`tests/browser/windows.mjs` 里“最多携带2招”的断言同步。旧档的 2 招仍然合法，空位留空。
- 营地配招和底栏招式格要能显示和使用 4 招，1280×720 与手机宽度都不挤压。按键 1—4 已按 `learned` 下标取招。
- 伙伴开局仍是 Lv5 的初始招式，175 种不变。

## 5. 升级学招式

- **数据**：`roster.json` 每个物种加 `levelUp`：`[{level,move,pp}]`，只收已准入、已实现的招式，取物种选定世代（`learnsetGen`）的 `L` 记录。`level` 为 1 的不收；`level` 为 0 的是进化时学的招式，保留。
- **G6.4 顺序**：经验 → 升级 → 学招式 → 进化（伊布选择）→ 进化后学招式 → 首领招式机 → 招募抽签。任何来源的升级都走同一流程，包括委托经验（`updateLevelsAfterCommissionReward`）。单分支进化（`findEvolutions`）和伊布选择后的路径都要接上“进化后学招式”。
- **规则**：同行全员（不含倒下者与已回营者）各自对照升级表，一次升多级时经过的每个等级都学。“已会”指当前带着的招式，已带的跳过。不满 4 招时直接学会，PP 满。满了弹窗让玩家选替换哪一招或放弃，不占回合；多个弹窗依次出现，用伊布选择的同一机制。关闭弹窗或按 Esc 等于放弃，不再询问。
- **进化后学招式**：用新物种的升级表，学 `level` 为 0 和等于当前等级的招式。
- **长测与无界面路径**：新招式有威力且高于当前最低威力时替换那一招（变化招式威力算 0，并列取靠前的），否则放弃。这是机器人的默认选择，不是规则。
- **只在本局有效**：不写入营地档案，下一局从出发时的招式开始。招式机学的招式照旧永久。
- **选招顺序（敌人和局内新同伴）**：升级表里等级不超过自身等级的招式，按（等级，招式 id）升序排列，取最后 4 个。不足 4 招时，按 `kit` 顺序取不重复的初始招式，补到 4 招为止，补的招式放在前面。`learned` 就按这个顺序。
- **局内新同伴**：在 `recruitUnit` 用上面的顺序带到当前队伍等级（G8.2）。结算后仍按 G8.5 成为带初始招式的新实例。
- **敌人**：普通敌人和挑战房敌人的生成处（不改 `speciesUnit`，`enemy()` 夹具依赖它）用上面的顺序。首领保持现有固定招式。BOSS 系列夹具走真实生成器，会跟着变；相性和睡眠规则对所有夹具都生效。
- **敌人用变化招式**（工作值，是 G4.6“方针与敌人共用”和 G5.11 的明文例外）：现有顺序下有伤害组合就不用变化招式，敌人几乎不会催眠。改为敌人能行动（`statusBlock` 之后）且存在合法的 A3 或 A1 候选时，先用战斗随机流抽 30%，抽中就按 A3 → A1 的顺序用第一个候选；没抽中或没有候选走 G4.6。自身强化、守住、回复不算。首领同样适用。伙伴不变。

- 世界和背包不入档，这次真正影响营地档案的是：携带上限 `MAX_CARRY`，仓库招式机校验 `ALL_TM_MOVES`（加睡觉、梦话）。

## 8. 验收

- 单元：相性倍率（克制、抵抗、无效、双属性 ×4 与 ×0.25）、本系、普攻不受影响、无效时全部目标不触发自降和附加效果、不抽命中、不醒；电磁波打地面系、草系挡粉末、四种属性免疫异常；AI 不选无效组合和免疫目标。
- 单元：伙伴能用催眠粉；睡眠的持续、再中无效、受伤醒来概率、出生睡着转 `slp`、主控等待、伙伴用道具与靠近、睡觉回满与换层中止、HP 满时拒绝、打鼾优先于梦话、PP 为 0 不触发、触发不递归、手动拒绝。
- 单元：升级学招式的不满直接学、满了替换与放弃、一次升多级、委托升级、进化后学招（单分支和伊布）、本局结束不入档、敌人选招顺序、首领不变、30% 的抽取与候选规则。
- 单元：旧档两种版本读入，2 招仍合法；175 种初始招式比对为 0 变化。
- 浏览器：真实输入完成一次升级学招弹窗、4 招显示与使用、主控睡着自动推进与切换、伙伴解除、相性提示，桌面与手机宽度各一次。
- Windows 全套检查与 600 局长测（只记录）；Linux 按多 lane 并行协作第 11 节复核，新建云任务前先问用户。
