# 自有 Pokémon Auto Chess 肉鸽 mod

用户确认曾开发自走棋肉鸽mod，仓库为[392fyc/pokemonAutoChess](https://github.com/392fyc/pokemonAutoChess)，fork自[keldaanCommunity/pokemonAutoChess](https://github.com/keldaanCommunity/pokemonAutoChess)。当前仅作为本作的素材、技能与系统参考；“自有”指用户参与开发的mod，不表示上游代码、精灵图或宝可梦知识产权归用户所有。发布经验另以[八款参考游戏](../跨项目/八款浏览器游戏参考与研究优先级.md)为来源。

## 本轮研究对象

2026-10-27 直接读取 GitHub 固定提交。主要对象是 `pve-mode` 的 **`3da223630f49893f5528e9cc7e6170befd28edec`**，其中已找到噩梦奖励、单体强化、Boss 与局内状态的实际代码。该分支包含 `feature/pve-mode` 的头提交，之后还有 32 个提交；默认 `master` 和 `feature/economic-roguelike-mode` 不能替代这一研究对象。分支身份、比较基点与具体源码位置见[来源与验证范围](资料来源与验证范围.md)。

这次选择依据是代码覆盖范围，不代表已确认用户实际部署的分支。未修改 mod 仓库，未安装依赖或运行游戏；以下结论是静态代码观察，不是完整功能审核或平衡结论。

## 已找到的实现与研究价值

| 实现 | 直接源码依据 | 对本作的具体价值 |
| --- | --- | --- |
| 分阶段奖励选择 | `NIGHTMARE_MILESTONES` 为 5、15、25、35；按阶段配置奖励等级权重，房间逻辑尝试生成最多三个选项，并限制每个槽位刷新一次 | 可研究如何把一次局内成长写成“出现条件、候选池、选择、应用、记录”完整流程。原阶段与概率只属于该 mod |
| 队伍效果与单体效果分开 | 奖励类型区分队伍被动、单体装备、经济与人数扩展；玩家状态分别保存已获奖励、待绑定单体奖励、候选项和计数器 | 本作可以分别讨论本局队伍增益与某名伙伴的个人培养，避免替换成员时连同无关队伍状态一起搬走 |
| 单体强化跟随实例 | `transformPokemon` 保存原实例 ID，并复制 `nightmareReward`、道具和部分持续成长；关联目标 ID 也参与维护 | 直接帮助梳理“改变形态、暂时离队、重新加入时，哪些数据属于同一名伙伴”。它仅证明这条变形路径，不能推成所有替换或存档路径均已正确 |
| 战斗事件触发成长 | 奖励模块复用攻击、受伤、击杀、死亡和周期效果。例：远程有效攻击累加玩家计数，达到阈值后增加后续使用的速度加成 | 可研究用统一事件表达成长，明确触发主体、计数归属、应用时点和清除条件；本作的回合与行动事件仍须单独定义 |
| Boss 配置与行为分开 | `PVEBossStage` 描述阵容、属性、能力、触发条件和奖励；第 49 阶段有超梦配置，房间创建 Boss 战斗并挂接噩梦效果 | 可以比较“普通敌人与守关敌人的差别”如何组织，避免只放大生命值。此处秒数和实时冷却不直接换算成本作回合 |

固定源码定位和行号集中在[证据表](资料来源与验证范围.md)。这些关联是面向本作的研究建议，尚未成为游戏规格。

## 需要分清的成长范围

当前读取到的 `nightmareRewards`、`nightmareCounters` 与单体绑定主要位于房间、玩家状态和战斗实体流程。它们足以支持讨论同一局内多场战斗之间的成长，以及变形时保留实例；本轮没有核实“结束一局 → 持久化保存 → 新一局重新载入”的完整链路。因此，源码或说明里的 permanent 不能在本研究中自动译为跨局永久培养。

对本作最值得先整理的是一张状态归属表：哪些属于本场战斗，哪些属于本次探险，哪些属于个人伙伴，哪些属于营地名册。用同一名伙伴依次经历变形、替出回营与下次出发，检查每类数据的去向。此方向连接[入队与基地培养](../../玩法研究/新伙伴入队状态与基地培养.md)和替换、携物与回营候选（归档：`docs/90-archive/审核版本/v0.7-2026-10-26/审核入口.md`），不预先替用户选择共享局内等级或永久个体等级。

## 本作怎样使用这份经验

1. **先研究已有奖励流程。** 选一个队伍奖励和一个单体奖励，沿配置、生成、选择、绑定、战斗触发与结束清理读取，形成可讨论的例子。重点是解释成长如何改变下一场选择，不先搬全部词条。
2. **再研究实例与成长的归属。** 把 mod 已处理的变形保留与本作要求的回营保留放在一起比较；继续补查跨局保存依据，不能把房间内同步当作持久化。
3. **保留玩法差异。** mod 中的人数购买、锁定单人和分身等效果有其自走棋用途；本作首版仍为三人同行。准备阶段结束时随机代选奖励的流程，也不直接用于本作“停下可思考”的行动推进回合。

依赖声明使用Phaser `^3.90.0`、React与Colyseus；本作已选Phaser 4。当前只借鉴系统划分与经验，不开展源码移植；依赖事实以固定提交的`package.json`为准，不从旧架构推导本作兼容性。
