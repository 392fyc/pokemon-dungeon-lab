# 本地研究库使用说明

## 进入顺序

先读README.md、项目框架/试开发准备包.md、项目框架/从研究到试开发的阶段路线图.md、项目框架/创作目标与地牢研究重点.md和市场研究/研究范围与双云分工.md，再读规则表、短规格及本包审核入口。PR #1—#3已合入main，研究基线为06cf1c0；PR #4准备包现以main为目标，32931fe已独立审核通过，后续补充按审核记录核对。

目标是个人可完成、能展示能力且玩家愿意玩的救援队/肉鸽地牢，不做自走棋或卡牌。三人同行已定，物种/行为/层数仅作预算。发布经验只来自八款参考游戏，自有mod仅作素材、技能与系统参考。免费开源不是素材授权，也不自动授权公开。

2026-10-29前由Codex主会话与两个Codex云分工，固定提交和轮次见分工记录，保留历史身份。PR #4准备包与PR #5阶段3—4单层片段均已合并（PR #5合并提交03e0c2b），下一步是阶段5。2026-10-30起由本机Claude主会话接手，执行位置、独立验收与交付方式见[Claude作业方式](工作环境/Claude作业方式.md)。

通用精确候选只在规则表维护；试开发短规格只补本试验参数、输入和界面。推荐临时可返回、奖励型招募、半额、独立试验重开，交换机与完整经济后置；均不冒充最终玩法裁决。旧审核包、冻结来源与旧数值不覆盖现行入口。正式外部管线资料仍归REA辅助研究/，本作规则归玩法研究/，两云不同时修改共享决定。

## 文档关联

本目录是 pokemon-dungeon-lab 仓库的 `docs/`，即设计资料权威位置（2026-10-29 由独立研究库并入，旧仓库已归档）；仓库根 AGENTS.md 的规则同样适用。原v0.1—v0.7及其摘要保留原字节；v0.7来源按审核请求/v0.7来源定位.json从固定提交核验，仅其中声明的现行决策入口允许更新。归并规则不改写冻结史稿。

新增研究按主题命名，在总索引、现行决策、当前分工和相应路线中维护入口，使用相对链接。提到 `docs/` 以外的仓库文件（代码、配置、测试）时写代码格式的仓库相对路径，不写 Markdown 链接，因为 Obsidian 只能打开 vault 内的文件；已有指向本机证据目录（如 `../../../Pokemon_REA_Workbench/`）的链接只在本机主 checkout 有效，保持原样。玩法候选、纸面核算、技术运行、独立审核和用户采纳分开。变更核验复用已有检查，发布时核对固定提交、远端文件树及干净状态。

pokebonk、pokemon-arena-2d、pokemon-autochess-mod保留参考证据范围；市场资料不用于重新打开用户已经排除的品类。历史恢复按对应编号交接定位；本轮已完成接收，不重复旧接手流程。

## 结论范围

用户已经确定的目标与研究建议分开保存。区分开发者自述、网页直接观察、公开客户端静态观察、分析推断和实际运行验证；不要把其中一种证据改写成另一种。

公开前端只能证明当前可见实现，不能证明作者使用的内部工具、团队分工或实际开发耗时。预告不能证明完整游戏已发布；数据表记录数不能证明可玩角色数。引用滚动网页或版本化脚本时保留核查日期与原始链接。

本目录目前承担研究与文档管理。开始游戏实现、安装环境或设置持续监测时，依据用户届时的实际任务范围执行。


## Obsidian 操作与检索

本目录是 Obsidian vault。笔记使用项目与主题标签，并可使用带完整库内路径的双向链接，避免多个 README 的同名歧义。代理在任务 worktree 中直接读写 UTF-8 Markdown，与相关改动一起走 PR；Obsidian 与其 MCP 指向主 checkout，只用于浏览和检索。遵守用户要求，不使用 Computer Use 编辑文档。现有内容发生外部修改时先读取并整合，不能用旧副本覆盖。
