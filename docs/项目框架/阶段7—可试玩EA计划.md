# 阶段7：从最小循环到可试玩 EA

用户在 2026-10-30 定下总目标：把 demo 推进到**可试玩的 EA 阶段**。[阶段6](阶段6—完整首版最小循环计划.md)已经跑通一个完整小循环：出发 → 远征 → 撤离或全灭 → 回到基地 → 学招、配招、编队 → 再出发。阶段7要补上 EA 还缺的部分。

阶段6 的结论和遗留问题见[阶段6复盘](阶段6复盘.md)。本页数值和具体选择都是 Claude 主会话的**工作候选**，可以随自测或用户意见修改。

## EA 是什么、怎样算达到

这里的 EA 指"拿到私有构建的人，能从全新存档开始连续玩多局"。它**不等于公开发布**：发布方式、素材许可路线和是否找体验者，仍由用户决定。

达到 EA 的通过条件：

1. **从零开始**：全新存档进入标题画面，选择主控，经过基地，开始远征。全程不需要开发工具、查询参数或检查入口。
2. **完整循环**：从全新存档连续玩至少 5 局，包含正常撤离、招募和培养；全灭、走失与救援用指定种子或构造存档必然触发一次并走完。每一步结果都正确保存。这一条由主会话（代理）通过浏览器检查脚本和内置浏览器完成，属于制作者实测，不是玩家证据。
3. **失败可以恢复**：全灭以后，靠基础收入与救援仍能继续正常游玩，不会卡死。由自动长测验证：30 个种子、每个种子连续 5 局，并含强制全灭的变体；每一局结束后，存档都能回到"可出发"的状态。
4. **能看懂**：界面全部使用中文名称；敌人信息可以查看；非法操作都给出原因；没有只给开发者看的提示文字。
5. **两种形态都实测**：网页私有构建和 Windows 私有包（Electron）都由主会话在本机实际启动；网页版用浏览器检查脚本，Windows 包用 computer-use 或等效的自动化输入，各打完至少一局。这是代理操作的制作者实测，不是真人键鼠，也不是玩家证据。
6. **存档有版本**：存档带版本号；遇到旧版本，能迁移就迁移，不能迁移就明确说明，并提供导出原记录。
7. **检查全部通过**：规则测试、独立断言、浏览器检查、长测和构建都通过；主脚本体积和首屏加载时间有记录，并对照阶段6末的基线（6.5 构建输出：主脚本约 1,466,000 字节，gzip 后约 391 KB；7.5 开工时重新构建，把命令与输出记进报告作为正式基线）。

## 里程碑

每个里程碑都是一个或几个 PR，合并前必须通过对应检查，并经独立审查。7.1 和 7.3 可以并行。

| 编号 | 交付物 | 通过条件 |
| --- | --- | --- |
| 7.1 新游戏流程与界面 | 标题画面、新游戏与继续、主控自选（第一到第三世代御三家共 9 种）、以基地为中心的主菜单；试验模式与检查入口收进开发者菜单；招式、物种与界面全部改用中文名；可以查看敌人信息（物种、HP、行为说明）；简短的新手引导（首次进入时说明移动、伙伴安排与撤离，可跳过）；解决阶段6复盘列出的可读性问题 | 全新存档不借助任何开发入口就能开始远征；固定主图等试验场景仍能从开发者菜单进入，原有检查继续通过 |
| 7.2 失败与回归 | 全灭时普通伙伴走失、进入救援池；付费救援后等待 X 次有效探险必定回归；未付费的到期后永久失去；基础收入；初始二人恢复；稀有服务点（低概率出现的伙伴交换机与局内商店，按[商店与伙伴交换机](../玩法研究/迷宫商店与伙伴交换机.md)的现行候选）。依据研究库的现行候选：[有效探险与基础收入](../玩法研究/有效探险与基础收入.md)方案 B、[救援费用与等待次数推演](../玩法研究/救援费用与等待次数推演.md)的纸面起点（单只费用 C=60、等待 X=1，X=2 作对照；基础净收入 R=100、未付费期限 L=4）、[救援队等级与失败成本](../玩法研究/救援队等级与失败成本.md) | 规则测试覆盖走失、付款、等待、到期、零余额恢复路线、交换机保伙伴与商店交易；长测中没有"无法再出发"的存档 |
| 7.3 内容扩充 | 名单扩到约 20—25 种（含 9 种御三家），招式机 6—8 种，远征 3 层，并在最后一层加入区域 Boss（不招募；按范围文档要求在 Boss 战前保留普通出口），至少 2 种楼层主题（地砖与敌人配置不同） ；生成脚本加入阶段7上限（20 美元），`--stage` 改为必填，并补测试 | 每个新物种都走完“数据 → 行为映射 → 素材 → 遭遇”链路；Boss 规则有测试；素材清单完整 |
| 7.4 平衡自测 | 扩展长测，统计通关率、全灭率、走失与救援的实际负担、平均轮数、等级分布；据此调整数值；评估招式机的其他用途（例如堆积后的处理）；评估招募与招式机是否拆成两条随机流 | 统计报告列出各项数值的取值依据；凡调整都标明是工作候选，不当作最终平衡 |
| 7.5 Windows 私有包与存档版本 | Electron 封装（便携版）、存档版本号与迁移、存档导出与导入、设置（动画、按键说明）；按需加载拆分主包（Phaser 单独分包），对照体积基线 | 主会话在本机启动 Windows 包，用 computer-use 或等效自动化输入打完一局（代理制作者实测）；网页版与 Windows 包的存档语义一致 |
| 7.6 EA 验收与复盘 | 按上面 7 条通过条件逐条验收，交付私有试玩包，写复盘 | 每条都有实际运行证据；未验证的内容（玩家体验）如实标出 |

## 范围之外

以下内容本阶段不做，也不表示从完整游戏中取消：

- 公开发布、联系体验者、开放网络权限：需要用户另行决定。
- 无尽迷宫、Z 晶、Mega：放到 EA 之后。
- 调整说明：[分阶段范围](分阶段范围与扩展顺序.md)把“区域 Boss”和“楼层主题”放在“首版后的连续区域”。本计划把它们提前到 7.3，理由是 EA 需要一个明确的终点目标来检验难度和失败路线；Boss 战前保留普通出口，跨区与无尽规则仍留在 EA 之后。商店与交换机仍按范围文档留在阶段7（7.2）。
- 四人队、移动端适配、联网与云存档。

## 资源与预算

- **API 费用**：总额度 50 美元，阶段6 实际约用 0.1 美元。阶段7 预算不超过 20 美元，单批仍不超过 2 美元。目前生成脚本只内置阶段6 的 15 美元上限（比计划更严），7.3 会改成按阶段执行 20 美元上限；在那之前，调用时必须写明阶段参数。主要用于楼层主题地砖、Boss 区域场景、界面图标；草稿一律用 flare 低质量档。
- **角色素材**：继续从 SpriteCollab 的固定提交下载，逐个文件记录来源与许可。官方原图（作者为 CHUNSOFT 的）没有授权，所以只能用于私有构建。
- **数据**：继续使用 Showdown 的固定 JSON，导入时先校验 SHA-256。
- **执行方式**：按[Claude 作业方式](../工作环境/Claude作业方式.md)，`mercury-dev` 负责实现，`mercury-reviewer` 负责只读审查，主会话负责整合与实测。危险操作必须隔离执行。

## 风险

| 风险 | 处理 |
| --- | --- |
| 失败经济让玩家卡死或刷钱 | 先用长测检查"零余额能否恢复"，研究库的反例逐条转成测试 |
| 内容扩充拖慢节奏 | 每批先打通一种物种的完整链路，再按清单批量处理 |
| Electron 打包涉及下载与执行安装脚本 | 只用锁定版本的官方 npm 包；Electron 二进制来自其官方 GitHub 发布页，并按官方 SHASUMS256 校验；安装在项目内被忽略的目录，不全局安装，不改系统设置。需要执行第三方安装脚本时，在隔离环境（专用目录或云环境）中进行。主会话判断这类下载属于已允许的开发依赖获取，不需要扩大网络权限；用户若有异议，先停下相关步骤 |
| 玩家体验始终没有验证 | EA 包交付后，由用户决定是否请体验者；观察记录表已经准备好 |
