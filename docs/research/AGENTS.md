# 本地研究库使用说明

## 进入顺序

先读 README.md、项目目标与当前决策.md 和 Obsidian使用说明.md，再根据总索引选择项目主题。制作流程位于 制作流程/。处理具体技术或版本结论时，阅读对应项目的 资料来源与验证范围.md。

## 文档关联

两款作品分别位于 pokebonk 与 pokemon-arena-2d。跨项目目录保存比较和面向地牢项目的建议。新增研究按主题命名，更新项目概况与顶层索引中的入口，并用相对 Markdown 链接连接相关主题。

## 结论范围

用户已经确定的目标与研究建议分开保存。区分开发者自述、网页直接观察、公开客户端静态观察、分析推断和实际运行验证；不要把其中一种证据改写成另一种。

公开前端只能证明当前可见实现，不能证明作者使用的内部工具、团队分工或实际开发耗时。预告不能证明完整游戏已发布；数据表记录数不能证明可玩角色数。引用滚动网页或版本化脚本时保留核查日期与原始链接。

本目录目前承担研究与文档管理。开始游戏实现、安装环境或设置持续监测时，依据用户届时的实际任务范围执行。


## Obsidian 操作与检索

本目录是独立 vault。笔记使用项目与主题标签，并可使用带完整库内路径的双向链接，避免多个 README 的同名歧义。MCP 写入前先核实连接的库；命令行以本库绝对路径读写 UTF-8 Markdown，并核对目标与保存结果；通过官方 URI 打开笔记时明确指定 vault=Pokemon_Game_Research 和库内 file。遵守用户要求，不使用 Computer Use 编辑文档。现有内容发生外部修改时先读取并整合，不能用旧副本覆盖。
