# 三人替换、携物与回营推演

状态：代理候选。本文补足 v0.6 留下的具体规则，不把研究建议或纸面检查当成用户采纳。目标是在三人上限内，让新人有用、旧培养能保住，并让“继续探索还是整队撤离”仍有明确区别。没有运行游戏或测得招募概率、胜率与玩家操作时间。

## 1. 从已确定条件出发

用户已确定三人同行、当场替换、换下成员回营保留培养。招募仍须实际击败合格非 Boss 并触发邀请；替换不恢复其他成员、不结束探险、不单独推进救援。完整一局先围绕一张普通迷宫与一条基地培养路径研究。

由此可以直接推出：替换能保护一个旧伙伴，并给在场队伍带来一名新人的生命和招式次数。不能一面允许这种规则，一面宣称招募没有恢复或保人价值。真正要比较的是，这份收益能否在不同队伍和敌人面前留下选择，而不是先添加次数上限或保护费用。

本版继承 [v0.3 行动候选](../2026-10-25-v0.3/伙伴控制与代表房间推演.md) 的完整行动轮概念：提交一次指令后，我方和敌方依既定顺序各处理行动。本版不批准该顺序，也不依赖速度数值；若以后采用连续个人行动条，需要重新定义等价的安全结算边界。

## 2. 邀请在什么时候出现

推荐在**完整行动轮结束后**显示本轮真实产生的邀请。轮内先登记邀请，继续完成已经提交的行动、连锁效果和该轮末的状态处理，然后才开菜单。菜单暂停世界，不等待清空整座房间或走廊。

1. 合格敌人被击败后产生一次招募判定。真实成功才登记邀请；没有成功就没有可选新人。
2. 本轮所有行动与轮末效果完成。本版以所有同行成员均倒下（HP 为 0）判全灭；睡眠等暂时不能行动不自动等于倒下。若已全灭，优先结算失败，本轮尚未接受的邀请失效，不能靠弹窗撤销全灭。
3. 队伍仍能继续时，按邀请实际产生顺序逐项显示。每项可接受或拒绝；必须处理完才能提交下一次行动，不能把邀请留成随时调用的后备名册。
4. 接受时若满员，选择一名当前同行者回营；若有空位，按空位招募处理。不增加第四同行位。
5. 每次接受并完成转移后，先结清此次离队、入队直接触发的即时效果，再处理下一份邀请；若这些效果使在场成员全部倒下，则保留已经完成的回营结果、结束本局并取消未接受邀请。菜单不推进普通行动、持续伤害周期或额外轮末结算。本版不凭空新增此类效果，只规定实际存在时的顺序。
6. 拒绝不消耗行动，也不重新抽概率；这次邀请结束。重新载入恢复同一份邀请队列、顺序、已接受和已拒绝结果；待处理邀请未清空前不能开始下一轮。

这样，A 击倒敌人后，B、C 与仍活着的敌人照常执行已提交行动；N 不会突然插入这一轮攻击，也不会吸走本来应由 C 承受的这轮伤害。清场后再开菜单虽然更安静，但持续出现敌人的走廊可能让邀请长期无法兑现；轮末处理保留即时招募的用途。

## 3. 替换是否另花一轮

| 同一邀请的处理方式 | 具体结果 | 主要代价 |
| --- | --- | --- |
| 推荐：轮末替换，不另推进一轮 | C 回营，N 下轮开始按正常队列行动；A、B 不恢复 | 有真实招募机会时可以直接保人、补充队伍资源；连续邀请可能很强 |
| 对照：替换后全队等待一轮 | C 回营，N 入场，三名我方均等待一次，敌人和状态正常推进 | 危险环境中要挨额外一轮；安静环境中成本可能只是多按一下，强烈依赖站位 |
| 对照：只占某个角色的一次行动 | 要指定谁支付，其他成员仍行动 | 主控切换、倒下角色和空位加入都会影响支付人，首批需要额外解释 |

本轮优先第一项。真实击败与概率邀请已经构成机会条件，换下有用老伙伴也会失去其当前作用；额外等待一轮不能保证保留取舍，反而可能让危险时才最需要的换人难以使用。这个判断不证明免费替换已经平衡。

**不额外耗轮不等于多一次行动。** C 已用掉的本轮行动不会退还；N 的首次行动是下一轮。沿 v0.3 候选，离队者从固定执行队列移除，新人追加到末尾：A→B→C 若换下 B，下一轮为 A→C→N，不能通过更换主控把 N 提到第一位。

换下主控时，玩家在同一菜单选择留下的未倒下成员或未倒下的 N 作为下轮主控，只改变操控对象，不重排执行顺序。暂时不能行动不禁止查看或选择该成员，也不免除其下一轮异常效果。已经存在的伙伴覆盖指令在本轮均已处理，离队者的持续指令与支援效果结束，不继承给 N。

## 4. 入场位置、倒下与连续邀请

满员替换时，N 使用被替出成员刚释放的格子。其他成员不移动，也不赠送展开队形。新人可能仍在后排或被队友挡住，不能仅凭有远程招式就断言它下一次一定能命中。

本版纸面模型把倒下成员保留在原格并继续占同行名额；倒下者不行动、不提供持续支援，敌人不继续攻击它。替换释放该格并由 N 占据，不另找远处有利落点。这是为检查倒下替换所作的明确假设，尚未选为全部移动规则；后续走廊研究需检查倒下占位是否造成过重阻挡。空位招募的落点不属于本次满员替换推演，不能直接套用“释放旧成员格子”。

推荐允许替出倒下成员，前提是轮末还有至少一名未倒下的同行者。A 为 0、B/C 存活时，真实邀请可以保住 A；A/B/C 都为 0 时先结束探险，不出现利用邀请起死回生的分支。成员本局已经进入救援池后，不能再成为同行替换目标。

不先限制每局替换次数，也不按是否出手过来筛除新人。同一轮若真的产生 N、M 两份邀请，玩家可先让 C 回营接 N，再让 N 回营接 M；N 虽未战斗，仍是接受后保留下来的新伙伴。最后同行仍为 A/B/M，C/N 安全在营地。这个结果强化收集与保人，是本候选接受的真实收益，不能在结论里漏掉。

若这种操作在原型中频繁让玩家只点菜单、把新人当资源包，需要比较邀请密度、基础组合差异和具体回营规则；不能凭纸面担忧提前增加每局一次的硬上限。本版不保证所有邀请都值得接受，也不保证默认跟随能利用新人。

## 5. 回营保人和物资运输分开

本轮首批组合建议只使用**队伍共用背包及已有保护袋候选**，不新增个人装备或独立携物槽。这样替换只转移伙伴实例与个人培养，背包、现金、招式机、消耗品和任务物品都留在本局原容器；背包满也不妨碍招募，没有凭空增加或减少包格。

| 操作 | 保住谁 | 保住什么物资 | 是否结束探险 |
| --- | --- | --- | --- |
| 招募替换 | 被换下的那个实例 | 不因换人运走物资，既有保护袋效果照旧 | 否 |
| 稀有交换机 | 主动选定撤回的实例 | 只运送明示准入与额度内的物资，旧候选的“两份”未定稿 | 否，人数减少 |
| 普通出口 | 按正常撤离规则带回队伍 | 按正常撤离规则处理全部允许带回内容 | 是 |

N 不附送装备包或治疗品，原敌人的掉落单独按本局规则结算一次。不能通过邀请菜单把新拾取的贵重物临时挂到 C 身上运回营地。

若首批后续确实加入个人携物，必须重新比较“随人回营”与“留在探险物资中”两种完整规则，再处理满包、掉落、装备效果和先换装再送回的组合。本版没有批准个人装备绑定、额外运货额度或自动丢物。只增加禁转交提示并不能防止玩家在击敌前提前换装，因此不把它当作已经解决的设计。

交换机的区别因此清楚：即使一直没有邀请，也可主动送回伙伴，并附带少量物资；代价是缺一名同行。它未必仍值得在首版实现，应在代表迷宫里观察实际使用理由，不能为了保留装置而削弱用户已定的替换能力。

## 6. 回营后的保存与整备

替换成功立即保存同一个伙伴实例及个人永久培养，标记为“已回营，本次探险不可调入”。它不再参与本局的攻击、被动支援、经验分配或全灭走失判定，也不需要新建付费救援订单。

推荐本次探险结束后再开放基地编队、教学、出售与付款。回营当下只确认已安全保存，不打开另一套基地操作；本局结束后按已有免费基本整备候选恢复可用成员的生命、PP 和普通异常。没有新增现实等待时间或救援次数，也不会因此治疗在场成员或救回仍在救援池的伙伴。

在共享本局等级候选下，回营者停止使用这局临时等级，但保留自己的已学招式；N 以当前本局等级和自己的基础组合加入，不复制老伙伴的学习投入。永久个体等级仍保留为成长对照，若采用它，需要再确认本局经验保存及新增成果判定，不能沿用“临时经验不算成果”的结论。

邀请的接受、C 离队、N 入队、即时效果结果、回营保存和邀请进度，应作为一次不可拆开完成的转移：要么恢复到尚未接受，要么恢复为已经换好，不能出现 C 同时在两处、N 重复初始化或同一邀请用两次。多邀请不必整批接受，但每项的接受、拒绝及未处理状态都须保存。这里只提出未来存档应满足的结果，未编写或验收存档程序。

## 7. 用同一组状态检查后果

下表数值均为纸面输入。三人上限固定，生命只用来区分状态；本局目标尚未完成时不发基础报酬。未付款剩余次数记 L，已付款等待次数记 X；有效探险的判定沿已有 B 候选，而非已定规格。

| 编号 | 明确输入与操作 | 本次应得到的结果 |
| --- | --- | --- |
| C1 普通替换 | A/B/C 本轮均已行动，轮末有 N 邀请，选择 C | C 回营，同行 A/B/N；本轮不再有人行动，N 下轮首次行动；背包及 A/B 的 HP、PP 不变 |
| C2 残血与功能 | A=10、B=24、C=30；A 是唯一控制通道者；N=60，只有攻击功能 | 换 A 能保住 A，却失去控制；换 C 保留控制但 A 仍脆弱；60 不代表新人更优，不计算虚构胜率 |
| C3 倒下替换 | A=0、B=26、C=34；有 N 的真实邀请 | 可让 A 回营，N 占 A 释放的格子；A 不入救援池；B/C 不恢复 |
| C4 同轮全灭 | 有邀请登记，但余下敌人或轮末效果使三人均倒下 | 全灭优先，尚未接受的 N 不成为伙伴，不取消损失或发放招募成果 |
| C5 多份邀请 | 同轮已有 N、M 两份真实邀请，先 C→N，再 N→M | 同行 A/B/M；C/N 回营，N 是一个新成果；M 下一轮首次行动，整局不因两次接受多结算 |
| C6 满包 | 背包已满，C→N | 包内容与容量不变，不自动丢物，不运输招式机；招募本身不占包格 |
| C7 新人先回营再全灭 | 目标未完成；通过 C5 保住 N，之后 A/B/M 全灭 | N/C 不判走失；N 使本局有新成果，有效一次、基础报酬 0；只对仍在场普通伙伴按失败规则处理 |
| C8 只有旧成员回营 | 已有 C 通过交换机空手回营，无目标、无新伙伴、无新物品，之后失败 | 旧 C 本身不制造成果；本局无效、报酬 0，旧池 L/X 不推进；真实新走失仍处理 |
| C9 临界旧救援 | C7 的结果；旧订单 U 未付费 L=1，费用 60，余额 0，无可出售安全物资 | 有效却无工资，U 进入最后付款窗口仍可能付不起；保住新伙伴不保证旧伙伴能救回 |
| C10 旧池与新池 | C7 结果；旧已付款 V 的 X=1，本局新人 M 新增走失，示例初始期限 4 | V 在终局回归；M 新入池仍为 4，不扣自己的发生局；V 不参与刚结束的场内全灭 |
| C11 重载 | C→N 已保存，关闭并恢复同一探险 | 同行仍 A/B/N，C 在营，邀请已用；N 不补第二份 HP/PP，未完成目标不因此领钱 |
| C12 多邀请中途重载 | C→N 已完成，M 尚未处理时关闭；或 N 已拒绝、M 尚未处理时关闭 | 前者恢复 C 在营、A/B/N 同行，N 已用、M 待处理；后者 N 保持已拒绝，不凭空出现新伙伴；顺序不变，M 未处理前不能行动 |
| C13 暂时不能行动 | A 的 HP=10 但暂时不能行动，B/C 均倒下，本轮已有真实邀请 | 不因无人能出招就判全灭；仍可处理邀请。A 的异常和有限生命继续保留，不自动治疗或解除 |

目标前接受 N、以后 N 走失入池时，已有 B 候选也将保留下来的新伙伴实例计为成果；不能只有 N 直接回营才算有效。各案例只检查明确给定的分支，不推出招募概率、地图可达性或连续失败时全救成功。

## 8. 下一次需要观察什么

这套候选可以进入三人代表房间和完整普通迷宫的后续设计，不能据此开始正式数据制作。最有价值的下一组对照是：同一个入口和敌人组合，接受不同功能新人、拒绝邀请、整队撤离三条路线分别留下什么 HP/PP、队形和安全成果。先比较真实决策，再定邀请概率和资源初值。

需要留给用户的实质取舍主要是：是否接受不额外耗轮的直接保护收益；是否接受尚有队员存活时替出倒下成员；是否接受首批共用背包且替换不运物。当前继续保留候选，不逐项请求即时裁决。

尚缺：真实控制与点击体验、倒下占位的走廊影响、多个邀请的菜单负担、招募初值与密度、交换机在同一地图中的实际用途、真实保存恢复和两端运行。纸面一致性或云端文档推演都不把这些项目记为通过。
