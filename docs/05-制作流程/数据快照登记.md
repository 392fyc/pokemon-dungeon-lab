# 数据快照登记

**状态：2026-10-31 由 `main` lane 建立。**

## 这页是什么

本页登记本作使用的全部外部数据快照，覆盖到第 9 代全部 1025 种。

- **为什么要固定快照：** 外部来源（Showdown、Bulbapedia、PokeAPI、SpriteCollab）会持续更新。按世代补全图鉴是分批进行的，如果每次都去抓最新数据，同一条规则在不同时间可能得出不同结果。所以把数据一次性固定下来：以后无论补哪一代，都用同一份、已核验过的数据。
- **快照放在哪里：** 快照本身放在主 checkout 中被 Git 忽略的 `.artifacts/` 目录，不进仓库。原因有两个：一是体积大；二是部分来源的许可没有核实，不宜再分发。
- **怎样确认快照没变：** 本页记下每份快照的来源、版本和 sha256 校验值（文件内容的“指纹”，内容变一个字节，指纹就会不同）。快照丢失时，可以按同一版本重新获取，再用校验值确认与原来一致。
- **用户的原话：** “可以把一些当前demo不做，但是未来确定的世代宝可梦数据先固定了”。

**怎样重新获取：**

- **Showdown：** 从上表的提交下载 `play.pokemonshowdown.com/data/` 下的三个文件，做法见 `tools/data/import_showdown.py`。
- **Bulbapedia：** 用 `tools/data/fetch_pmd_wiki.py --moves <清单> --out <文件>` 抓取。快照里的 `requestedIds` 字段就是当时请求的招式清单。注意：重新抓取时页面可能已经被人编辑过，所以 sha256 不一定相同。各页的 `revid`（页面版本号）记录在快照里，可以对照旧版本做核验。
- **PokeAPI、SpriteCollab：** 从上表的提交下载原始文件。

**对以后扩充的提示：**

- **素材缺口：** 第 5 代以后，SpriteCollab 的精灵缺口逐代变大，第 9 代只有 90/120。
- **招式缺口：** 新世代物种越来越依赖“无官方迷宫数据”的招式。
  - 用户 2026-10-30 已说明：“部分旧官方探险队没有的宝可梦，招式可能需要依赖我们自己设计在游戏中的表现，大部分仍参照官方探险队。”
  - 所以补到这些世代时，需要先为这类招式设计本作的表现，再按类别加模板。
- **传说与幻：** 后几代占比明显升高，第 7 代 27 种、第 9 代 28 种。按 7.8 规格第 14 节，它们暂不作野生出现。

## 3. 扩充顺序

用户 2026-10-31 补充：

> 如果数量太多的话，可以参考pokemonautochess，先做一些热门的也可以

main 的落实：

- 数据快照一次性固定全部世代。它成本低，这一轮补齐只抓了 237 页。
- 真正加入游戏的物种要考虑素材、平衡和例外处理，所以可以按热门程度挑选，不必整代一次放入。挑选时参考 [pokemon-autochess 研究](https://github.com/392fyc/pokemon-dungeon-lab/blob/d03ef5144f5671b3b8d5418b94353223742e911a/docs/06-%E7%A0%94%E7%A9%B6/%E5%8F%82%E8%80%83%E9%A1%B9%E7%9B%AE/pokemon-autochess-mod/README.md) 中的物种选择。
- 具体名单在扩充时再与用户确认。
