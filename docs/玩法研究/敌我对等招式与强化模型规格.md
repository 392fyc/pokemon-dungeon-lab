# 阶段7.8 敌我对等招式与强化模型规格

**状态：工作候选规格，2026-10-30 统一修订。** 第 1–9 节已经并入第 10–13 节的全部用户决定，以及以下已合并的前提：营地存档（PR #75）、图鉴 160 种（PR #65）、全部素材（PR #76）、7.7b（PR #72）。

- 用户原话保留在第 1 节和第 10–13 节。

**main 对“敌我对等”的理解：**

- 敌人和玩家用同一套官方招式模型（[官方招式模型规格](官方招式模型规格.md)）：射程、目标、效果、伤害公式、PP 都相同，不再为敌人另设攻击规则。
- 敌我差异只来自各自的强化模型，即等级来源、首领倍率与行为开关。
- 这会取代两样现有规则：
  - 敌人三档：`dungeon.ts` 的 `TIERS`。
  - 首领专用攻击规则：`BOSS` 的固定伤害、射程和每回合次数。7.7 重平衡把首领定为 HP 60、伤害 4，已由 PR #53 合并，是现行的过渡值。

## 2. 敌人成为“有招式的宝可梦”

- **普通敌人：** 每个野生敌人按其物种在 `roster.json`（名单）中的数据生成：
  - 招式取该物种的初始招式（`kit`），PP 与同物种的玩家伙伴相同；
  - 等级按第 13 节，最大 HP 按第 5 节公式。
- **首领：** 风速狗已经在名单里（PR #65 随第 1 代一起导入），`maxHp` 为 30，初始招式是神速＋咬住。
  - 规则是“首领与普通版本共用名单数据，首领多出来的只有首领特性”，所以首领直接用名单招式**神速＋咬住**。
  - 这是 main 的决定。此前写的“喷射火焰＋咬住”是名单导入前的工作值，现在以名单为准，也不在 `boss.json` 里另设招式。
  - 首领特性放在 `src/data/boss.json`（见第 5 节）。
- **没有物种的敌人**：指固定图的 E、R，`scenarios.ts` 里 V5、V6、V8 的敌人，K4 等。
  - 按用户所选的对照指定物种：近战 E→小拳石，远程 R→波波，追击→卡蒂狗。
  - 伤害为 0 的阻挡块不给招式，带“只等待”开关（不普攻、不移动）。
  - 这些单位的等级取迷宫起始等级 Lv5。
- **PP 用完：** 与玩家一样，改用普攻。
- **招募：** 敌人被打倒并入队时，按该物种的名单数据生成，不继承敌人的倍率和首领特性；等级按局内队伍等级（第 13 节）。
- **首领可招募为普通版本（用户决定）：** 击败首领后，与普通敌人一样按招募概率发出邀请，入队的是普通风速狗。“独特特性”暂不设计。需要 dev 修改的地方：
  - 击败首领时，`kills` 改为记录其物种。现在记的是空字符串，所以不会发邀请。
  - 营地档案校验：去掉 `base.ts` 中“首领物种不能作为普通伙伴”的拒绝，以及失去记录对风速狗的拒绝。改为营地存档后，招募来的伙伴只存进营地档案，所以真正挡住招募的是这里。
  - 嵌套单位（招募快照、邀请）仍然不得带 `boss` 标记，但允许物种是风速狗。
  - `roster.ts` 中 `BOSS_SPECIES` 这个特例改由 `boss.json` 驱动，注释里的“不可招募”删去。
- **共用物种池（用户决定）：**
  - 名单中的每个物种都可能作为野生敌人出现，也都可以被招募。
  - “初始可选”只表示开新游戏时能选。
  - 具体出现在哪一层，由第 14 节的主题敌人池规则和第 13 节的等级决定。
  - 风速狗不作为初始伙伴，也不进招式机可学池。这一点用户没有明确答复，按推荐处理。

## 3. 相对阵营：把只对一边生效的引擎规则对等化

引擎里有几条规则写死成“敌人打玩家”这一个方向。对等后，改为按**相对阵营**判定：“对方”指与行动者不同阵营，“己方”指相同阵营。

| 规则 | 现状（代码） | 对等后 |
| --- | --- | --- |
| 目标类别 `enemy`／`teammates`／`party` | 按 `side==='enemy'`／`'friend'` 写死（`targetKindMatches`） | `enemy` 指对方；`teammates`／`party` 指己方（敌方的“同伴”是同层存活的其他敌人） |
| 普攻 | 只能打 `side==='enemy'` | 只能打对方 |
| 守住、反击、快速防守、反射壁、光墙 | 只在“敌人攻击玩家”时生效（`resolveDamage`） | 任何一方都可以获得；只对**对方**造成的攻击伤害生效 |
| 守住、反击的持续 | 设为 3，每回合末减 1，覆盖 3 个敌方阶段 | 统一为“覆盖之后的 3 个对方行动阶段” |
| 等级伤害加成 | 对任何行动者都用全队等级 `s.prog.level` | 用行动者自己的等级：玩家伙伴用局内队伍等级，敌人用第 13 节的敌人等级；公式按第 13.2 节第 8 条 |
| 吹飞 | 首领不会被吹飞 | 能否被吹飞由首领特性决定；敌人也可以吹飞玩家，撞墙、撞单位的伤害规则相同 |

每一条都要有正向和反向测试。例如：
- 敌人用守住挡玩家的招式；
- 敌人带反击时，玩家贴身攻击被反弹；
- 敌人用帮助给同层敌人加攻击；
- 快速防守挡下敌人的 `front2`／`line10`／`room` 远程招式。

### 3.1 攻击类别（物理／特殊）

反射壁只挡物理攻击，光墙只挡特殊攻击，所以每次攻击都要知道自己是物理还是特殊。原来按敌人三档区分（近战算物理、远程算特殊，首领按距离），7.8 删除三档后需要新的来源。

- **招式：**
  - 按 Showdown `moves.json` 的 `category` 批量导入：`Physical` 算物理，`Special` 算特殊。
  - 导入时写进 `pmd-moves.json` 根部的 `categories` 映射（招式 id → 类别）及其来源说明 `categorySource`。现有 217 个招式对象不改动。
  - 这是 dev 在 lane bus 第 65 条提出、main 采纳的做法。
- **普攻：** 用户决定（2026-10-30，原话）：

  > 普攻按照物攻、特攻较高一方算类型和数值。

  main 的落实：
  - 类型：比较该物种名单 `baseStats` 中的 `atk` 与 `spa`，`atk` 较高为物理，`spa` 较高为特殊；两者相等时算物理（main 的默认值）。
  - 数值：现行伤害公式（`6+ceil(威力/2)`＋等级加成＋阶段）不读种族值，所以“数值”这一半暂时没有可作用的地方。以后若引入攻防种族值，普攻按较高一方的攻击种族值计算。在此之前，这一半记为待细化，不自行补全公式。
- 敌我双方都用同一规则。

## 4. 共用的选招规则（非玩家操控的单位）

非玩家操控的单位（敌人，以及设有作战方针的玩家队友）每次行动都按以下步骤决定。

- 选招本身是确定的。
- 需要随机的地方（敌人物种、等级、睡眠、漫游选路）各用一条独立随机序列，都由远征种子派生（第 12.2 节第 5 条、第 13.2 节第 3 条、第 14 节）。
- **作战方针**是这套算法的参数：敌人一律用“主动出击”；队友按自己的方针调整步骤 1–5 的取舍（第 11 节）。

1. **列出候选：** 对每个可用招式（PP 足够，且不是被拒的连续守住或快速防守）与每个合法目标的组合，计算“估算收益”：
   - **伤害招式：**
     - 估算伤害 ＝ `6+ceil(威力/2)` ＋ 行动者等级加成 ＋ 行动者攻击阶段 − 目标防御阶段，最少 1。
     - 目标处于对其生效的守住时，记为 0。
     - **目标只能是对方**：即使招式的官方目标是 All，也不主动选己方。
     - `line10` 只命中射线上的第一个单位；如果这个单位是己方，这个组合无效。
   - **吹飞类招式**（吼叫、吹飞、龙尾）：
     - 吹飞路径会撞墙或撞上**对方**单位时，加 5（撞击伤害）。
     - 会撞上己方单位的组合判为无效。
     - 龙尾另加它自身的伤害。
     - 对“不被吹飞”的首领：吼叫、吹飞不能以它为目标；龙尾只计伤害，不计撞击。
   - **吸取：** 收益计算同伤害招式；自身 HP 低于一半时，收益 ×2。
2. **选收益最大的组合。** 收益相同时依次比较：PP 多的招式优先；再按招式顺序；再选距离最近的目标；再按目标的队列顺序。
3. 没有收益大于 0 的候选时，考虑**自身或己方类招式**：
   - 自己没有守住、且有对方能打到自己时，用守住；
   - 防御阶段低于 1 时，用变圆或变硬；
   - 同房间有两名以上己方时，用帮助（每个对象的攻击阶段加到 +2 为止）；
   - 己方有人会被对方的远程招式打到时，用快速防守；
   - 己方都没有某种屏障时，用反射壁或光墙。
4. 相邻有对方、能普攻时：普攻。
5. 否则，按方针移动（第 11 节），野生敌人按第 12 节行动。“不移动”的首领和“只等待”的阻挡块不移动。

## 5. 强化模型（敌我各自的差异来源）

强化模型只调数值与少量行为开关，不改招式规则本身。

**公式：**
- 敌人最大 HP ＝ `max(1, round((名单基础HP ＋ max(0, 等级−5)) × HP倍率))`。
- 伤害的等级加成与玩家用同一公式：`floor(max(0, 等级−5) ÷ 4)`（第 13.2 节第 8 条）。

| 对象 | 强化项 | 工作候选 | 说明 |
| --- | --- | --- | --- |
| 普通敌人 | 等级 | 第 13.2 节第 3 条的楼层等级段 | 与玩家同一刻度，只是来源不同 |
| 普通敌人 | HP 倍率 | ×1，待长测 | 名单 `maxHp` 范围 14–62（160 种实测）。作为常量放在 `dungeon.ts` 的主题配置旁 |
| 首领 | 等级 | `max(所在层上限＋levelBonus, 首领物种的进化等级)` | 风速狗为 Lv22 |
| 首领 | HP 倍率 | `boss.json` 的 `hpMultiplier`，工作值 3 | Lv22 风速狗：(30＋17)×3＝141，待长测 |
| 首领 | 行为开关 | `boss.json` 的 `canMove`、`canBeBlownAway` | 风速狗：不移动、不被吹飞（沿用 7.3） |
| 无物种的阻挡块 | 行为开关 | 只等待（不普攻、不移动） | 只用于固定图与试验场景 |
| 玩家 | 局内队伍等级、招式机、配招、进化 | 见第 13 节 | — |

**`src/data/boss.json` 的结构（main 维护，已建立）：**

```json
{
  "note": "说明文字",
  "bosses": {
    "arcanine": { "levelBonus": 2, "hpMultiplier": 3, "canMove": false, "canBeBlownAway": false }
  }
}
```

- 键是名单中的物种 id；只有上面四个字段，全部必填。
- 基础数据（HP、招式、PP）一律来自名单，这里不重复。
- dev 在 `tests/core/` 加一条校验测试，检查：
  - 物种必须在名单里；
  - 字段齐全、类型正确；
  - `levelBonus` 为非负整数；
  - `hpMultiplier` 为正数。
- 首领出现在哪一层、哪个房间，仍按 `dungeon.ts` 现有的首领房间规则决定。`BOSS` 常量里只保留单位 id 与物种 id，数值与开关改从 `boss.json` 读取。

更丰富的强化，例如称号、精英个体、遗物式加成、首领被招募后的“独特特性”，属于用户保留的系统，等用户一起设计，不在本阶段。

   - 每层生成普通敌人时，每只有 25% 的几率睡着。随机数取自远征种子派生的随机序列，同一种子结果相同。
   - 首领与怪物屋（目前没有）不睡。
   - 睡着的敌人不行动。被攻击（受到伤害或被吹飞），或任一对方在回合结束时与它相邻（含斜角，即横纵差都不超过 1；引擎移动仍是四方向）时醒来，醒来后紧接着的那一个敌方阶段不行动：被攻击或被吹飞醒来时，就是当回合的敌方阶段；回合结束时因对方相邻醒来时，就是下一回合的敌方阶段。
   - 固定图与开发者场景不随机生成敌人，所以不会出现睡着的敌人。
3. **醒着的敌人每回合：**
   1. 有当前可见的对方：按第 4 节选招或攻击；打不到就追最近的可见对方，并把这名对方的位置记为“追击记忆”。
   2. 看不到对方、但有追击记忆：走向记忆位置。连续 4 回合看不到对方就清除记忆（前 3 回合仍走向记忆位置，第 4 回合清除）。到达记忆位置后仍看不到，也清除。
   3. 既看不到对方、也没有记忆：漫游。
      - 在房间内：从房间的出口（与走廊相接的边缘格）中按随机序列选一个，作为目标走过去，到达后进入走廊。
      - 在走廊中：沿“当前方向”前进。当前方向是这名敌人上一步的移动方向；没有上一步（刚醒、刚生成、刚放弃追击后停在原地）时，从可走的方向中按随机序列选一个。
      - 岔路：除来路外可走的四方向邻格有 2 个或以上。岔路处能直行就直行，不能直行就按随机序列从其余可走方向中选。
      - 拐弯：除来路外只有 1 个可走邻格时，走那一格。
      - 死路：除来路外没有可走邻格，掉头。
      - 要走的格子被其他单位占着时，本回合原地等待，方向不变。
      - 进入房间后重新选择出口。
4. **首领与阻挡块：** 首领不睡、不漫游，仍按首领特性（例如风速狗不移动）；阻挡块的“只等待”开关优先。
5. **随机序列：** 睡眠判定与漫游选路使用一条新的独立随机序列，由远征种子、楼层号与固定标签 `enemy-ai` 派生；不借用地图生成的序列（`dungeon.ts`），也不借用招募抽取的 `prog.rng`，以免睡眠和漫游再额外扰动地图与招募的随机序列（每层敌人数改变后，固定种子的地图本身仍会改变，见第 8 节）。
   - 取数顺序：每层生成敌人时按敌人 id 顺序先做睡眠判定；之后每个敌方阶段按敌人行动顺序，只有需要随机的敌人才取数。
   - 同一种子、同一操作序列，结果相同。
6. **迷宫内状态不存档：** 睡眠、漫游目标、追击记忆都只在内存中（营地存档模型）。

### 12.3 验收

- 视野：房间内、走廊内、隔墙三种情况各有测试。
- 睡眠：同一种子下哪些敌人睡着可复现；被攻击、对方相邻时醒来；醒来那回合不行动。
- 追击记忆：看不到 4 回合后放弃；到达记忆位置后放弃。
- 漫游：房间选出口、走廊直行优先、死路掉头，同一种子可复现。
- 与第 11.4 节合并列出敌人行为新旧对照。

## 13. 等级与进化模型（2026-10-30 用户决定）

### 13.1 用户决定（原话与选项）

讨论顺序如下（均为本对话中用户原话，除非注明是选项）：

1. main 问“进化形态要不要随楼层解锁”，用户答：“按等级设置”。
2. main 提出“另设出现等级，战斗等级不动”或“战斗等级改为原版刻度”两种做法，用户答：

   > 按照进化原版刻度，需要特殊条件的则在原版基础上做一些小调整。请你思考敌我同图鉴的意义是什么。就是为了这里更方便设计

3. main 问等级归属（每只永久等级，或共享本局等级），用户答：

   > 这是个讨论点。理论上rougelite来说，每局重置是应该的。

4. main 据此提出“每局重置＋原版刻度＋局内进化”，并问局内等级全队共享还是各算，用户答：“全队共享”。
5. 用户随后补充：

   > 有两个等级：探险队等级和局内队伍等级。探险队等级是永久的全局成长，而队伍等级是每次进入迷宫重置

**main 的理解：**

- 敌我同一个图鉴、同一个等级刻度、同一条进化规则。敌方的妙蛙草从 Lv16 起出现，正因为我方妙蛙种子在 Lv16 进化。这是一套规则作用于双方，不为敌人另设“出现等级”。
- 等级每局重置，属于肉鸽的局内成长；长期成长来自招募、招式机、金钱和以后与用户一起设计的系统。
- 局内等级全队共享，沿用现有的“共享本局等级”结构，只换成原版刻度。本节称它为**局内队伍等级**。
- 另有**探险队等级**：永久的全局成长，不随远征重置。它就是 [救援队等级与失败成本](救援队等级与失败成本.md) 中用户已定方向的“救援队等级”：升级后解锁更危险、收益更高的任务。两者在命名、界面和数据上分开表达。
- 探险队等级的具体规则（怎样获得、升级门槛、解锁哪些迷宫、是否影响迷宫的起始队伍等级）本节**不定**，留待与用户一起设计。本节的“起始等级 Lv5”只是迷宫配置的工作值，与探险队等级暂无联系。

### 13.2 规则（main 的落实方式，工作候选；用户的决定见 13.1）

除注明“用户决定”的内容外，本节各条均为 main 的推导与工作候选，用户可改，数值由长测确定。

1. **刻度：** 双方都用原版的 1–100 刻度。
2. **我方（局内队伍等级）：**
   - 每局开始时，局内队伍等级取该迷宫的起始等级（工作候选 Lv5）。
   - 局内打倒敌人得经验，全队一起升级；局后重置。
   - 招募来的伙伴以当时的局内队伍等级入队（现有规则）。
3. **敌人：** 每层有一个等级区间，敌人等级在区间内按下面的独立随机序列取值，且不低于该物种的进化等级。工作候选：

   | 楼层（主题） | 敌人等级 | 普通敌人数 |
   | --- | --- | --- |
   | 第 1 层（苔石洞） | Lv5–6 | 4 |
   | 第 2 层（潮湿水窟） | Lv8–11 | 4 |
   | 第 3 层（灰烬裂谷） | Lv12–20 | 4 |

   - 现有每层敌人数为 2／3／3（`dungeon.ts` 主题配置），改为每层 4 只，以免队伍等级远落后于敌人（推算见第 7 条）。
   - 首领等级＝max(所在层上限＋首领特性里的等级加值, 首领物种的进化等级)。风速狗：max(20＋2, 20)＝Lv22。
   - 第 3 层上限取 20，是为了让进化等级为 20 的形态（九尾、雷丘、风速狗、伊布的进化形等）能作为野生敌人出现；用户已答复风速狗“也作为野生出现”（第 10 节问题 6）。
   - 敌人等级在 [max(该层下限, 该物种进化等级), 该层上限] 内按整数等概率取值。
   - 敌人等级用一条独立随机序列取值：由远征种子、楼层号与固定标签 `enemy-level` 派生，不借用地图生成的序列与 `prog.rng`（同第 12.2 节第 5 条）。

4. **进化等级（每个物种一个数，敌我共用），按原版批量计算：**
   - 未进化形态：1。
   - 某物种的前一形态不在本作图鉴中（例如皮卡丘的前一形态皮丘是第 2 代）：也按未进化形态处理，计 1。这是 main 对用户所说“小调整”的落实。若以后出现“前一形态不在图鉴、更前一形态在图鉴”的情况，按图鉴内最近的前一形态算阶段（2026-10-30 数据中 0 例）。
   - 靠等级进化的：取原版进化等级（Showdown `evoLevel`），例如妙蛙草 16、喷火龙 36。
   - 靠道具、交换、亲密度、携带道具或学会招式进化的：按它在本作图鉴内的进化阶段折算，第一阶段计 20，第二阶段计 36（main 的工作值）。例如九尾、雷丘、水伊布计 20；胡地、耿鬼、怪力计 36。
   - 这个数就是该物种的“进化等级”。
5. **敌人出现：** 一个物种能在某层出现，当且仅当它的进化等级 ≤ 该层敌人等级上限。生成时，该敌人的等级在区间内、且不低于它的进化等级。
6. **我方进化：**
   - 当局内队伍等级达到某名伙伴的下一形态的进化等级时，它在轮末结算时进化为下一形态。
   - 最大 HP 按新形态的公式重算；**当前 HP 不变**（与 R07“最大生命提升不顺带治疗”一致），若超过新上限则取上限。
   - 招式不变，进化时不学新招。
   - 轮末结算顺序：经验 → 升级 → 进化（含伊布选择）→ 首领招式机 → 招募抽取。每次轮末结算都检查进化，一次最多进化一段；新伙伴入队时等级已超过进化等级的，在之后的第一次轮末结算进化一段。
   - 只有下一形态在本作图鉴里才会进化。
   - 有多个分支的（本作图鉴内只有伊布：水伊布、雷伊布、火伊布），在轮末结算时请玩家选择，不占回合；关掉选择框就暂不进化，下次升级再问。
   - 局后恢复为进入远征时的形态（与等级一起重置）。
   - 招募来的已进化敌人以它被招募时的形态入队，以后每局按起始等级出场，形态不回退。招募快照与结算都使用被招募时的物种，而不是局内进化后的物种（`base.ts` 结算中 `newInstance` 现用 `u.species`，要改）。
7. **经验与升级（工作候选，长测确定）：**
   - 打倒一名敌人得经验＝该敌人等级（首领同样按其等级）；从 L 级升到 L＋1 级需要经验 L；取消现有 Lv5 上限（改为 100）；取得目标的经验另定，暂取 0。
   - 推算（推断，未经模拟）：每层 4 只、取各段中位数（5.5／9.5／16、首领 22）且全部打倒时，队伍进入第 2 层约 Lv8、进入第 3 层约 Lv12、打完第 3 层约 Lv16、击败首领后约 Lv18。进入第 2、3 层时正好在该层敌人等级段的下限，第 3 层的高等级敌人最多高出约 8 级；御三家（Lv16 进化）约在第 3 层末尾进化。玩家常不打完所有敌人（7.4 长测），实际会更低。
8. **等级对数值的作用（工作候选，长测确定）：**
   - 现有的“每级最大 HP＋2、伤害＋1”在原版刻度下增长过快：Lv5 到 Lv20 会多出 15 点伤害。
   - 改为：
     - 最大 HP＝名单基础 HP＋（等级−5）；
     - 伤害等级加成＝`floor((等级−5)÷4)`（Lv5 为 0，Lv21 为 4）；
     - 低于 Lv5 时两项都不为负。
   - 双方用同一公式。

## 14. 主题敌人池（main 的工作候选）

### 14.1 依据

- **用户决定：**
  - 敌我共用一个物种池；
  - 风速狗也作为野生敌人出现；
  - 进化形态按等级出现；
  - 传说与幻之宝可梦暂不作野生出现（用户所选选项：“暂不作野生出现 (推荐)”）。
- **为什么仍是工作候选：** 2026-10-30 main 向用户展示过按属性分主题的预演（按当时名单 160 种计：苔石洞 62 种、潮湿水窟 60 种、灰烬裂谷 28 种；补入 15 种后会有变化）。用户没有提出异议，但也没有明确确认这种分组方式。

### 14.2 规则

1. **候选物种：** 取名单中的所有物种，去掉以下两类：
   - 图鉴导入标为“暂不出场”的物种（`availability`）；
   - 名单中 `legendary` 为 `true` 的物种（即传说与幻之宝可梦；导入时由 Showdown `tags` 得出）。
2. **主题按第一属性分配。** 每个物种只属于一个主题：
   - 苔石洞（第 1 层）：一般、草、虫、岩石、地面、飞行；
   - 潮湿水窟（第 2 层）：水、冰、电、毒、超能力、妖精；
   - 灰烬裂谷（第 3 层）：火、格斗、恶、幽灵、龙、钢。
3. **按等级筛选：** 某层可出现的物种，是该层主题的候选物种中，进化等级不高于该层敌人等级上限的那些（第 13.2 节第 4、5 条）。
4. **挑选：**
   - 每个敌人从该层可出现的物种中等概率挑选；候选列表按名单顺序排列。
   - 使用独立随机序列 `enemy-species`，由远征种子、楼层号和这个标签派生。
   - 先挑物种，再按第 13.2 节第 3 条取等级。
   - 三条独立序列（`enemy-ai`、`enemy-level`、`enemy-species`）的派生方法沿用 `dungeon.ts` 中拾取物与服务点序列的做法：用远征种子、楼层号与该标签对应的固定常数做乘法哈希，再以 `mulberry32` 生成；具体常数由 dev 选定并由测试锁定。
5. **`WILD_SPECIES`：**
   - 改为各主题可出现物种的并集，再加上第 2 节无物种敌人对照的物种。
   - 删除 `LEGACY_WILD`，以及按三档划分的 `pool:{melee,ranged,chase}`。
6. **非首领远征：** 开发者菜单中不带首领的远征，各层都使用第 1 层（苔石洞）的可出现物种，等级取 Lv5。
7. **最终形态暂不出现：** 按第 13.2 节的等级段，进化等级高于 20 的形态（多为各条进化链的最终形态）在当前 3 层迷宫里不会作为野生敌人出现。以后迷宫加深、或主题可以重复时，它们自然会放出来。

### 14.3 验收

- 候选物种的排除规则、主题分配、等级筛选各有测试；同一种子下，挑选结果可以复现。
- 每层至少有一个可出现的物种，防止空池；风速狗在第 3 层的候选中。
- 报告三个主题、各层实际可出现的物种数。
