# 分阶段范围与扩展顺序

**从现在到试开发的执行顺序，以[阶段路线图](从研究到试开发的阶段路线图.md)为准。**本页只维护试开发之后的完整首版与远期内容范围，不能把下表全部变成首次可玩的前置条件。具体预算、角色配置、地图节点和保存职责见[核心玩法与首版范围](../玩法研究/核心玩法与首版范围.md)，具体选择见[代表场景](../玩法研究/伙伴选择的代表场景.md)。

用户已明确：Z 晶、Mega 作为后续扩展更新研究，不进入首批的大量设计；按阶段推进，每一阶段都让游戏系统成立。第一版人数以用户最新明确的三人队为基准，局内同样不扩员；四人队只保留为未来更新候选，不进入首版研究。招募、迷宫和费用细则继续保留为候选。

这是一份当前范围表，不是排期、工期承诺或最终内容数量。日常交流直接报告本轮发现、取舍和真实未决项，不反复提示默认的文档维护方式与当前工作阶段。

关联：[当前决策](../项目目标与当前决策.md)、[运行方式](研究与制作运行方式.md)、[入队与基地培养](../玩法研究/新伙伴入队状态与基地培养.md)、[无尽恢复](../玩法研究/无尽迷宫恢复与局内成长.md)。

## 完整首版候选：一次出发能够改变下一次选择

要成立的体验：带熟悉伙伴出发，途中招到能用的新人，决定继续还是保住收获，回基地后通过一项培养选择改变下次配招。失败后仍能按已有救援和基础收入候选恢复队伍。

| 必要内容 | 首批只解决什么 |
| --- | --- |
| 代表伙伴与战斗 | 少量初始及可招募伙伴；可靠攻击、射程、保护、控制等差异，每名新人有可用基础组合 |
| 队伍与招募 | 以三人队验证跟随、控制与实际概率邀请；初始二人恢复保留，可当场替换、下场回营地待机；具体行动与携物细则待设计 |
| 成长 | 优先比较共享本局等级与个人永久招式库；永久个体等级保留对照，不同时实做两套 |
| 恢复 | HP/PP 消耗、已有恢复品、一次性小额休整；普通出口不兼任免费全恢复 |
| 一张完整普通迷宫 | 基础目标、一个继续选择、普通出口和有限战利品；不要求同时完成全部三张旧样例 |
| 基地培养 | 带回招式机、给选定伙伴学习、下次重配已学招式；可用伙伴免费完成基本出发整备 |
| 失败与回归 | 大部分物资损失、普通伙伴走失、付费等待、到期与两人恢复路线按现有候选衔接 |
| 稀有服务点 | 交换机保持低概率保伙伴定位；商店与装置复用现有候选，不要求每局都遇见 |

这一阶段可以没有 Z 晶、Mega、独立材料合成树、完整进化网络、繁殖与个体值/努力值、招式熟练度、营地建筑、饥饿或疲劳。暂缓不表示永久取消；新增一项时需说明它解决哪个已经出现的问题。

完整首版是否成立，看新人能否立即贡献、老伙伴的配招投入是否有用、继续与撤离是否有理由、失败后是否仍能进行正常探索。不是看系统菜单数量，也不要求先拟完数百种伙伴。

## 首版后的连续区域：已有队伍能适应不同区域

复用完整首版的战斗、招募、等级、物品、休整和结算规则，先用两个区域检查一次连续冒险，再扩展无尽组合。

- Boss 阻挡进入下一区域，战前保留普通出口；跨区不重置 HP/PP、招募名额和救援时钟。
- 奖励主题先复用招式与现成消耗品。道具强化材料、伙伴培养材料在有实际消费用途后分别加入，不先铺四套货币和专用地图。
- 明确深入后带回什么、下一段恢复多少、何时必须考虑结束；不承诺无限生存或每十层重发工资。
- 若恢复型伙伴、局内换招或普通进化能解决已发现的体验缺口，每次引入一类并检查相关资源和保存结果；不把它们一次绑成阶段门槛。
- 等级达到上限后的变化先靠队伍用途、房间与敌人组合、资源和奖励目标；必要时再比较有限的局内构筑选择。

两区域可以说明规则如何连续，但不能代表真正长局已经平衡。区域数量、十层间隔和长局时长继续按体验收敛。

## 后续内容更新：添加新选择，不回头补首批缺口

四人队仅作为未来更新候选保留，当前不展开规则、验证或内容适配。保留 Z 晶主题、Mega、更多培养与强化方法作为后续扩展候选。Z 晶与 Mega 的具体用法、适配范围和成本本轮不继续展开；完整首版的出发、获胜、撤离、培养和救援均不得依赖它们。

“扩展更新”描述内容发布顺序，不要求现在开发插件框架。先用现有伙伴、招式、物品和获取来源承接新内容；当某个新机制实际需要额外规则时，再定义它的生效与保存方式。

既有 Z 晶的来源说明可以保留作参考，但不进入当前首批任务清单，也不在普通样例或无尽前四区中设置必须存在的 Z 晶奖励。首批不预留一堆空白按钮、专用货币和等待未来填补的流程。

## 每次推进的最小交付

按[路线图](从研究到试开发的阶段路线图.md)的完整里程碑组织近期交付：试开发准备包、运行骨架、可玩片段与复盘。每项工作要能说明它服务哪个阶段和哪个观察问题，不把每个局部例子拆成新的决策与审批周期。来源研究只补影响当前里程碑的事实，纸面例子标明假设。

后续制作按：选定这一阶段的候选 → 补足必要状态与例子 → 实际运行完整循环 → 判断体验 → 决定是否进入下一阶段。独立审查用于成长归属、失败、救援与资源恢复等真实交互，不为每个数字或文字开一轮流程。

当前先固定单个试验版本的场景与资源，人数按三人队执行；完整成长、整备、救援经济和首版服务点在扩大范围前处理。共享本局等级与个人招式库仍为工作候选，不为比较另一成长体系而同时开发两套。常规细化连续完成，不频繁停下询问。
