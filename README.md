# 三人地牢试开发

本仓库正在按获准准备包开展阶段3—4：先做能运行、能保存的一轮，再完成探索、战斗、邀请、撤离／全灭和独立重开的单层片段。采用Phaser 4.2.1＋TypeScript与Vite，使用自制几何占位和人工试验数据。本阶段交付私有网页构建，Windows Electron封装留待后续。

## 运行单层试验

使用Node 24.22.1及随附npm，在仓库根依次执行：

```sh
npm ci
npm run dev
```

打开命令输出的本机地址，选择固定有邀请或无邀请对照。方向键移动，点击相邻敌人普攻，先选技能再点目标；“安排伙伴”进入整轮草稿，确认提交后才执行。G和T是交互点，首次可取得并继续或请求撤离，取得后只提供请求撤离。

进度只保存在同一浏览器、同一网页来源。保存失败时先重试；关闭只能恢复最后成功写入的完整状态。终局后可开始独立试验，同时保留上一份结束记录。详见[运行、检查与交付说明](https://github.com/392fyc/pokemon-dungeon-lab/blob/d03ef5144f5671b3b8d5418b94353223742e911a/docs/90-archive/%E8%AF%95%E5%BC%80%E5%8F%91/trial-run.md)。

## 项目方向

- 每局进入随机地牢探索，包含轻度撤离带出机制；伙伴、招式机和特殊物品可用于以后冒险，具体保留和损失规则待设计。
- 可以采用 Pokémon Showdown 数据库，首批阵容从某个时代中选取有限而多样的子集。
- 角色视觉参考 Big Kid Nation 的 Pokémon Arena 2D；研究 PokéBonk 的招式适配、融合及内容生产方法。
- 本片段采用行动推进回合、三人同行、固定队列与一次伙伴干预；数据时代、正式名单、融合和长期经济不在本次实现范围。
