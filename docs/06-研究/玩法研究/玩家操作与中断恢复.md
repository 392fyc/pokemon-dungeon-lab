# 玩家操作与中断恢复

> **2026-10-30 更新：** 用户决定只在回到营地时存档，迷宫内离开回到出发前。本页第 5–7 节中关于迷宫内保存、关闭后恢复原局与迷宫内保存失败的内容，由 [营地存档模型规格](../../04-规格/营地存档模型规格.md) 取代；其余内容不变。

当前推荐：**普通单步直接执行，先安排伙伴时再确认整轮；邀请同屏比较实际落点与能力，保存成功不用确认。**地图负责操作，队伍栏说明谁还能做什么；查看详情按需打开。

本页是 REA-research-lab 的纸面界面与状态方案，经主会话整合。它连接[连续小探险](一段完整探险的连续推演.md)、[伙伴移动与入场](伙伴跟随与倒下通路.md)和[招募取舍](招募资源与伙伴取舍.md)。本页负责界面文案和输入情境，精确规则以[当前规则表](../../90-archive/试开发/当前规则表.md)R02—R11为准；表内提示是这些规则的呈现，不单独定义第二套规则。研究基线已复审合并，控制与保存仍未实现或通过可用性测试。

## 1. 首次进入只解释眼前必要的规则

第一次操作可用三句话：

> 普通移动、普攻或等待直接推进一轮，按队列行动后轮到敌人。想让伙伴配合，先安排一名伙伴，再选择主控动作并提交。邀请会标出新人位置；回营伙伴保留培养，新人下一轮才行动。

常驻显示楼层、目标简况、三个同行实例的准确生命、倒下与主控标识、行动队列、本轮已选动作、伙伴安排是否使用，以及简短保存状态。已发现出口标在地图上，不泄露未探索出口。

```text
第二层　目标：已完成
同行 3/3，其中1名倒下
A［主控］12/20 → B 8/20 → C［倒下］→ 敌方

点选相邻空格移动；点选相邻敌人普攻
[技能] [安排伙伴] [等待] [查看队伍]
已保存：第18轮结束
```

选中角色或招式才展开每招准确的当前/最大 PP、射程、遮挡、目标和代价。本轮选中技能的消耗直接可见。不把不同招式的次数合成一条“队伍总 PP”，也不计算含糊的总战力。

## 2. 普通动作直接执行，伙伴组合才显式提交

当前采用如下语义操作约定，用于设计和计数，键鼠、触屏与手柄绑定尚未实现。一次合法普通输入只推进一轮，不包含自动连走或跨轮指令。

| 操作 | 当前候选 |
| --- | --- |
| 选相邻空格、相邻敌人或等待 | 无伙伴草稿时，分别执行移动、普攻或等待，直接推进一轮 |
| 主控技能 | 先选招式，显示消耗、目标与遮挡；再选目标或方向即执行，不另加通用提交 |
| 安排伙伴 | 先选伙伴与本轮动作，再选主控动作，预览后显式提交整轮 |
| 换位 | 选择相邻伙伴与换位，预览双方占用的动作，在较晚者到序时交换；显式提交整轮 |
| 目标与普通拾取 | 所在格直接显示取得并继续；若兼出口也显示取得并撤离，选择其一记一次动作，进入格仍另用移动 |
| 出口与楼梯 | 选择交互后确认本轮执行，替代通用提交；轮末不再确认同一转场 |
| 切主控与查看详情 | 使用队伍栏明确的主控入口；查看角色详情另有入口，二者不推进世界或改变队列 |

没有伙伴草稿时，也按[规则表R03](../../90-archive/试开发/当前规则表.md#r03-输入与本轮草稿)自动预演前序伙伴的已知默认行动，检查主控到序时动作是否合法；通过后直接执行，不增加确认。地图可轻量显示方向与预计作用，不强制进入预览页。选技能尚未选目标、或正在编辑伙伴草稿时可取消；查看、编辑和取消不推进世界。危险但合法的普通动作不反复询问“确定吗”，用已知威胁和目标提示说明后果。

有伙伴草稿时，方向或目标输入只修改主控计划，不突然执行。地图预览按真实队列，不能画成三人同时行动；换位同时标出双方动作已占用及完成时机。

```text
本轮草稿中：提交前不推进世界
A：强击H，PP 2→1
B：保护A，PP 1→0［本轮指定］
C：等待［邻接主控］
之后：敌方行动
[提交本轮] [返回修改]
```

非法输入给具体原因，例如“目标不相邻”“B会先进入目标格，本轮未执行”“本轮已安排另一名伙伴”“PP 不足”。已知占位冲突在任何人行动前拒绝，不能先让伙伴移动再让主控等待。只有实际执行出现预检无法预知的变化、使后序动作失效时，才显示相应的“本轮等待，未消耗PP”，不自动换招；它与提交前拒绝不同。

必须先建立伙伴草稿，才进入组合编辑；此后可反复修改主控计划与该伙伴动作，并非普通状态下先点主控动作也能留作草稿。伙伴草稿可暂时未完成或当前被挡住，提交前按所选主控动作和真实队列检查，仍不合法才禁止提交。例如先选B射击草稿，再选择主控A移开，按A先动、B后射击预检。轻量预览不展示未知敌人的确定结果。

非法移动不改成普攻、换位或等待，不推进世界。整轮执行后清除伙伴覆盖，即使失效也不延续；已有一名安排时须先取消才能另选。草稿状态持续显示“本轮草稿中”；切主控或明确取消组合会清除伙伴草稿和未执行的主控计划，回到直接操作，不自动执行。关闭详情不清草稿，取消使用明确按钮。

保存或演出期间的动作输入不排队，恢复可操作后不自动执行旧输入或草稿。具体按键重复、误触率和“先安排伙伴再行动”是否直观，仍需实际体验。

结果用简短记录说明实际移动、伤害、PP 和倒下；普通无事移动不弹窗。预览不承诺安全，不显示未知敌人的确定后果。最后敌人倒下后，尚未行动的伙伴仍按本轮输入执行，再完成轮末处理；没有额外的免费展开阶段。

倒下栏写“倒下，仍占同行名额”，选中说明不能行动、正常撤离随队归营、真实邀请可替出且跨层不受限制。地图只留短暂表现后退场，不让身体外观误导通行；倒下不等于已经走失或回营。主控变更提示“B 接任主控，行动顺序不变”。

## 3. 邀请只要求比较人和确认实际位置

真实邀请在完整轮末及全灭判断后显示。没有邀请就没有虚拟候补，也不提示下一场应该招到人。

```text
N想加入　邀请1/2　处理期间不推进回合

新人N                         选定回营：C
生命 10/20                    生命 6/20
强击 1/2 PP                   强击 1/2 PP
变化：同配招，多4生命，强击次数相同
C回营保留学习，本局不能再调回

地图高亮：新人加入这里
处理后：A → B → N；下一轮才行动
其他成员不恢复，共用背包不随替换带走
[确认：C回营，N加入] [改选成员] [拒绝N] [查看队伍/地图]
```

接受前必须看到准确新旧实例、生命、逐招 PP、已学招式归属、实际落点、处理后队列、首次行动时机和必要的主控继任。离队后失去什么作用，要区分“无人装备直线打击”和“有人装备但 PP 为0”，不依据未知房间推荐换最残血的人。

地图直接高亮落点及本批固定的集合位置。详细帮助再解释固定范围与顺序，坐标供研究文档使用，普通面板不用显示内部编号、随机状态或存档字段。

改选和查看不推进世界，查看后返回保持同一资源与集合位置。退出比较视图不等于拒绝；保留“还有邀请待处理”的入口，不能先移动、跨层或主动切主控再回来。拒绝是一项已处理结果，连续邀请中拒绝后一份也不撤销前一份接受。

接受前选回营对象，再确认明确的“N加入、C回营”。拒绝先在当前面板切到“将拒绝N”，再确认拒绝或返回比较，不另开弹窗。关闭、返回或点空白不能拒绝，下一份邀请不继承上一份的按下状态。比较所需资源与落点同屏可见，不要求先开完整队伍面板再返回。

## 4. 四个具体输入的操作结果

坐标与输入对应[统一入场对照](伙伴跟随与倒下通路.md)及[连续招募账本](招募资源与伙伴取舍.md)，均以已成功保存、可操作的邀请界面为起点。未给定的旧成员 PP 由真实状态读取，不在面板凭空补齐。

| 输入 | 玩家看到与可选操作 | 完整结果 |
| --- | --- | --- |
| C在一层倒下；二层A主控(2,2)、B(2,3)，收到N邀请 | 仍显示3/3，C倒下；选C时高亮(3,2)，可确认、改选、拒绝、查看 | C回营，N到(3,2)，队列A→B→N；A/B不恢复，N下轮才行动 |
| 走廊A0、B1、C主控2；C生命6/20、强击1/2，新N同配置生命10/20、强击1/2 | 直接写多4生命、次数相同，替C高亮本格2 | C回营，N在2，队列A→B→N；A暂接主控，整批结束后可免费选N |
| A主控(2,2)、B(2,3)、C(4,2)，依次N替A、M替C | 第一项预览(2,2)、B→C→N；保存后第二项预览(3,2)、B→N→M | B接主控但本批集合位置仍(2,2)；M不改放到B旁的(3,3)；菜单内零次行动 |
| A主控(2,2)、B(1,2)、C倒下；敌占右、下、上 | 替C显示“附近没有位置”，确认不可用；替B高亮(1,2)，替A高亮(2,2)，拒绝始终可用 | 预览失败不先送走C；接受后才完整转移。远处(5,5)空格不用，敌人仍在，有位置不等于安全 |

第三例在第一项保存完成后显示“A 已回营，还有1份邀请”，地图集合标记继续保留即可，不需每项重讲整套算法。第四例的查看和改选不会使敌人再次行动，也不会让玩家在菜单里先腾出一格。

## 5. 撤离、失败与关闭分开表达

到达有效出口后，显示目标状态、当前同行者、倒下者随队归营，并提供“确认撤离／继续探索”。打开面板不等于完成交互；交互动作以[连续推演](一段完整探险的连续推演.md)的明确候选处理，不附送治疗或救援计数。物资详情可以展开，不必全部挤进确认框。

出口和楼梯都提示“使用占本轮行动，敌人仍会行动”。目标或成果兼出口时，“取得并撤离”同一次动作，也须确认；“取得并继续”不请求撤离。楼梯仍另用动作。本轮的确认只做一次；完整轮末确认交互者存活且仍在交互格后，先处理该轮邀请再离开，不弹第二次“确定转场”。邀请面板可显示“本轮结束将撤离／进入下一层，先处理这份邀请”。请求已成立后换下使用者不另付动作。跨层显示集合位置、不恢复资源；入口不可用时留在本层并说明动作已用。具体顺序沿连续推演。

终局分别用“正常撤离”“全队倒下”等准确标题，结果页共用以下结构：

- 伙伴逐人的实际归属；此前已回营者保留培养，不再卷入失败。
- 实际带回、保护与失去的物资。
- 基础报酬是否达标及实际金额。
- 实际新增、推进或完成的救援事项。
- “结果详情”和“回基地”。

倒下不直接写成走失；全灭按已选定的失败配置取得结果，再逐人说明。未定费用、期限与损失数值不能在玩家界面伪造为定值。基础目标与新增成果的一次终局计数沿[现有候选](有效探险与基础收入.md)处理。

“保存并关闭”和“放弃探险”必须分开。关闭后恢复原局，不是正常撤离。若后续采用菜单放弃，应明确它适用的失败后果，不用普通返回按钮静默结束本局。

## 6. 不同中断点分别恢复什么

承诺限于成功保存的完整处理点。未提交动作草稿可不保存，恢复时说明需要重新选择；不恢复半轮、半次换位或半次替换。

| 成功保存的中断点 | 重新进入后的结果 | 不得重复的内容 |
| --- | --- | --- |
| 普通完整轮末，无待处理邀请 | 同层同位置、同生命与PP、同世界结果，进入下一轮编辑 | 刚结束的动作、扣PP、掉落 |
| 轮末产生邀请，尚未处理 | 同一邀请、同批集合位置、顺序与新人资源 | 重抽资源、自动接受、先执行下一轮 |
| 一项邀请已处理，仍有下一项 | 保留回营、入场、队列与主控继任，继续下一项 | 第一项转移、依据继任主控重选集合位置 |
| 出口或跨层请求已成立 | 邀请未完则继续处理；已完则执行待转场；已转场则恢复目标层 | 交互动作、同批邀请、落点初始化；不能重置旧层敌人与物品 |
| 终局结果已定，尚未回基地 | 同一结果页，继续回基地 | 走失判定、报酬、救援计数；不能恢复为仍可获利的探险 |

## 7. 保存完成后再允许下一项改变状态的操作

当前推荐每个完整处理点保存成功后，再开放下一项改变游戏状态的操作，避免多段未保存结果叠加。这会有短暂停顿，是否可接受仍需实际样例；不先用账号、云存档或服务器结算扩大范围。

保存成功只更新常驻小字，不弹“保存成功，请确认”。保存中和失败时仍清楚显示状态；成功后不自动提交玩家未执行的草稿。

| 状态 | 玩家提示 | 允许 | 暂停 |
| --- | --- | --- | --- |
| 已保存 | “已保存：第18轮结束”或“N已加入” | 当前流程允许的下一轮、下一邀请或回基地 | 无额外限制 |
| 正在保存 | “正在保存，请稍候再关闭” | 查看地图、队伍、招式与结果；无待处理邀请且非终局时可编辑未提交动作 | 提交、确认或拒绝下一邀请、跨层、进入基地及后续消费 |
| 保存失败 | “最新结果未保存，画面保留；关闭可能回到第17轮结束” | 查看、比较、重试保存 | 新行动、接受或拒绝、终局继续及基地状态变化 |

失败提示同时列最后成功保存点；一个都没有时写“尚无可恢复记录”，不能继续显示已保存。邀请项已经在当前画面完成但保存失败时，写“N 已加入，但这次变化尚未保存；暂不能处理下一份邀请”。

重试只保存当前完整结果，不重新攻击、抽取、回营或发报酬。终局保存失败保留结果页，不重算失败，也不开基地操作。玩家仍可能直接关闭程序，未保存的最新结果可能丢失；这套文案和状态要求不宣称任意强退零损失或本地防篡改。
