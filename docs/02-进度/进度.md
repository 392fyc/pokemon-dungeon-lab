## 已知问题

- **机器人胜率偏高，平衡放到最后**（D-20261104-01、D-20261110-02）：见上一节的数据，高于目标；等地图、队伍与祝福组合、敌人成长这些系统完善后再做。#168 暂停，首领 HP 倍率保持 4（倍率 3.0 在当时基线上实测 59.1%，见 #168 评论）。平衡只用机器人测过（四种打法），没有真人数据。
- **队长被混乱队友打倒后引擎不校验指令**（#211）：长测探测到非法移动被接受；玩家能否触发待查，长测在这种情况下跳过探测。
- **地形图块是原版素材**：私有构建默认用 PMDCollab 提取的原版迷宫图集，没有授权文字；公开发布前必须换成升级后的程序画师（D-20261103-12）。
- **换层生成变慢**：#178 的生成约束和 #200 的真转弯保证让单层生成平均约 24 ms，单独运行最大约 0.2 s，换层时可能有一次轻微卡顿。2026-11-11 在 Windows 本机用 `tools/terrain-stats-178.mjs` 复测 3000 层（1000 个种子 × 3 层）：平均 24.5 ms，中位 17 ms，p99 112 ms，最大 186 ms，数据仍成立；游戏里实际换层是否卡顿没有实测。
- **手机宽度没有设计，v0.2 前不考虑**（用户 2026-11-11，D-20261111-04）：界面设计稿只画了电脑宽度；390×780 下营地等比缩小，字和角色偏小；320 宽的睡眠标签已修，361—375 宽没有实测。
- **招式特效的小瑕疵**：密集群体招式的浮字和相邻 HP 略有重叠；飞行粒子飞过目标时会短暂画到未揭示区域和墙上，轨迹只由已显示的位置算出，不泄露地形。2026-11-11 核对代码：浮字（`src/render/playback.ts` 的 `floatText`）没有按相邻单位错开，只有同一单位的多条状态浮字错开；只有“同房间”类招式的粒子按已揭示格裁剪（`src/render/combat-effects.ts`），飞行类没有。没有后续修复的提交或 Issue；画面上现在是否仍可复现待查。
- **天赋内容待重做**：现有三项继续生效，内容以后由用户和 main 一起重做，见 [#201](https://github.com/392fyc/pokemon-dungeon-lab/issues/201)。
- **长测性能**：8.2 大地图上长测耗时约为 8.1 的 4.6 倍；#128（PR #130）优化寻路后约减少 34%。剩下的主要开销是每条命令的整局状态复制（`structuredClone`），暂未处理。单轮游戏响应估计仍是毫秒级，没有实测。
- 结算画面在 v0.1 只有“收获型奖励”有内容；深度和难度奖励自 8.5 起列出探险队经验；营地任务奖励写“本局无此项奖励”，等 v0.2 填入。
- 开发者模式可用网址参数 `?dev=1`、`?fixture=` 打开（`src/main.ts` 第 51—52 行，浏览器检查需要），私有构建保留；公开发布前要处理。
- **构建分块**：某轮 Windows 正式构建（日期待查）的标题入口 6,341 字节、游戏逻辑 387,182 字节、图鉴与招式数据 518,472 字节、Phaser 1,367,250 字节。标题按需加载游戏；既有性能测量见 [PR #105](https://github.com/392fyc/pokemon-dungeon-lab/pull/105)。
