# 阶段5 观察记录表

每位体验者、每次观察复制一份填写。观察要回答的问题和三种结论见[路线图](../项目框架/从研究到试开发的阶段路线图.md)的“阶段5”一节，任务与提问方式沿用[验收与观察场景](试开发验收与观察场景.md)的“未来观察”一节。这张表只负责把实际发生的事记下来，不设满意率或分钟数门槛，也不把少量样本推广成"多数玩家喜欢"。

## 二、任务顺序

1. **首次探索**：只告诉体验者"完成目标后由你决定是否继续"，不给路线答案，不提 R 的位置，也不提返回的办法。
2. **比较这份邀请**：在 N 想加入时，请体验者先说出会留谁、换谁、为什么，再做决定。
3. **安排一次伙伴配合**：请体验者用一次"安排伙伴"或"换位"完成一个自己想做的动作。
4. **保存后关闭再回来**：在任意一轮结束后关闭页面再打开，请体验者说出恢复后的状态是否和离开时一致。
5. （可选）首次探索结束后，再单独观察 V1 或倒下变体；不要在首次探索前透露。

## 四、事后提问（记原话，不替体验者概括）

- 刚才为什么留下（或换掉）这名伙伴？
- 你是在什么时候决定返回、继续或撤离的？是什么让你这样决定？
- 哪里和你预想的不一样？
- 有没有哪一步你想做却做不出来？
- 你愿意再玩一次吗？（另外记下体验者是否真的主动开始了下一局）

## 五、整理时分开归类

把每个问题归入下面一类，不要混在一起：

| 类别 | 例子 |
| --- | --- |
| 程序故障 | 显示的计划与实际执行不一致、保存恢复出错 |
| 信息看不懂 | 不知道自己为什么受伤、看不懂拒绝原因 |
| 意图难以表达 | 知道想做什么，却找不到操作方法 |
| 选择本身缺乏吸引力 | 看懂了，但觉得留谁、换谁都无所谓 |

少走路不等于觉得无聊；接受一份明显有利的邀请，也不等于这里没有玩法。没有独立体验者时，这张表保持空白，相关结论标为未验证。

## 六、自测阶段已知、需要特别留意的问题

详见[阶段5制作者自测](../项目框架/阶段5制作者自测-2026-10-30.md)：敌方行动的结果不显眼、组合草稿看不出执行顺序、敌人的伤害和射程不显示、草稿中的拒绝提示写着“本轮未执行”、交互点标签被单位挡住、窄窗口下地图与操作区不在同一屏。观察时记下体验者是否在这些地方停顿或误解。
