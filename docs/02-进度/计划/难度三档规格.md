# 难度三档规格

状态：草稿，等实现合并后把结论收进[游戏规则](../../01-现行规则/游戏规则.md) G2、G7.4、G9.6 并删除本页。用户决定见[决策登记](../../03-决策/决策登记.md) D-20261101-01；选项包与用户原话在 [#110](https://github.com/392fyc/pokemon-dungeon-lab/issues/110)。

## 1. 目标

出发前可以选简单、普通、困难三档；三档只改敌人（含首领）的 HP 与伤害倍率，不改敌人数量、招式、地图与玩家数值。普通档是 0.4（能力值伤害合并时由 0.5 改定）。

## 2. 规则

| 档位 | 倍率（敌人 HP 与伤害） | 基础报酬 | 说明 |
| --- | --- | --- | --- |
| 简单 | 0.28 | 100 | 首领 HP 约 39 |
| 普通 | 0.4 | 100 | 普通倍率随能力值伤害由 0.5 改为 0.4（PR #115）；首领 HP 56 |
| 困难 | 0.56 | 150 | 首领 HP 约 79 |

- 倍率作用点：`speciesMaxHp(…, multiplier)`、`resolveDamage` 里敌人出手的那一步，以及现在直接读 `ENEMY_DIFFICULTY` 的 `src/core/engine.ts:110`、`:316`（AI 估算伤害）和 `tools/soak/balance.mjs:18`；首领沿用 `hpMultiplier × 倍率`，不单设。倍率与困难档报酬是 main 工作值（D-20261101-03）。
- 救援费 60、钱袋、期限、走失概率三档相同。
- 档位在**出发前**选，每局可改；默认是上一次出发用的档位，新存档默认普通。
- 一局进行中不能改；结算画面显示本局档位。

## 3. 界面

出发前面板（`#purse-picker` 附近）加一行“难度：简单／普通／困难”三选一，下方一句说明：“简单：敌人更脆、打得更轻。困难：敌人更硬、打得更重，基础报酬 150。”结算面板“本局结果”标题后加“（困难）”之类的档位标记，普通档不标。

## 4. 存档

- `Profile` 新增 `difficulty:'easy'|'normal'|'hard'`，出发时写入 `World`（`s.difficulty`），局内所有倍率读 `s.difficulty` 对应的值，不再读全局常量 `ENEMY_DIFFICULTY`。
- 存档版本升为 `trial-rules-5`／`trial-content-5`：旧 `-4` 营地档案读入时补 `difficulty:'normal'`，其余字段不变；导出导入沿用现有校验。**版本号变更须由用户确认**（协作文档第 6 节）；确认前 dev 可以实现，PR 合并等确认。
- 开发者场景（`?dev=1`、`?fixture=`）固定普通档。

## 5. 测试

- 单元：三档倍率下敌人 HP 与伤害的例子；首领 HP 39／56／79；困难档报酬 150；旧 `-4` 档案迁移补 `normal`；`-5` 档案往返一致。
- 浏览器：出发前切到困难→出发→敌人信息里的 HP 与普通档不同；刷新后档位保留；结算显示档位。
- 长测：`tools/soak/balance.mjs` 加 `--difficulty easy|normal|hard`，main 在合并前跑三档各 30 种子 tactical，记进进度页。

## 6. 文件分工（dev）

`src/core/dungeon.ts`（三档常量）、`src/core/engine.ts`（读 `s.difficulty`）、`src/core/roster.ts`（`speciesMaxHp` 调用点如需）、`src/core/base.ts`、`src/core/save.ts`（字段、版本、迁移）、`src/core/economy.ts`（困难档报酬）、`src/app/game.ts`（出发前选择、结算标记）、`tests/core/*`、`tests/browser/*`、`tools/soak/balance.mjs` 与 `tests/core/soak-bot.mjs`（`--difficulty` 参数，与 main 协调后改）。

## 7. 验收

`tsc`、`npm test`、`npm run test:acceptance`、`npm run build`、`npm run test:browser` 通过；PR 带 `lane:dev`、`Refs` 对应 issue、`KB:` 行写明“游戏规则 G2、G7.4、G9.6 与决策登记由 main 合并时更新”。
