# 救援机制案例与风险验证

当前规则以[核心玩法与首版范围](核心玩法与首版范围.md)为准。本页用于案例和风险对照：首版同行最多三人；首版地图当前候选可返回G，单向推进仅作对照。具体概率、费用和参数仍未验证。

核查日期：2026 年 10 月 25 日。依据用户最新补充和[当前救援框架](伙伴招募与委托救援框架.md)。用户已选择未付费期限按后续有效探险计数，并明确等级解锁高风险高收益任务、由玩家选择的关系；当前推荐完成公开目标或保留新增跨局成果才计有效，完成目标才发基础报酬；这些条件与最后付款窗口仍是候选，详见[有效探险与基础收入](有效探险与基础收入.md)。本页区分官方先例、纸面推演和待实现验证，没有运行游戏原型。

## 两段时钟与连续全灭的纸面例子

假定入池期限 L = 4、付费等待 X = 2，采用本轮推荐的目标/成果判定与到期局最后付款窗口。下列甲、乙、丙均完成基础目标，故不论成败都是有效局；立即退出那局没有完成目标或取得任何新增跨局成果。B 是更早入池的伙伴，已经用掉两次期限，所以从剩余 2 次开始。数值仅用于检查。

| 事件 | A：已付费 | B：未付费 | C：本次新走失 |
| --- | --- | --- | --- |
| 探险甲出发前 | 等待 2 次 | 期限剩 2 次 | 随队可用 |
| 甲达标后全灭，且 C 判定走失 | 等待 1 次，委托不取消 | 期限剩 1 次，无额外全灭扣罚 | 完整 4 次入池，不扣本局 |
| 另一局无目标、无新增成果，中止退出 | 计数仍为 1 | 计数仍为 1 | 计数仍为 4 |
| 探险乙完成有效结算 | 到期回归 | 期限归零，进入最后付款窗口 | 期限剩 3 次 |
| 乙结算后给 B 付费 | 可用；本例随后留在基地 | 立即受保护，等待 2 次 | 未付费，仍剩 3 次 |
| 探险丙达标后再次全灭 | 未参战，不判走失 | 等待 1 次，不重置、不失败 | 期限剩 2 次，仅正常流逝 |

若乙的最后窗口结束时 B 仍未付款，按候选规则永久失去 B；不会因为 A 的委托完成而自动救回 B。中止那一行只不推进计数；本轮候选仍按失败处理物资和普通参战伙伴，新走失者以完整 L 入池。无效不意味着免除损失。

A 到期归队时不在刚结算的参战名单内，不能在乙再次被判走失。C 的加入不占用 A、B 的名额，救援池不是串行队列。

## 最后一次收入的例子

另设伙伴 D 未付费，剩余 1 次，报价 100，基地余额为 0。本次完成公开基础目标，按收入候选可获得净基础收入 100。只保留新成果而没有完成目标的有效局，不自动发这笔钱。

推荐顺序是：先入账 100 → D 的期限归零 → 玩家有最后付款机会 → 付款后 D 进入 X 次等待，下一局才开始推进；结束窗口仍未付款才永久失去。若先删除 D 再发钱，玩家会在明明凑齐费用时失去伙伴，这正是付款窗口要避免的情况。

如果同次有两只 D、E 到期且各需 100，这笔 100 只能保护其中一只。是否允许出现这种必须取舍的局面，是平衡与体验问题，不能通过调整结算顺序假装资金已经足够。

## 连续失败与低资产恢复

[有效探险与基础收入](有效探险与基础收入.md)给出三名伙伴、零余额、每次达标报酬 100、单只费用 100、L = 4、X = 2 的逐局表：目标前无成果失败不推进；三次达标后全灭分别付款 A、B、C，A 在第 3 次有效局回归，B、C 在第 4、5 次回归。表内时钟与余额已按事件顺序计算，没有运行游戏原型。

这条恢复路径依赖免费基础目标确实能由初始二人完成。最低路线建议无强制战斗，目标处可撤离；正常迷宫多次失败后可转做该路线。门槛前失败不赚钱、不推进已付费等待，属于明确取舍。

## 探索段、出口与恢复负担的检查

用户已允许 B 作为候选继续研究。新增任务与局时建议见[基础勘探任务与单局节奏](基础勘探任务与单局节奏.md)，阶段出口与收益比较见[撤离点与深入探索收益](撤离点与深入探索收益.md)。

假设出发前 A 已付费剩 2 次，B 未付费剩 1 次；C 是本局普通参战伙伴：

| 本局事件 | A、B 的计数 | 物资、队伍与收入 |
| --- | --- | --- |
| 首段完成基础目标，经过第一出口选择继续 | 均不变 | 取得一次基础报酬资格；背包和 C 没有存回基地 |
| 第二段经过出口继续 | 均不变 | 没有第二笔基础报酬，不回血补货；仍是同一局 |
| 第三段全灭且 C 走失 | A 剩 1 次，B 归零 | 发本局已赚报酬，处理物资；C 以完整 L 入池 |
| 基地最后付款窗口 | A 不额外推进；若付 B 则 B 获得完整 X | 可以用本次刚入账的收入付费；C 不倒算刚结束的探险 |

如果第一出口直接撤离，也只推进一次，不会因“撤离”和“目标完成”各算一次。局内暂停后恢复仍是同一局，不推进任何池内次数。此例只检验候选顺序，没有运行地图或存档。

| 反例或场景 | 必须解释的结果 |
| --- | --- |
| 三只伙伴都需筹款，玩家只为等待重复跑最低路线 | 短局 4 分钟、每局挣一只费用、X = 2 的假设下仍要 5 局约 20 分钟；目标变化不能消除这项成本 |
| 玩家选继续后才发现旧出口不可返回 | 当前首版可返回G；单向推进仅作对照，若以后采用须重新明确方向并在继续前提示，不能悄悄关闭旧出口 |
| 普通任务也有基础工资，却被要求先完成专用恢复关 | 不符合共享前段建议；正常探索应能直接筹款和推进救援 |
| 最低二人缺某种属性，基本观察点无法到达 | 不符合最低恢复目标；必须存在不靠指定伙伴或道具的普通路径 |
| 路过普通出口便自动把新伙伴和袋外物资送回，再继续 | 普通出口不增加保护；用户新提案的交换机通过明确选择安全转移一名成员及有限物资，与整队撤离分别处理 |
| 玩家因现实事务中断 | 使用稳定回合保存，恢复同局；不要求再走到下一出口，也不等于合法撤离 |
| 高收益深段吸引玩家，但大部分价值已在背包中 | 可以合理选择早撤；“继续比例更高”不是唯一验收目标 |

## 队伍数量与任务风险的概率影响

假定一次全灭后，每名普通伙伴独立以 p 的概率走失。n 名普通伙伴至少走失一名的条件概率为 1 - (1 - p)^n，平均走失数量为 np。

| 示例 | 至少走失一名 | 平均走失数量 |
| --- | --- | --- |
| p = 20%，n = 1 | 20% | 0.2 |
| p = 20%，n = 2 | 36% | 0.4 |
| p = 20%，n = 4 | 59.04% | 0.8 |
| p = 20%，n = 6 | 73.7856% | 1.2 |
| 三名普通伙伴，某任务 p = 10% | 27.1% | 0.3 |
| 三名普通伙伴，另一任务 p = 30% | 65.7% | 0.9 |

以上为公式计算，不是正式概率、任务档位、队伍上限或实机模拟；分母是“已经全灭的局”。不同任务的 p 需与其实际入账、全灭概率、救援费和局时共同评价。等级提供任务选择，具体风险来自玩家选择的任务。详情见[等级与失败成本](救援队等级与失败成本.md)。

费用按每只 C 计算时，同时走失 m 只仍需 mC。并行省掉串行等待，不减少费用。不同剩余期限还会造成付款先后问题，不能只检查全部伙伴最后总价。

## 边界场景清单

| 场景 | 用户提案或候选应给出的结果 | 状态与需要补齐的内容 |
| --- | --- | --- |
| 初始二人留基地，全普通队出发 | 允许；全灭只判该队普通伙伴 | 自由编队是用户提案，首版同行上限已定三人 |
| 所有普通伙伴走失 | 初始二人可继续出发 | 免费基础路线与默认补给为配套建议 |
| 初始主控只是在战斗中倒下 | 不提前结算全队走失 | 按[规则表R06](../../90-archive/试开发/当前规则表.md#r06-倒下与主控继任)处理退图与继任，不提前结算整队失败 |
| 切换队长或招募同种御三家 | 不自动获得初始角色保护 | 身份绑定为代理建议 |
| 已付费与未付费伙伴同时在池中，玩家又全灭 | 不重新判走失、不加收费用；目标完成或保留新成果才推进 | 当前推荐条件，尚待选择 |
| 目标前全灭，只有出发时带入的旧保护物品 | 无工资、不推进旧池；仍按失败结算本队 | 旧物品返回不是新增成果 |
| 目标前带回新保护物品或新伙伴 | 无基础工资，L、X 都推进一次 | 跨局成长口径需随保留规则补齐 |
| 完成目标后全灭或菜单中止 | 一次基础报酬、一次计数，普通风险不免除 | 同局多次提交不能重复领取 |
| 低风险路线完成目标后退出 | 同地点合法出口可正常撤离并领取报酬 | 实际时间要与故意中止比较 |
| 本次新伙伴走失，同时旧订单回归 | 新失散拿完整 L；旧返回者不参与本局判定 | 纸面顺序已明确，未实装 |
| 多只订单同次到期 | 全部各返回一次 | 不需等救援空位 |
| 未付费伙伴 L 归零 | 先发收入，再提供最后付款窗口 | 窗口是代理候选，需选择 |
| 最后窗口期间关闭游戏或离线多日 | 恢复窗口，不按现实时间扣次数 | 探险时钟已选，保存方式待实现 |
| 付费瞬间、扣款后关闭游戏 | 同一保存结果，不能有扣钱无订单或重复扣款 | 后续存档验证要求 |
| 余额为零但有基础路线 | 能出发；是否来得及救回全部伙伴看净收入与期限 | “能出发”不能代替经济验证 |
| 救援队升级后继续原任务，或池中仍有旧委托 | 相同任务条件仍用同套风险；按报价/等待锁定候选，不改变旧单 | 具体费率与报价锁定方式未定 |
| 新招募伙伴接受加入后全灭 | 候选按普通伙伴抽取走失 | 新伙伴跨局归属待选择 |
| 普通伙伴走失，保护袋内有招式机 | 物资与伙伴分别结算 | 共享保护袋是候选 |
| 伙伴获救或未付费到期 | 不重复生成已丢物资、不再次扣保护物品 | 装备保留规则仍需设计 |
| 故意快速全灭 | 无目标无成果时无钱无计数；达标或保留成果时按对应规则结算 | 不能宣称所有快速失败收益都已消除 |

## 需要带进后续试玩的反例

**有成果但拿不到基础工资。** 目标前失败若保留了新伙伴、物品或未来选定的跨局成长，仍算有效并推进期限。玩家可能得到非货币成果却没有救援现金，需要明确提示并提供可达基础委托；不能把所有早期失败都描述成冻结期限。

**门槛一直达不到。** 无目标无成果的局冻结两段时钟，因此已付费伙伴也暂不回归。必须实际验证基础路线无强制战斗、初始二人能做完，不能仅将通关门槛改名为基础任务。

**标注收益提高，但实际净收入覆盖不了损耗。** 高阶任务虽然能找到更多物资，若频繁全灭导致实际入账很少，再叠加多人救援费，就可能长期收不抵支。需要比较包含成功与失败的多局收入和全部救援负担；任务宣传收益或单只救援费占比不足以证明可负担。

**先装保护袋，再故意快速失败。** 即便没有基础工资，新物品自身仍有价值，快速失败可能比远距离撤离有效率。本轮让有成果的局推进期限，阻止一边获利一边冻结旧池；没有声称因此消除了所有故意失败策略。基础路线通过目标处正常出口减少绕路动机，标准迷宫仍需测量。

**总钱够，但最早到期者先消失。** 五次后能存够总价，不代表第一只在两次内就能付费。期限检查必须按每个到期点算，救援池应能清楚排序。

这些是规则设计和后续验证的输入，当前没有为了文档写一套镜像程序充当游戏测试。

## 商店、伙伴交换机与费用的新例子

完整推演见[迷宫样例](迷宫与任务样例推演.md)、[服务点](迷宫商店与伙伴交换机.md)、[费用与等待](救援费用与等待次数推演.md)。一手先例与 PDF 页码集中在服务点文档；该功能组合属于本作提案。

| 场景 | 当前候选结果与限制 |
| --- | --- |
| 新招募伙伴携新物资先行撤回，余队后来全灭 | 已送回成员和物资安全，不再判走失；最终有新成果所以有效，达标才发工资；一次计数 |
| 旧成员空手送回，未达目标且无其他新成果就中止 | 已撤回成员安全，但单次旧对象移动不创造工资或有效计数；留队者照常承担失败 |
| 全灭后载入，重新触发装置 | 保存需恢复同一成员、物资与已用额度，不能重复得到货物；尚未实现 |
| 实际遇到稀有装置、撤回一人后继续 | 缺员不会自动补齐；要再次击败合格敌人并触发邀请，且新成员未必匹配原作用。只有这些条件实际共同成立才评估代价偏低 |
| 保护袋加两份运输覆盖所有重要物资 | 本次物资风险可能很低；要统计所保价值，不能只数格子 |
| 卖旧物把售款带回、或买回同一旧物 | 不是新增探索成果；若无目标或其他成果，不凭交易动作计有效 |
| 目标前用旧钱买店内新商品并保留 | 新补充候选按真实新取得物品计有效，无基础工资；允许有成本的购物短局，不宣称已消除所有加速策略 |
| 基础报酬100尚未入账，局内钱只有30，想买50的商品 | 不能透支工资或自动扣基地救援金；本例不能买 |
| 三人各60，零余额、每次净得100，X=1 | 第1局付一人、第2局付两人、第3局全部返回；若导致走失的失败局已有100，后续只需两次有效局 |
| 四名各80，再连续两局各新增两名，收入始终每次100 | 即使第7次总收入700大于总价640，也可能在第6次到期窗口失去一名；详见逐局表 |

以上结果不证明所有初始队伍可过图、每次都能招到替补、或任何连续失败都能救回全部伙伴。

| 满员遇到新邀请，只想送旧成员安全回家 | 接纳实际邀请并替换时，可以让原成员回营地待机，保留其个人培养 |
| 满员唯一新人倒下 | 按[规则表R06—R08](../../90-archive/试开发/当前规则表.md)仍可替出，跨层资格不变；倒下退图不占地图格，仍占同行名额 |
| 本局新人 N 被交换机撤回 | N 安全保存、不能再参战，最终属于新成果 |
| 本局新人 N 被替换，接纳 M | N 回营地保留并作为真实新实例参与最终成果判定；M 必须已触发邀请，携物处理待定 |
| 当前遭遇有邀请但队伍在接受前全灭 | 未接受者不变成可保存或可救援的新伙伴 |
| 撤回后连续几场战斗均无邀请 | 队伍保持缺员；不保证生成装置、增加概率或补一个队员 |
| 本局送回恢复伙伴后招到控制伙伴 | 人数补回不等于恢复原作用，需换路线、用物品或正常撤离 |
| 无尽第十层，玩家不想打 Boss | 战前普通出口可结束；打赢 Boss 是进入下一区域的条件 |
| 连过多个 Boss 和区域 | 同一局，不重发保证工资、不额外推进 L/X、不自动治疗或从基地调人 |
| 无尽每区各自低概率生成装置 | 长局累计可能趋近必遇；当前另比较整局至多一个生成机会，具体概率未定 |
| 缺特定属性或某只伙伴 | 基础目标与普通出口应有普通路径；高级任务可以有难度，但不能靠随机招募作为唯一通行条件 |

邀请示例的 34.39%/56.95% 和装置多区累计的 65.13%/87.84% 只来自独立等概率假设，未测招募率、出现率或胜率。

## 新伙伴成长与无尽恢复的边界

关联：[入队与培养](新伙伴入队状态与基地培养.md)、[恢复与成长](无尽迷宫恢复与局内成长.md)、[分阶段范围](分阶段范围与扩展顺序.md)。以下使用共享本局等级的 B 候选，不把它与有效探险方案 B 的名称混成同一个已批准选择。

| 场景 | 当前成长候选的结果 |
| --- | --- |
| 新人加入前队伍本局 12 级 | 使用同一本局 12 级，不给队伍补发经验，不复制老伙伴个人招式机投入 |
| 深层招到新人后撤离 | 保留伙伴与基础招式，不把本局高等级变成永久等级 |
| 升级使最大 HP 100 变 110，当前 35 | 当前仍 35；不回血、不回 PP、不复活 |
| 战斗有经验，但目标前失败且无其他保留成果 | 临时经验不计有效，无工资、无 L/X 推进；实际物资损失与走失仍处理 |
| 新人最终进入救援池 | 保留新实例，按有效候选推进旧池一次；新人本局不扣 L |
| 旧招式机在基地教给老伙伴 | 个人学会、物品消耗；不追溯改变已结束探险、不重复推进 L/X |
| 新招式机在普通背包全灭丢失 | 没有凭此永久学会；若无其他条件，不凭丢失的物品判有效 |

| 满员替换新人，再接受另一真实邀请 | 原新人回营地保留，新人只初始化一次；剩余成员不因此恢复，个人培养不复制 |
