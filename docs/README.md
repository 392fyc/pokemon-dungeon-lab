# 宝可梦游戏研究总索引

本研究库为宝可梦题材游戏的体验与制作方法提供依据。当前目标是通过完成一个作品展示个人能力，并让更多玩家喜欢；变现不是核心。优先研究救援队式探索与肉鸽地牢的新玩家体验，以及模型与素材、技能、特殊系统和发布管线。各专题以各自核查日期与构建为准。

## 当前研究与审核状态

2026-10-28，PR #1经[复审](https://github.com/392fyc/pokemon-game-research/pull/1#issuecomment-6469667742)及用户批准，以[ce6058e](https://github.com/392fyc/pokemon-game-research/commit/ce6058e20ff2307bdc1a685386f014411a7b4f28)合入main，作为研究基线。原报告未验证的历史正文、外部事实和库外证据仍未验证；合并不批准玩法、数值或实现。

PR #2已通过[固定提交3123483的复审](https://github.com/392fyc/pokemon-game-research/pull/2#issuecomment-6472957606)，并于2026-10-29（本地时间）经用户批准以[9ca775a](https://github.com/392fyc/pokemon-game-research/commit/9ca775a21bc68e2cfa712aa4622ce5cd16ce1e8e)合入main。已合入内容包括[首片段方案](玩法研究/返程与招募的首片段方案.md)、[返回对照](玩法研究/可返回出口的探险对照.md)、[招募对照](玩法研究/招募奖励与服务点取舍.md)与[当前规则表](玩法研究/当前规则表.md)；合并树与复审树一致，仍不代表玩法定稿或游戏实现获准。

PR #3路线方案已以[06cf1c0](https://github.com/392fyc/pokemon-game-research/commit/06cf1c010af01728742d73444b67c5e884a8d7f5)合入main，文件树与已审核1555ec6一致。当前[试开发准备包](项目框架/试开发准备包.md)完成阶段1—2材料，PR #4已改为面向main；32931fe通过[独立审核](https://github.com/392fyc/pokemon-game-research/pull/4#issuecomment-6476246314)。两条建议与合并状态的后续补充见[审核记录](审核请求/2026-10-29-试开发准备包.md)，不冒称新提交已复审。阶段3仍待一次开工确认，之后连续完成运行骨架和单层片段；本轮未开始实现。

三人同行是已定约束，其他数量仅作预算；发布经验只参考用户列出的八款游戏，自有mod只作素材、技能与系统参考。当前目标见[创作目标](项目框架/创作目标与地牢研究重点.md)，双云任务与来源见[分工记录](市场研究/研究范围与双云分工.md)。免费开源仍是意向，不改变素材许可或仓库可见性。

## 地牢候选资料与研究路线

当前先看[准备包](项目框架/试开发准备包.md)、[短规格](玩法研究/单层试开发短规格.md)和[规则表](玩法研究/当前规则表.md)。试验采用G4／T7／R9主图，比较6轮结束、9轮探看返回、11轮取物，以及同图留C或换N的11轮承伤对照；完整输入和结果见[验收场景](玩法研究/试开发验收与观察场景.md)。保留当前跟随，普通单步直接执行、伙伴组合才提交。既有[核心玩法范围](玩法研究/核心玩法与首版范围.md)、[节奏研究](玩法研究/探索节奏与操作简化.md)和[早期紧凑图](玩法研究/一段完整探险的连续推演.md)保留各自输入，不混算不同地图轮数。这些是纸面规格，不是体验结论。

规则细节见[伙伴跟随与倒下通路](玩法研究/伙伴跟随与倒下通路.md)和[招募资源与伙伴取舍](玩法研究/招募资源与伙伴取舍.md)：倒下跨层仍可替、所有新人统一入场，容许换人补资源；用可用配招体现旧伙伴同行价值。局部[代表场景](玩法研究/伙伴选择的代表场景.md)与连续账本分别说明计算范围，不能把遭遇截断位置当成下一场开局。发布取舍另看[八款参考游戏的发布与维护经验](REA辅助研究/八款参考游戏—发布与维护经验—2026-10-27.md)，不使用自有 mod 作为发布依据。

已定方向：[三人队当场替换与营地待机 v0.6](审核版本/2026-10-25-v0.6/审核入口.md)；人数范围沿用[首版三人队 v0.5](审核版本/2026-10-25-v0.5/审核入口.md)。三人走廊与操作证据见[v0.4](审核版本/2026-10-25-v0.4/审核入口.md)，其数值仍为候选。控制与房间规则基线见[v0.3](审核版本/2026-10-25-v0.3/审核入口.md)。成长、普通单局与失败账本见[v0.2](审核版本/2026-10-25-v0.2/审核入口.md)。完整框架基线保留为[框架审核 v0.1](审核版本/2026-10-25-v0.1/审核入口.md)；各版均不以文档检查代替用户玩法裁决。

当前分工见[市场与管线研究](市场研究/研究范围与双云分工.md)；[游戏项目路线](项目框架/游戏项目路线.md)负责汇总，[REA 辅助研究路线](项目框架/REA辅助研究路线.md)负责外部制作实现。公开源码足够时直接研究，新的技术报告集中在[REA 结果目录](REA辅助研究/README.md)。

## 当前最有用的结论

技术路线已选 Phaser 4 + TypeScript，网页先用于开发验证，Windows 使用同一游戏代码加 Electron 封装；依据见[引擎决策](技术选型/二维迷宫引擎决策.md)。用户已选行动推进回合，并明确选择未付费救援期限按后续有效探险计数，离线不扣次数。

当前用户参考提案包括自由编队、初始主副不走失、非 Boss 概率招募、全灭时普通伙伴概率入池、未付费到期永久失去、付费后等待固定次数必定回归，以及大部分物资损失与少量保护。等级解锁高风险高收益任务、玩家选择任务与撤离、救援成本与对应产出配套的关系已由用户明确。用户已允许[有效探险与基础收入方案 B](玩法研究/有效探险与基础收入.md)作为候选继续研究：目标报酬、成果计数与短基础路线。当前沿基础目标兼容正常探索、阶段保证出口和自愿深入的方向，形成溪谷、矿道、遗迹三组[具体样例](玩法研究/迷宫与任务样例推演.md)，纳入商店和队员携少量物资先行撤回装置。用户已明确装置低概率出现、主要保护伙伴，撤回削弱队伍；后续补位必须经历击败合格敌人和概率邀请，不能预设成功。普通出口不自动存货，交换机是显式安全转移，仍不额外结算救援。任务、局时与恢复负担见[勘探节奏](玩法研究/基础勘探任务与单局节奏.md)；较低费用与 X=1 的优先比较见[费用推演](玩法研究/救援费用与等待次数推演.md)。所有分钟数、费用、次数和具体地图仍是候选，尚未定稿。已选方向、用户提案和代理建议在[当前决策](项目目标与当前决策.md)分别标明，尚未开始游戏实现。

[首版人数](玩法研究/队伍人数与满员招募.md)已按用户裁决收束为三人队，局内同样不扩员；初始二人恢复路线保留。用户已明确可当场替换，下场成员回营地待机；具体行动、携物与回营整备细则仍待设计。[伙伴与迷宫分工](玩法研究/伙伴探索价值与迷宫分工.md)保留招式、道具强化和培养等奖励方向，按实际用途分批加入。用户已明确 Z 晶与 Mega 延后作为扩展更新，不进入首批大量研究。[无尽规则](玩法研究/无尽迷宫分区与守关规则.md)按区域与 Boss 连续探索，十层只是例子；Boss 阻挡继续，战前有正常出口，换区不自动恢复、不补人、不额外计救援。

[入队与基地培养](玩法研究/新伙伴入队状态与基地培养.md)优先比较共享本局战斗等级、个人永久招式库：新人取得可用基础组合，老伙伴保留预先培养的配招；永久等级路线仍作对照。部分生命与 PP 入队、基地使用招式机和免费重配已学招式都是候选。[无尽恢复](玩法研究/无尽迷宫恢复与局内成长.md)优先比较有限恢复品与一次性小额休整，升级不当治疗。按[分阶段范围](项目框架/分阶段范围与扩展顺序.md)先让一次普通冒险影响下次选择，再用两个连续区域检查无尽。

PokéBonk 的公开客户端将资料筛选、招式候选、共享攻击原型、参数覆盖和特殊行为分开处理。融合另有资格筛选、配方优先级、分字段强化继承与槽位替换；新融合实例会重新从等级 1 开始，不能简单宣称所有成长等价保留。相关研究已经连接到制作流程。

两个项目都署名使用 SpriteCollab 的部分角色图像资源。Pokémon Arena 2D 的预告还把水域和场地变化作为专题展示，说明角色动作之外的场地、特效和演出同样值得研究；公开资料不足以确认其内部实现。

版本号数量和预告播放量各有明确边界：前者不能直接换算为开发效率，后者不能直接换算为实际玩家或留存。
