# 素材管线（阶段6.1）

这条管线回答一个问题：怎样以个人成本，把角色、地砖、交互点等真实素材接进游戏，同时说得清每个文件从哪里来。计划依据见[阶段6计划](../项目框架/阶段6—完整首版最小循环计划.md)，格式背景见[角色素材与招式特效流程](角色素材与招式特效流程.md)。

所有素材只用于私有构建。每个进入工程的文件，都在 `public/assets/manifest.json` 里记录来源、许可、摘要，以及生成或下载它的参数。

## 两条来源，各管一类

| 素材 | 来源 | 为什么这样分 |
| --- | --- | --- |
| 宝可梦角色（多方向、多动作） | SpriteCollab，固定在提交 `448d3af85e2cfa85a8c5ead076eddb145251b473` | 用户偏好的 Arena 2D 风格就来自这里；整套方向和动作，图像模型很难画得一致 |
| 地砖、墙、交互点（之后还有特效与界面） | `gpt-image-2.5` 原创生成，再像素化 | 原创内容不涉及官方角色设计；单张静态图正是图像模型擅长的 |

许可要点（2026-10-30 核对）：

- SpriteCollab 的社区投稿采用 CC BY-NC 4.0，即只能非商业使用，并且必须署名。
- 现有 15 种角色（阶段6 的 9 种，加阶段7.1 的 6 种御三家），`credits.txt` 里的作者大多是 `CHUNSOFT`，也就是官方游戏原图。这类图没有经过授权，CC 许可也覆盖不到它们。
- 宝可梦知识产权不在任何许可之内。

署名随构建发布，写在 `public/THIRD-PARTY-NOTICES.txt` 中。

## 角色：下载与索引

```bash
python tools/art/fetch_spritecollab.py <commit> 0001,0004,... --anims Walk,Idle,Attack,Hurt,Shoot
python tools/art/build_character_index.py
```

- 下载器只取列出的动作，外加 `AnimData.xml` 与 `credits.txt`。某个动作如果是"复制自"另一个动作，下载器会顺着引用去取被复制的那张图。
- 索引脚本读取 `AnimData.xml`，生成 `src/render/characters.json`，内容包括每个动作的帧宽、帧高与逐帧时长。时长以 1/60 秒为单位。
- 动作图每一行对应一个朝向，顺序是：下、右下、右、右上、上、左上、左、左下。这个顺序已对照 0004 号的待机图核实。
- 目前的选择：
  - 15 种：0001、0004、0007、0016、0019、0021、0025、0041、0074，以及 7.1 加入的 0152、0155、0158、0252、0255、0258（第二、第三世代御三家，同一固定提交，同样取 Walk、Idle、Attack、Hurt 与 Shoot（Shoot 若是复制自其他动作，则取被复制的那张，例如 0252 为 Charge；渲染器目前不用 Shoot））；
  - 只用待机动画；
  - 同伴面向最近的敌人，敌人面向最近的同伴。

  单位编号与物种的对应只在本试验内使用，由 `src/render/sprites.ts` 中的 `SKINS` 决定；6.2 会改为由名单数据决定。

## 场景：生成、像素化、记录

```bash
python tools/art/gen_image.py tools/art/cards/<card>.json --batch <批次名>
python tools/art/pixelize.py <原图> tiles/<名字>.png --size 24 --card tools/art/cards/<card>.json [--trim]
```

1. **素材卡**（`tools/art/cards/*.json`）写明用途、模型、质量档、尺寸、是否透明背景，以及完整提示词。提示词统一要求"粗颗粒像素画、深色描边、低饱和土色、左上光源"，并明确排除文字和生物。
2. **生成**的原图放在被忽略的 `.artifacts/art-gen/<card>/` 中，不直接进入工程。
3. **像素化**：把原图整张盒式缩小到 24×24 像素，再用中值切分量化成 16 色。带透明背景的物件先按不透明区域裁成正方形（`--trim`）。对比过裁切局部、32 像素等方案：整张缩到 24 像素的地砖平铺后看不出接缝，最清楚。
4. **记录**：成品写入清单，记下模型、卡片、提示词、原图摘要与全部后处理参数。

画面中，一格的显示尺寸按"24 像素×缩放"计算，Phaser 开启 `pixelArt`，所以放大后仍保持像素颗粒。地面四周八个方向上不是地面的格子都画成墙砖；未揭示的格子降低透明度，显示得更暗。

## API key 与费用

- key 只从主 checkout 被 Git 忽略的 `.env` 读取。本机系统环境变量里另有一个与本项目无关的 `OPENAI_API_KEY`，脚本会刻意忽略它。key 不复制、不打印、不提交。
- 用户说明该 API 总额度为 50 美元。`gen_image.py` 在每次调用前先估算费用，超过任一上限就拒绝调用。上限是：全项目 50 美元、阶段6 15 美元、单批 2 美元。账本是 `tools/art/usage-ledger.json`。脚本在发请求**之前**，先按估算费用写入一条“待定”记录；成功后改成 API 返回的实际用量。如果遇到超时、网络错误或中途崩溃，保留估算值，因为服务端可能已经扣费；只有 API 明确拒绝（HTTP 错误）时才记为 0。`--batch` 是必填参数，`--stage` 默认是 `stage6`；估算会按图片面积放大。拒绝逻辑已经用一份接近上限的临时账本离线验证：三种上限都在调用前生效，账本不被改动。脚本没有文件锁，所以同一时间只运行一个生成进程。
- 账本按官方模型页的单价估算：图像输出每百万 token 30 美元，图像输入 8 美元，文本输入 5 美元。若与 OpenAI 用量页不一致，以用量页为准并修正账本。
- 素材文件以原字节保存：根目录的 `.gitattributes` 对 `public/assets/**` 关闭换行转换，否则 Windows 检出时会改变文本文件，清单中的摘要就对不上了。
- 6.1 的实际花费：1 次端到端测试，加 5 张 `gpt-image-2.5-flare` 低质量档草稿，每张约 0.0064 美元，合计约 0.038 美元。
- 6.4 素材批次（`6.4-fx-draft`，2026-10-30）：5 种招式特效（强击冲击、直线光弹、保护护罩、推退气流、回复闪光）、上下楼梯地砖、两种恢复品图标（蓝色树果、紫色补剂瓶），共 9 张 flare 低质量档，约 0.058 美元；项目累计约 0.096 美元。这批素材由 6.4 的表现部分接入画面。

## 动画与特效接入（6.4）

目标：让玩家看清一轮里"谁动了、谁打了谁、谁受伤、谁用了什么"。动画只是表现：规则结果在命令完成时就已确定并保存，动画不改规则、不改存档。

**怎么知道发生了什么。** 规则只返回整轮结束后的世界状态，不发事件。画面层（`src/render/animation.ts` 的 `inferEvents`）拿命令前后两份状态和日志新增的行，按日志顺序还原步骤：

- 日志里写明主语的步骤直接解析：移动（`X移动到x,y`）、敌人趋近、推退、换位、受伤数值和倒下、使用橙橙果／PP补剂。
- 日志不写"谁打的"，所以攻击者靠推断：伤害落在敌人身上时，按队列顺序找尚未行动的同行者，且其显式动作（主控动作或被安排的伙伴动作）以该敌人为目标，或没有显式动作但与目标相邻（规则里默认动作就是打相邻敌人）。伤害落在同行者身上时，按敌人顺序找下一个距离合适的敌人（近战相邻，远程同排／列且在射程内）。
- 保护不写日志：以"显式保护动作且没有'动作失效'日志"判定已生效，并按队列位置插在后面行动者的第一步之前。
- 推断可能指错攻击者（例如一个同行者对同一目标有多种合理解释），但只会让挥动的角色或特效起点不对，不会改变结果；动画结束时一定整体重画真实状态。

**可见性。** 画面只用最终状态里已揭示的格子判断：目标是敌人而它所在格未揭示、敌人移动的起点或终点未揭示，这一步不播放；看不见的敌人发起的攻击只播放被击中者的受伤，不画攻击者和特效。

**时长与跳过。** 单步基准时长：移动180 ms、换位200、攻击／受伤320、保护240、推退220、回复260；整轮总长超过1.5 s 时所有步骤等比例加速，需加速到0.3倍以下则整轮不播放。动画有3 s 兜底超时。按住或按下 Shift 可跳过正在播放的动画，启动时已按住 Shift 则不播放。

**开关。** 优先级从高到低：查询参数 `?anim=off|on`；页面脚本变量 `window.__trialNoAnim`（浏览器检查用，默认的22组检查都开启它）；图例旁"动作动画"复选框（保存在 `localStorage` 的 `trial-anim-pref`，不在存档命名空间内）；系统"减少动态效果"设置。`window.trial.animating()` 与 `window.trial.animationEnabled()` 供检查读取。

**输入锁。** 动画播放时，所有按钮点击在捕获阶段被丢弃，方向键、句点、数字键、Esc 等键盘输入和画布点击也被丢弃——丢弃而不是排队，动画结束后需要重新输入。结束时保存协调器与原有规则不变：保存中仍只能查看与编辑草稿。页面刷新或读档不重播，直接显示最终状态。

**用到的素材。** 招式特效 `public/assets/effects/fx-*.png`（强击、直线、保护、推退、回复），楼梯 `public/assets/tiles/stairs-down.png`／`stairs-up.png` 替换原先出口图标加着色，橙橙果与PP补剂拾取点用 `public/assets/props/item-berry.png`／`item-tonic.png`；角色动作用已有的 Walk、Attack、Hurt 表。

**已知局限。**

- 右侧面板与顶部文字在动画开始时就显示最终数值，只有画布分步演出。
- 镜头不随移动补间，动画结束时才跳到新位置。
- 单位脚下的影子和主控光圈原先画在地砖之下，实际看不见；本次提到第 3 层：在地砖与交互点之上，在角色、高亮和文字之下，并跟随单位移动（主控会话复核时修正）。
- 动画时序和观感只做了自动截图与脚本检查，没有玩家反馈；Windows 原生运行未验证，浏览器检查在本机 Edge 上完成。
