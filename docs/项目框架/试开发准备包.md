# 单层试开发准备包

状态：准备包32931fe已通过[独立审核](https://github.com/392fyc/pokemon-game-research/pull/4#issuecomment-6476246314)，可作为一次开工确认的依据；本次补充见[审核记录](../审核请求/2026-10-29-试开发准备包.md)。阶段3尚未开始，研究审核不等于批准安装、同步准备仓或实现游戏。阶段依赖见[路线图](从研究到试开发的阶段路线图.md)。PR #3已合入06cf1c0，本包PR #4现以main为目标。

## 本片段要回答什么

| 问题 | 提供的比较 | 哪种证据才能回答 |
| --- | --- | --- |
| 伙伴是否改变玩家做法 | 留C远攻、让B承伤、换N保留C实例；低生命D用推退省保护 | 程序按规格运行后，观察玩家实际选择和理由；纸面路线只证明这些做法存在 |
| 操作能否表达意图而不过重 | 普通一步直接执行、一次伙伴干预、切近出口者返向、非法输入解释 | 记录真实误触、取消、切主控、求助和提示；没有独立体验者时玩家结论仍为未验证 |
| 新情报是否使继续／返回有意义 | G可先结束，探看后首见R，再选择返程或取T | 首次体验中何时改变计划、为什么改变；重复验收路线不能证明新玩家感受 |

片段以一张固定单层图和少量独立检查初态为预算。几何占位、人工数据足够验证上述问题；不以完成完整经济、素材库或随机迷宫为开工前提。检查初态不作为玩家可选关卡，也不增加首版内容承诺。

## 一次确认的临时基准

以下推荐合在一次开工确认中采用，允许试验复盘后修改。三人上限已经确定，不重新征求；其余均不改写为正式游戏定稿。

| 项目 | 本包推荐 | 本次不据此回答 |
| --- | --- | --- |
| 队伍与行动 | 三人同行；现行固定队列、一名主控加至多一次伙伴干预，按R01—R06 | 最终操作手感或更多人数 |
| 地图与返回 | G4／T7／R9主图，可返回已知出口，资源和敌人不刷新；仅同层 | 跨层入口、随机地图和长局节奏 |
| 招募定位 | 允许邀请直接成为奖励；接纳、拒绝和换谁都保留；固定有／无邀请分别检查 | 自然邀请率、长期收集和名册经济 |
| 新人资源 | 沿R07半额快照；每个招式分别计算；本轮不启用60%对照 | 最终资源平衡 |
| 技能与交互 | 采用[短规格](../玩法研究/单层试开发短规格.md)的目标、伤害、保护、推退及取得时机 | 完整招式系统、属性、命中和成长 |
| 正常撤离 | 同行名单含倒下者归营；此前回营者单列；展示实际HP/PP、目标和带出物，不治疗 | 免费基本整备和跨局恢复政策 |
| 全灭 | 保存仍同行的倒下者及已回营者；背包记“已取得、未带出”，不进入跨局库存；目标保留实际完成标记 | 正式走失概率、永久损失、救援费或有效探险计数 |
| 重开 | 终局保存后手动开始独立试验，新身份、新初态，不继承上局内容；保留最近一次结束记录 | 游戏内复活、免费整备、长期培养价值 |
| 操作和观察 | 采用短规格键鼠候选；正常输入不加通用确认；执行[验收与观察场景](../玩法研究/试开发验收与观察场景.md) | 满意率、分钟数和玩家样本结论 |
| 开发与打包工具 | 在已选Phaser 4.2.1＋TypeScript之外，推荐Vite用于本片段开发与打包，随开工包一次确认；安装前核对官方包元数据、发行说明及Node兼容要求，锁定精确版本 | 本轮未选择Vite版本、安装依赖或验证构建；不提前决定正式发布配置 |
| 暂不接入 | 商店、交换机、救援经济、教学成长、跨层、无尽、Z晶、Mega、账号、云存档和Electron | 不表示从完整游戏取消这些功能 |

正常结束与全灭都先成为不可重复结算的本次结果。重开不是同一局被治好后继续；界面使用“开始独立试验”，不使用“复活”或“免费整备”。本包没有决定正式游戏的失败经济。

## 阶段3—4的建议授权范围

开工确认针对整个包及下列范围一次进行，获准后按既定顺序连续推进：

1. 在`pokemon-dungeon-lab`核对真实工作区，按清单同步固定研究来源并更新非受管说明；保留用户改动，确认受控交付方式。
2. 使用已选Phaser 4＋TypeScript，并将推荐Vite纳入本次开工确认；核对官方依赖、既定4.2.1版本基线和打包工具兼容要求，锁定实际版本，再安装最小依赖及建立工程。调整技术基线须说明原因，不能静默升级。
3. 建立可操作画面、完整一轮和最小保存恢复，再接通一张主图、招募、退出、全灭及独立重开；运行必要检查并形成私有可玩产物。
4. 规则正确后再观察体验，报告哪些已实际验证、哪些尚未验证；不以截图或纸面计算代替真实可操作片段。

授权范围不包含扩大网络权限、修改Mercury受管文件、公开部署、引入第三方角色／Showdown数据／mod代码或合并其他PR。出现确切权限或来源阻塞时给出最小依赖，不自行绕过。

现有游戏云HEAD与远端不同；云Shell对GitHub访问和受控推送入口尚未落实。这些不妨碍本包研究交付，必须在工程改动前按[开工清单](../制作流程/试开发工程与同步清单.md)解决。现有两个云聊天继续分工，主会话负责规格、整合和交付；不额外创建并行研究项目。
