# 营地存档模型规格

**状态：工作候选规格。用户决定见第 1 节；第 3 节以后是 main 的落实方式，待独立审查。** 本页取代 [玩家操作与中断恢复](玩家操作与中断恢复.md) 第 5–7 节中“迷宫内保存与恢复”的部分，那几节的其余内容（操作约定、邀请、撤离表达）不变。

## 1. 用户决定（2026-10-30，对话中）

在确认敌人行为时，用户答复原话：

> 做原版贴近，但不用考虑存档问题：我们只有在回到营地后才会存档，结算收获。如果在迷宫图中退出，会自动读档到进入迷宫前在营地的状态。

main 随后问：“在迷宫里快要全灭时关掉页面，就能回到出发前——不丢伙伴、不付救援费。这样可以吗？”用户选了选项“可以，中途退出不罚 (推荐先这样)”（选项标签，不是原话）。

main 的理解：

- 一次远征（从出发到回到营地）在存档里是**不可分割的整体**：要么在回到营地时整体结算并保存，要么什么都不留下。
- 远征中途因任何原因离开（关页面、刷新、浏览器崩溃），重新打开时回到出发前的营地状态，本次远征作废，**没有惩罚**。用户知道这允许“快全灭时退出”来避免损失，并接受。

## 2. 为什么这样更简单（从目标推导）

- 现有存档每完成一个处理点就保存整个迷宫世界（`Envelope.current`），为此要校验每一种中间阶段（`playing`、`invitation`、`exit`、`transit`、`ended`）、处理保存失败时的冻结与重试，并保证读档后与关闭前逐项一致。
- 新规则下，迷宫世界只存在内存里。存档只需要描述营地，迷宫内的新状态（7.8 的敌人睡眠、漫游目标、追击记忆，队友方针的临时修改）都不用进存档、不用校验，也不会因读档产生不一致。

## 3. 规则（main 的落实方式）

1. **存档内容：** 只存营地档案（`profile`）与格式元数据。迷宫世界（`World`）不写入持久存储。
2. **写入时机：**
   - 营地里的操作（学招式、编队、商店、付费救援等）照现有方式保存；
   - 远征**回到营地**时：把本次远征的结果（带出的物品与金钱、招募的伙伴、走失的伙伴、学到的招式机等）一次性结算进营地档案，然后保存一次；
   - **出发时不写入**。所以存储里留着的始终是出发前的营地状态。
3. **中途离开：**
   - 远征进行中、或已出结果页但还没回到营地时离开，重新打开后读到的是出发前的营地档案。
   - 因为出发时不写存档，重开时程序无从得知“上次有过远征”，所以不在重开时提示；改为在出发确认处说明一次：“远征途中离开（关闭、刷新）会回到出发前的状态，本次远征作废。”
4. **结果页：** 远征结束（撤离或全灭）后先显示结果页；只有按“回到营地”才结算并保存。结果页上关闭页面也算中途离开（第 3 条），这是按用户原话“回到营地后才会存档”的字面执行。
5. **保存失败：** 只剩营地里的保存会失败。沿用现有的“保存失败 → 画面保留、可重试、禁止后续改变状态的操作”，但范围缩小到营地。回到营地的那次结算保存失败时，停在结果页并可重试，不重复结算。
6. **导出／导入：** 只导出、导入营地档案。
7. **开发者场景：** 开发者菜单和测试用的固定场景（`scenarios.ts`、`?dev=1`）改为直接在内存里构造世界，不再经过存档读取。

## 4. 旧存档

- 读到带进行中远征（`current` 不为空、阶段不是营地）的旧存档时：丢弃这次远征，保留营地档案，等同于“中途离开”。
- 读到已结束但未回营地的旧远征（`current.phase==='ended'`）时：同样丢弃，不补结算。理由同第 3 条第 4 项。私人试玩阶段接受这点损失。
- 存档格式因此改变，需要升级版本号。按[多lane并行协作](../工作环境/多lane并行协作.md)，版本号变更须用户在 Codex 中确认。

## 5. 受影响的现有内容（实现时逐项改写或删除）

| 现有内容 | 处理 |
| --- | --- |
| `save.ts` 的 `Envelope.current`／`recent` 与 `validWorld` 等迷宫世界校验、`migrateWorld` | 删除或只用于旧档丢弃；营地档案校验保留 |
| 浏览器检查 M2、S1（关闭页面后同源恢复原局） | 改为“关闭后回到出发前的营地” |
| S4、S6、S7、S8 中迷宫内保存失败、待退出写失败重试等 | 删除迷宫内部分，保留营地保存失败的对应检查 |
| 远征、6.4、7.2 等检查中“重载一致” | 改为只在营地状态上检查重载一致 |
| 连续五局检查的“每局终局与回基地各一次导出／导入往返” | 只保留回到营地后的往返 |
| [玩家操作与中断恢复](玩家操作与中断恢复.md) 第 5 节“保存并关闭”与第 6、7 节迷宫内中断表 | 标为被本页取代 |
| 7.8 规格第 6 节与第 11.5 节（敌人状态、方针写进单位存档） | 迷宫内的单位不再存档；方针只存在伙伴实例上，迷宫内改动在回到营地时写回 |

## 6. 顺序

建议先实施本规格，再实施 7.8：7.8 的敌人睡眠、漫游与追击记忆都是迷宫内状态，存档模型先简化，7.8 就不需要为它们设计存档字段与校验。

## 7. 验收

- 远征中、结果页上关闭或刷新页面，重开后营地档案与出发前逐字节相同。
- 回到营地后，档案包含本次结算结果；重开后一致。
- 营地保存失败时可重试、不重复结算；回营结算保存失败停在结果页。
- 旧存档中的进行中或已结束远征被丢弃，营地档案保留。
- 导出、导入只含营地档案。
