# 图鉴批量导入规格（第 1 代 151 种起）

状态：现行。批量导入以本页为维护约定，招式执行规则见[游戏规则](../01-现行规则/游戏规则.md)；属性、睡眠、四招和升级学招按 D-20261104-03。

## 0. 用户决定（原话）与本规格的理解

| 用户原话或选择 | main 的理解（执行解释） |
|---|---|
| “23有点太少了，可以扩展一下。而且敌我同一个图鉴应该更好做” | 敌人与伙伴共用一个图鉴，这一点已写入 7.8 规格第 10 节。本规格扩充的就是这个图鉴。 |
| “按世代补全最好，并且需要考虑到不同世代可能有技能差异。最好是，以未来扩展为基准，选定某个世代，无论做哪个世代出现的宝可梦，都以该世代进行技能配置。一般来说，做新不做旧” | 招式以第 9 代为基准世代。某物种在第 9 代没有收录时，退到收录它的最新世代，并在数据里写明（第 2.2 节）。 |
| 选择题“先补哪代”，用户选了“第 1 代 151 种”（这是选项文字，不是原话） | 第一批是图鉴编号 1–151 的全部基础形态。现有名单里第 2–3 代的 9 种保留。 |
| “请按照之前的批量化模式，先形成导入模式再做，别一个一个对照” | 先定规则和脚本，规则一次作用于全部物种和招式。人工只处理脚本列出的例外清单，不逐个比对。 |

## 1. 为什么必须批量

第 1 代 151 种按第 2.2 节取学习表后，可学招式合在一起去重，有几百个，没法逐个人工比对。由脚本统一判定，原有 25 招对象仍逐字节保留。当前 175 物种的招式数量与准入、排除结果见[数据快照登记](数据快照登记.md)。

所以工作分成三步：

1. **抓取**：联网，一次性完成。
2. **导入**：离线运行，结果确定，可以重复。
3. **例外清单**：人工按类别决定，不按单个招式决定。

## 2. 规则

### 2.1 物种范围

- 取 Showdown `pokedex.json` 中 `1 ≤ num ≤ 151`、且没有 `forme` 字段的条目。实测正好 151 个。
- 现有名单的 23 种里，14 种属于第 1 代，已经在范围内。另外 9 种是第 2–3 代，全部保留：
  - 第 2 代：菊草叶、火球鼠、小锯鳄、乌波、戴鲁比；
  - 第 3 代：木守宫、火稚鸡、水跃鱼、幕下力士。
- 首领物种风速狗属于第 1 代。合计 151＋9＝160 种。
- **2026-10-30 补充（7.8 规格第 13.3 节，main 的工作候选）：** 上述 9 个第 2–3 代物种的完整进化链也纳入图鉴，共 15 种：月桂叶、大竺葵；火岩鼠、火暴兽；蓝鳄、大力鳄；森林蜥蜴、蜥蜴王；力壮鸡、火焰鸡；沼跃鱼、巨沼怪；沼王；黑鲁加；铁掌力士。合计 175 种。
  - 理由：按局内进化规则，下一形态不在图鉴里的物种不会进化；不补的话，只有初代御三家能进化，第 2–3 代御三家不能。
  - 规则表述（供脚本实现）：对第 2.1 节第二条保留的每个物种，沿 Showdown `evos` 逐级加入后续形态，直到没有后续形态；带 `forme` 字段的地区形态不加入（与本节第一条一致，例如洗翠火暴兽 `typhlosionhisui` 不加入）。
  - 新增物种按第 2.2–2.6 节同一管线导入，不冻结任何字段，排在名单末尾；顺序以上面列出的 15 种为准（城都御三家三条链、丰缘御三家三条链，再沼王、黑鲁加、铁掌力士；每条链按进化深度），由测试锁定。
  - 7.8 起，导入时为全部物种追加 `evoLevel`、`prevo`、`evos`、`legendary` 四个字段，定义见 [敌我对等招式与强化模型规格](https://github.com/392fyc/pokemon-dungeon-lab/blob/d03ef5144f5671b3b8d5418b94353223742e911a/docs/04-%E8%A7%84%E6%A0%BC/%E6%95%8C%E6%88%91%E5%AF%B9%E7%AD%89%E6%8B%9B%E5%BC%8F%E4%B8%8E%E5%BC%BA%E5%8C%96%E6%A8%A1%E5%9E%8B%E8%A7%84%E6%A0%BC.md) 第 7 节第 3 步。
- 现有 23 种冻结以下字段：`kit`、`maxHp`、`starter`，以及它们在名单中的先后顺序。它们的 `learnable` 按第 2.5 节处理。

### 2.2 学习表世代（“做新不做旧”）

- 基准世代是第 9 代。Showdown 的学习方式代码举例：
  - `9L1`：第 9 代，升级学会，1 级；
  - `8M`：第 8 代，招式学习器；
  - `8V`：经 HOME 从别的作品传入第 8 代。
- **世代选择**：取该物种至少有一条升级条目（`<世代>L<等级>`）的最新世代，最高第 9 代。只有这样才能保证“这一代确实收录了该物种”。
  - 反例：波波在剑盾、朱紫都没有收录，但有 `8V` 传入条目。如果按“有任意条目”来选，会误选第 8 代，结果一个升级招式都没有。按本规则会选第 7 代。
- 在选定的世代里，取代码以该世代数字开头、且第二位不是 `V` 的全部条目。
- 输出字段 `learnsetGen`，即实际使用的世代。
- 学习表只决定“能学什么”。招式数值来自官方迷宫数据（第 2.3 节），PP 见第 2.5 节。

### 2.3 官方迷宫数据与取值对照

**来源**：Bulbapedia 的 MediaWiki API 返回招式页源码（wikitext），从中读取这样的行：

```
{{MDMoveRow|game=…|pow=…|pp=…|acc=…|range=…|target=…|cuts=…}}
```

模板里缺省的字段按 `-` 处理。有的值包在提示模板里，例如 `range={{tt|Front|Indicated as Others in-game}}`：取第一个参数（源站正文显示的值，这里是 `Front`），提示文字不用。抓取脚本是 `tools/data/fetch_pmd_wiki.py`，它核对每页原文中模板起始的次数与解析出的行数，不相等就停下，避免静默丢行。

**作品优先级**：沿用 [官方招式模型规格](https://github.com/392fyc/pokemon-dungeon-lab/blob/d03ef5144f5671b3b8d5418b94353223742e911a/docs/04-%E8%A7%84%E6%A0%BC/%E5%AE%98%E6%96%B9%E6%8B%9B%E5%BC%8F%E6%A8%A1%E5%9E%8B%E8%A7%84%E6%A0%BC.md) 的“探险队优先”，细化为 `TDS → S → TD → GTI → SMD → RTDX`。

- 探险队内部：源站在时／暗与空数值相同时写一行 `TDS`，不同时分成 `TD`（时／暗）和 `S`（空）两行。本规格取 `S`，因为空之探险队是探险队的最终版，符合“做新不做旧”。例如冲浪：`TD` 威力 18、`S` 威力 30，取 30。
- `RTDX`（救助队 DX）放在最后一级，只在前面都没有时使用（第 6 节默认值第 6 条）。
- 源站另有 `RB`（红／蓝救助队）、`BSL` 两种代码，本规格不采用。

**作品代码对照**：

| wikitext 中的 `game=` | 含义 | 写进 `pmd-moves.json` 的 `game` |
|---|---|---|
| `TDS` | 时、暗、空之探险队，三作共用一行 | `MDTDS` |
| `S` | 空之探险队（与时／暗数值不同时） | `MDSky` |
| `TD` | 时／暗之探险队（与空数值不同时） | `MDTD` |
| `GTI` | 无限之迷宫 | `MDGtI` |
| `SMD` | 超不可思议的迷宫 | `SMD` |
| `RTDX` | 救助队 DX | `RTDX` |

现有 25 招的 `game` 保持原值不变（22 个 `MDTDS`、1 个 `MDGtI`、2 个无官方作品）。

**射程对照**：比较前先去掉首尾空白，再不分大小写比较。`Enitre room` 是源站的笔误，按 `Entire room` 处理。

| 官方原文 | 本作 |
|---|---|
| `Front` | `front` |
| `2 tiles away` | `front2` |
| `10 tiles away` | `line10` |
| `1 tile around user` | `around` |
| `Entire room` | `room` |
| `User` | `user` |

**目标对照**：

| 官方原文 | 本作 |
|---|---|
| `Enemy` | `enemy` |
| `User` | `user` |
| `Teammates`、`Teammate(s)` | `teammates` |
| `Party` | `party` |
| `All` | `all` |

**暂不支持的取值**：下面这些值在 2026-10-30 的快照中实际出现过，但本作还不支持。遇到时，该招式进例外清单，原因写“射程暂不支持”或“目标暂不支持”。

- 射程：`Entire floor`、`Tile below user`、`Others`、`Varies`、`2 tiles around user`、`4 tiles away`、`Random adjacent tile`，以及诅咒那种按属性分支的写法。
- 目标：`All except user`、`Teammate`（单个队友）、`Others`、`Wall`、`Floor`、`Varies`，以及按属性分支的写法。

**未知取值**：不在上面任何一张表里的值，导入脚本直接报错停下。这说明快照变了，要先更新本节。

**一致性抽检**：

- 对象：现有 25 招中有官方作品的那些。
- 做法：按各招已选定的作品，取新快照里的对应行，逐字段比较 PP、命中、斜角。作品对应关系是 `MDTDS` 对应 `TDS`，`MDGtI` 对应 `GTI`。
- 不比较的：叶影与太晶爆发是本作自定的招式，没有官方作品。

### 2.4 招式准入

导入器的 `classify_moves` 依次处理原有 25 招、已定稿的扩展模板和通用排除条件。原有对象逐字节保留；太晶爆发只保留数据行供旧档迁移，不进入任何物种可学清单或招式机池。新模板按类别实现，逐招来源与本作取舍写进生成数据。

- 作品、射程、目标依第 2.3 节。未知取值直接停止；已知但不支持的取值进入排除清单。睡眠专用八招在通用排除前按已批准模板处理，梦话的可变射程／目标由被调用招式决定。
- 排除非标准招式、无官方迷宫资料，以及未实现的自身代价／条件、一击必杀、固定伤害、多段、换人、回调威力、零基础威力、蓄力机制。反作用已有独立模板，不再属于排除项。
- 需要伤害的模板要求所选官方 `pow` 为整数；缺失或范围值不改用其他作品或主系列威力补造，原始行进入“官方威力不可用”清单。
- 通用攻击模板保留伤害、吸取和吹飞；附加状态、阶段、自身代价由 `import_move_effects.py` 的固定 Showdown 字段及逐招来源规则生成，按游戏规则 [G5](../01-现行规则/规则-战斗与敌人.md#g5-战斗) 执行。
- 纯变化模板支持六项现行能力阶段、纯异常、团队保护、回复。只改速度的招式不准入；含速度的多项强化忽略速度。破壳、充电、生长、虚张声势、吹捧、摇晃舞等需要其他规则的变化招式仍不准入。
- 睡眠模板包括催眠术、催眠粉、唱歌、蘑菇孢子、恶魔之吻；睡觉对应打盹，打鼾与梦话是受击后的被动反应。粉末标记用于草系免疫。所有行为按 G5.13，主系列说明不作为运行规则。

准入与排除的招数合计要等于可学招式总数，由测试检查；各类别的招数由导入器输出的 `.artifacts/pokedex/summary.json` 与 `exceptions.md` 保存，总数见[数据快照登记](数据快照登记.md)。

### 2.5 PP、初始招式与可学招式

**PP**：

- 每招的最大 PP 取探险队官方 `official.basePp`（8.8，#165），同一招式在所有物种里相同。叶影没有探险队数据，取 Showdown 的基础 PP 40。生成位置：`import_pokedex.py` 的 `pp_for`、`import_showdown.py` 的 `pp_from_specs`。
- 每个招式全局只有一个 PP 值；测试 R5 要求它等于官方 `basePp`（叶影 40）。

**`learnable`（可学招式）**：

- 规则：该物种在 `learnsetGen` 世代里，通过除 `V` 之外任何学习方式能学会、并通过第 2.4 节准入的全部招式。
- 现有 23 种：取“旧 `learnable`”与“按本规则算出的集合”的并集，按招式 id 合并，PP 用全局值。这样旧的 `7V` 来源也会保留，例如波波、小拉达、烈雀的掷泥。

**`kit`（营地新伙伴的初始招式）**：

175 物种的初始招式与 PP 冻结于 `tools/data/starting-kits-191.json`。下列选择过程只使用扩展前准入范围，新增模板不改变 `kit`：

1. 只看 `learnsetGen` 世代的升级招式（代码为 `<gen>L<level>`）。
2. 按等级从低到高排，同级按招式 id 的字母序。
3. 取前 2 个准入招式。
4. 如果这 2 个都不造成伤害，第 2 个换成等级最低的伤害招式。

**暂不出场的物种**：

- 按上面 4 步凑不出“2 个准入招式、且至少 1 个造成伤害”的物种，只进图鉴，标为“暂不出场”，不进出场池，并列入例外清单。它的 `kit` 照样按第 1–3 步记下能取到的招式（可能少于 2 个或为空），供以后加模板后复用。
- 目前这样的物种有 5 种，名单见 D-20261030-61（[决策登记](../03-决策/决策登记.md)）。这与官方学习表一致，不是数据错误。

**`levelUp`（局内升级学习表）**：取所选 `learnsetGen` 的 L 条目，仅保留当前准入招式，排除 L1、保留 L0，按等级和招式 id 排序，写入等级、招式和统一 PP。它不受 `kit` 冻结限制。普通／挑战敌人与局内招募的当前等级装配取最新四个不同招式，不足时按 `kit` 顺序补足；固定首领保持专用装配，营地新伙伴仍用 `kit`。（游戏规则 [G6.9](../01-现行规则/规则-成长与招募.md#g6-等级经验与进化)—[G6.10](../01-现行规则/规则-成长与招募.md#g6-等级经验与进化)）

**`maxHp`**：沿用 `12 + floor(baseStats.hp / 5)`。这是工作候选，平衡另定。

### 2.6 中文名

**来源**：PokeAPI 仓库 `data/v2/csv/` 里的三个表：`pokemon_species_names.csv`、`move_names.csv`、`moves.csv`。语言 id 用 `12`，即简体中文 zh-Hans（已由同目录的 `languages.csv` 核实）。

**招式对应**：把 `moves.csv` 的 `identifier` 去掉连字符，与 Showdown 的 id 对应，例如 `water-gun` 对应 `watergun`。

PokeAPI 快照的固定提交见[数据快照登记](数据快照登记.md)。

- 招式的拼写与 Showdown 对不上时，导入按 `tools/data/import_pokedex.py` 的拼写别名表 `SHOWDOWN_MOVE_NAME_ALIASES` 取 PokeAPI 的简体译名（例：Showdown 的 `visegrip` 对应 PokeAPI 的 `vice-grip`，译名“夹住”）。
- 手写招式译名与 PokeAPI 不同的，只有精神利牙／精神之牙仍保留手写译名，列入“译名差异”；其余已改用 PokeAPI 的官方译名（#93），由导入脚本生成。

**与现有译名的关系**：

- 现有 `src/data/names-zh.json` 里的手写译名优先保留。
- 与 PokeAPI 不一致的，列入例外清单“译名差异”，由 main 一次性决定，导入时不自动覆盖。
- PokeAPI 里缺的名字，同样列出。

### 2.7 角色素材

**来源**：沿用 `tools/art/fetch_spritecollab.py`，从 PMDCollab/SpriteCollab 的固定提交按图鉴编号批量下载，并写入素材清单（见 [素材管线](素材管线.md)）。

**可用判定**：读根目录的 `tracker.json` 批量判断，下面三项都满足才算可用，缺项要列出：

- `portrait_complete` 大于 0；
- `sprite_complete` 大于 0；
- `sprite/<dex>/AnimData.xml` 和所需动作的文件实际存在。

`tracker.json` 的固定提交见[数据快照登记](数据快照登记.md)。由字段取值推断，1 表示部分完成，2 表示完成，这一点未经官方文档核实，所以仍须按上面第三项检查所需动作的文件是否实际存在。

**许可**：

- 社区作品为 CC BY-NC 4.0。
- 作者为 `CHUNSOFT` 的文件是官方游戏素材的收录，不在这份授权之内。
- 现有脚本已在许可说明中写明这一点，并限定只用于私有构建，本规格沿用。

## 3. 管线

```
抓取（联网，由 main 执行，快照放在主 checkout 中被 Git 忽略的 .artifacts/）
  tools/data/fetch_pmd_wiki.py   Bulbapedia API → .artifacts/pmd/wiki-<日期>.json ＋ .sha256
  PokeAPI CSV、SpriteCollab tracker.json → .artifacts/pokeapi/、.artifacts/spritecollab/（按日期存，附 sha256）
导入（离线运行，只用标准库，可重复，由 dev 实现）
  tools/data/import_pokedex.py   快照 → src/data/roster.json、pmd-moves.json、names-zh.json
                                 ＋ src/data/move-types.json、type-chart.json、.artifacts/pokedex/summary.json、exceptions.md
```

**抓取的约束**：

- 设置明确的 User-Agent；
- 每批不超过 10 页，每次请求间隔至少 1 秒；
- 带 `maxlag=5`。

**招式清单的生成**：对第 2.1 节的物种按第 2.2 节取学习表（含所有学习方式、不含 `V`），合并去重；抓取快照内的 `requestedIds` 字段保存了请求的招式清单，可据此复现，快照的哈希见[数据快照登记](数据快照登记.md)。

**导入的约束**：

- 先校验快照的 sha256，不一致就退出；
- 用同一份快照重复运行，输出逐字节相同。

## 4. 不在本规格内

- 新物种出现在哪些迷宫、哪些楼层、什么等级：随 7.8（敌我对等）规格的等级表和主题池另定。导入只产出图鉴数据，出场池默认不变。
- 多段、蓄力等未定稿类别的实现；待定范围见[后续招式与道具范围](../02-进度/计划/8.9招式与道具对齐原版规格.md)。
- 第 2 代及以后的物种：用同一管线，扩大第 2.1 节的范围即可。

## 5. 验收

1. **可重复，且不改动已有数据**：
   - `import_pokedex.py` 用同一份快照运行两次，输出相同；
   - 现有 25 招逐字节不变；
   - 现有 23 种的冻结字段不变；
   - 旧 `learnable` 的招式 id 集合是新集合的子集。
2. **151 种齐全**：第 1 代 151 种全部在 `roster.json` 中，每种都带 `learnsetGen`。暂不出场的物种在例外清单中写明原因。
3. **招式数对得上**：准入招式数，加上例外清单中按招式计数的互斥原因之和，等于全部可学招式的数量。物种级、译名级的清单类别不参与这个求和。
4. **一致性抽检作为测试运行**：即第 2.3 节的一致性抽检。
5. **全量检查通过**：`npm run check`、`npm test`、`npm run test:acceptance`、`npm run build`、`npm run test:browser`。

存档版本变更按[多lane并行协作](../07-工作环境/多lane并行协作.md)和用户授权执行。当前规则 6／内容 7 及规则 5／内容 5、规则 5／内容 6 的迁移已经由 D-20261104-03 批准。

## 6. main 的默认值（用户可改）

1. **初始招式**（第 2.5 节）：按扩展前准入范围取最低等级的两个升级招式，至少一招造成伤害，之后以 175 物种冻结表核对。局内四招装配与升级学招另按 G6.9—G6.10。
2. **暂不支持的类别**（第 2.4 节）：先不进本作，只列入清单。之后按受影响物种的多少，决定先给哪一类加模板。
3. **排除 `V` 代码**（第 2.2 节）：世代选择和新增物种的可学范围，都不算经 HOME 传入的条目。现有 23 种的旧可学招式照样保留。
4. **自身代价招式不进本作**（第 2.4 节第 5 条）：在有代价模型之前不收录，以免出现没有代价的高威力招式。
5. **探险队内取空之探险队**（第 2.3 节）：`TD` 与 `S` 不同时取 `S`。
6. **救助队 DX 作最后一级来源**（第 2.3 节）：7 个招式以它为数据来源，其中 4 个准入（十万马力、水流裂破、修长之角、地狱突刺）；跺脚、磨砺、狂舞挥打被后续规则拦下。救助队 DX 的威力尺度可能与探险队不同（例如十万马力 `pow=30`），平衡阶段复核；不想引入时可删去这一级，这些招式改记“无官方迷宫数据”。
