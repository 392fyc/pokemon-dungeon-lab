# 失败、回归与稀有服务点（阶段7.2 执行规格）

本页把研究库的现行候选落成阶段7.2 可以直接实现、直接检查的规格。依据有五份：

- [有效探险与基础收入](有效探险与基础收入.md)中的方案 B；
- [救援费用与等待次数推演](救援费用与等待次数推演.md)的纸面起点；
- [救援队等级与失败成本](救援队等级与失败成本.md)；
- [迷宫商店与伙伴交换机](迷宫商店与伙伴交换机.md)；
- [项目目标与当前决策](../项目目标与当前决策.md)中的用户框架提案。

里程碑与通过条件见[阶段7计划](../项目框架/阶段7—可试玩EA计划.md)。

**本页每个数值都是 Claude 主会话的工作候选**，不是最终平衡。标了"（工作候选）"的数值是本页新提出的，研究里没有这个起点。救援队等级与高风险任务档位暂不实现。

## 要成立的体验

全灭会真的损失伙伴和物资。但玩家可以靠完成基础目标挣钱、付费救回伙伴，也可以只带"初始二人"继续冒险。以下几条是用户的框架提案，属于约束，必须保持：

- 初始主控和副手不会走失；
- 付费后等待固定次数，伙伴必定回归，付费救援不会再次失败；
- 等待期间再次全灭，不影响救援池里的伙伴；多只伙伴各自处理；
- 未付费的伙伴到期后永久失去；
- 期限按有效探险计算；
- 交换机出现概率低，用途是保人；被送回的成员本局不再参战；空位只能靠再次击败敌人、触发邀请来补。

## 名词

| 名词 | 意思 |
| --- | --- |
| 账户 | 基地里的钱，跨局保存，只在基地里使用：付救援费，以及往钱袋装钱 |
| 钱袋 | 本局随身带的钱（存档字段名为 `purse`，与已有的 `bag` 区分），只能在局内商店花。正常撤离时余额退回账户；全灭时丢失 |
| 初始二人 | 新游戏时选定的主控和副手，档案中有受保护标记，永不走失。新游戏流程上线前的旧档案，受保护的初始成员是三只御三家 |
| 有效探险 | 见下一节。每局最多算一次 |
| 救援池 | 走失伙伴所在的列表。每只伙伴记录：未付费时的剩余期限 L，或已付费时的剩余等待次数 X |
| 本局成果招式机 | 本局取得的招式机，可能来自成果 T，也可能来自商店购买。局内用列表保存，每张都有自己的去向 |

## 有效探险怎样判定

一局只要满足以下任一条，就算一次有效探险：

1. 完成了基础目标 G；
2. 本局有新增的跨局成果被实际保留，包括：
   - 本局新招募的伙伴，终局时在同行名单里，或曾经回营，或经交换机送回，或在全灭后走失进了救援池（研究第 52 行：入池的伙伴也算保留下来的实例）；
   - 本局取得、并正常带回或经交换机送回的招式机（无论来自 T 还是商店）。

以下情况**不算**有效探险：

- 局内的橙橙果、PP 补剂，不论是拾取的还是买来的（它们不会带回基地）；
- 全灭时没带出的招式机；
- 只走到出口、没有完成目标也没有新成果的空手撤离；
- 在基地进行的各种操作。

**只保留了新成果、没有完成 G**：算有效探险，但不发基础报酬。

## 基础收入

- 首次完成本局的基础目标 G，就记入基础报酬 **R = 100**。之后即使全灭，这笔钱照付。报酬在结算时进入账户，每局最多一次。
- 没有完成 G，就没有报酬：撤离、进入楼层、倒下都不发钱。

## 本轮不做"中止探险"

局内没有主动放弃的按钮。玩家要离开，只能走到出口撤离。研究中"中止视同失败"的候选，留待以后再定。

## 终局结算：按顺序一次完成

终局时（正常撤离或全灭），以下内容在同一个完整处理点里确定，并与终局记录**一起保存**。之后读档只会看到同一份结果，不会重抽，也不会重算。

1. **走失抽签（只在全灭时进行）**：终局同行名单里的伙伴逐只处理：
   - 有受保护标记的（初始成员）不会走失；
   - 其他伙伴各以 **p = 0.5（工作候选）** 的概率走失。抽签使用存档里的随机状态，结果写进终局记录。
2. **判定有效探险**，并计算本局报酬。

回到基地时，按以下顺序执行一次写入：

1. 报酬入账；正常撤离时，钱袋余额也退回账户；
2. 有效探险时，对**出发前**就在救援池里的伙伴：未付费的 L 减 1，已付费的 X 减 1；
3. 已付费、X 减到 0 的伙伴回归名册，带着原有的个人招式与配招；未付费、L 减到 0 的伙伴永久失去，记入"已失去"；
4. 本局走失的伙伴进入救援池，L = 4，从下一局开始计数；其余同行伙伴和此前回营的伙伴回到名册；
5. 本局成果招式机中，"已带回"和"已安全送回"的进入仓库，每张只入库一次；
6. **整理编队**：从编队中移除不在名册里的伙伴。主控若已不在名册，就由剩余编队成员中顺序第一只接任。编队若因此变空，就自动改为全部受保护的初始成员，并以档案记录的初始主控为主控（受保护成员永不走失，所以一定可以出发）。新流程档案回填的是初始二人；旧档案回填的是三只御三家、以 P3 为主控。

**付款窗口**：玩家只能在基地付款。剩余 L = 1 的未付费伙伴，必须在下一次出发前付款；否则那一局一旦算有效探险，它就会永久失去。基地画面对这类伙伴要醒目提示"下次有效探险后失去"。

## 救援付款

- 在基地为救援池中未付费的伙伴支付 **C = 60**（从账户扣），它的状态就变成"已付费、剩余等待 X = 1"。
- 账户不足时拒绝付款，并说明还差多少。
- 已付费的伙伴没有过期规则，一定会回归。
- 再次全灭不改变救援池里已有伙伴的状态。

## 局内商店（稀有）

- 每局在第 1 层或第 2 层，以 **35%（工作候选）** 的概率出现一个商店格。位置由生成器决定，记入存档。
- 只能用钱袋付款。每局库存固定，读档不会刷新：

  | 商品 | 数量 | 价格（工作候选） |
  | --- | --- | --- |
  | 橙橙果 | 2 | 20 |
  | PP 补剂 | 1 | 30 |
  | 招式机（从招式机池中按存档随机状态抽取一张） | 1 | 80 |

  实现补注（7.2）：这张招式机从 `dungeon.seed` 导出，开局写入存档；它仍是存档内保存的随机来源，但不消耗 `prog.rng`，以免改变既有种子上的招募序列。

- 主控站在商店格上即可打开商店。买东西不占回合，打开商店本身不改变世界。每笔交易就是一次完整的保存。
- 买到的招式机加入"本局成果招式机"列表，去向规则和 T 相同。首版不做卖出。

## 伙伴交换机（稀有）

- 每局以 **25%（工作候选）** 的概率在某一层出现，每局最多使用一次。
- 主控站在交换机格上交互，选择一名同行伙伴，该伙伴必须仍然存活，且不是主控。它立即安全回到基地。这次交互占主控的一次行动（实现补注：被送回者在主控本次行动开始时即离开，本轮不再行动）。主控本人留在局内，所以队里至少还有一名可行动的成员。
- 与研究候选相比，这里收窄了两处（工作候选，以后可以放宽）：
  - 不能送回主控，因为交互必须由主控在场完成；
  - 只能运送招式机，因为果实和补剂只在局内使用、不带回基地。
- 被送回的伙伴：不再参加本局；之后即使全灭也不会走失；本局结算时，按"此前回营者"的身份回到名册。
- 运送物资：最多 **2 份**。只能从"本局成果招式机"里选，被选中的招式机从局内持有改为"已安全送回"，之后全灭也不会丢失。全灭时的终局记录分别显示"已安全送回"和"已取得、未带出"两类。
- 交换机处理完成后，作为一个完整处理点保存。读档后不能重复使用交换机，也不能重复运货。
- 交换机不回血，也不给留下的成员补 PP。
- 留下的空位不能从基地调人，只能靠在局内再次击败敌人、触发邀请来补。

## 出发与基地画面

- **出发前**：设定本局钱袋金额，范围 0 到 min(200, 账户余额)，每档 20，默认 0（上限 200 与每档 20 均为工作候选）。这笔钱出发时从账户扣除。
- **基地显示**：账户余额、救援池（每只伙伴的状态、剩余次数和付费按钮；剩余 L = 1 的醒目提示）、已失去记录。
- **结算画面显示**：本局是否算有效探险及原因、报酬、走失名单、各招式机的去向、救援池的变化。

## 存档

档案新增以下字段，并由结构校验覆盖：

| 字段 | 内容 |
| --- | --- |
| `account` | 非负整数 |
| `rescue[]` | 实例（含个人招式）、`paid`、剩余次数 |
| `lost[]` | 已失去的伙伴记录 |
| 受保护标记 | 每个实例上标明是否属于初始成员 |
| `origin` | 初始主控的实例编号，用于空队回填 |

局内与终局新增以下内容：

- `purse`（钱袋）；
- 商店库存与交易记录；
- 交换机状态；
- 本局成果招式机列表（每张有来源和去向），用来取代原来的单一招式机字段；
- 走失抽签结果与有效探险判定。

**旧档案的迁移**：

按档案内容判定，不按创建时间判定（阶段7.1 已上线，玩家手里已有新流程建的、同样没有标记的档案）：

- 档案没有受保护标记时，P1、P2 标为受保护，`origin` 记 P1；
- 若 P3 存在且是御三家，说明是新游戏流程上线前的旧档案（新流程开局只有 P1、P2，野生招募只出非御三家），P3 也标为受保护，`origin` 改记 P3；
- 没有新字段的档案，按账户 0、救援池为空读入。

**进行中的旧局内存档**：规则版本号不升级，按以下规则迁移：旧的单一 `tm` 字段转成只有一张（去向"持有中"）的招式机列表；`purse` 记 0；本局没有商店和交换机；走失抽签和有效探险判定在终局时照常进行。没有基地档案的旧局（6.5 版之前开始的远征）里，同行的 A、B、C 视为受保护的初始成员，不参与走失抽签。

## 验收

**规则测试**（预期写成字面值）：

- 有效探险与报酬：
  - 完成 G 后全灭，报酬照付，并算有效探险；
  - 没完成 G、只保留新伙伴，算有效探险，但没有报酬；
  - 空手撤离、只取得局内果实或补剂，L 和 X 都不推进；
- 走失：
  - 受保护的初始成员不会走失（含旧档案的 P3），其余伙伴在固定种子下走失；
  - 终局读档后，走失名单不变；
- 救援：
  - 付费成功与余额不足；
  - 已付费的伙伴到期回归；未付费的伙伴到期永久失去；
  - L = 1 时，在基地付款就能避免失去；
  - 再次全灭不改变已有订单；
- 结算后的编队：
  - 主控走失后，由剩余编队成员接任；
  - 编队全部走失后，回填初始二人；
- 钱袋：
  - 正常撤离时退回账户，全灭时丢失；
  - 账户不足时，不能往钱袋里装钱；
- 商店：库存固定、读档不刷新；用钱袋付款；余额不足时拒绝；
- 交换机：
  - 只能用一次；
  - 不能选主控；
  - 被送回的伙伴之后不会走失；
  - 送回的招式机之后全灭也不丢；
  - 送回招式机后正常撤离，仓库只多出这一张；
  - 空位只能靠局内招募补；
- 旧档案迁移：
  - 旧档案三只初始御三家都受保护，`origin` 为 P3；编队全空时回填这三只、以 P3 为主控；
  - 新流程建的、没有标记的档案读入后，只有 P1、P2 受保护，`origin` 为 P1；
  - 保存于局中途的旧存档（含单一 `tm`）能读入并继续，终局后招式机正确入库；
  - 没有基地档案的旧局全灭时，A、B、C 都不会走失；
- 存档：每个新处理点都能存档往返，篡改后被拒绝。

**长测**：扩展现有长测，加入强制全灭的变体，检查：每局结束后存档都能回到"可出发"；账户永不为负；救援池的变化与规则一致；没有卡死的存档。

**浏览器检查**：用真实点击完成"完成 G → 全灭 → 有伙伴走失 → 在基地付费救援 → 下一局（算有效探险）结束后该伙伴回归"。为了让检查稳定，可以用开发者入口预置一份带救援池的存档。
