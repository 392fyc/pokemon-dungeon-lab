# PDMN：招式特效与手机布局的源码解析

本页回答本作当前要做的四个决定：

1. 与 2026-11-02 的构建 `C3KDzAd0` 相比，PDMN 新构建变了什么，[场景渲染与界面](场景渲染与界面.md) 的结论是否还成立。
2. 它怎样决定一个招式播什么动画，数据从哪来，一个招式从命中到上屏走哪条路径。伤害数字、白闪、屏幕抖动怎么做。
3. 窄屏（手机）怎样判定、怎样重排画面、手指怎样移动和选招、底部栏在手机上是什么样。
4. 招式学习和道具栏的界面怎样组织。

末节“对本作的建议”是整理者的分析，不是决定。

## 问题与结论

**术语先说清楚**：PDMN 是浏览器里的《宝可梦不可思议迷宫》同人作。它的“客户端”是浏览器下载的一组 JS 文件，页面用 Phaser（一个网页游戏引擎）画画面。下文的“分块”指这组 JS 文件里的一个文件。

### 1. 构建变化：地形、暗度、底栏的结论全部仍成立

- 新构建的入口是 `main-BMgPAbFr`，旧的是 `main-C3KDzAd0`（源码，入口 HTML 与 `capture-manifest.json`）。
- 上篇关于 DTEF 地形、8 邻位掩码、暗度场、底部栏的结论，在新构建里逐项对上了：
  - DTEF 的 48 项掩码表（`Dc`）与旧构建逐字相同；
  - 暗度数值（0.3 / 0.58 / 0.7，上限 0.9）、六组光源半径与强度，去掉压缩变量名后与旧构建逐字相同；
  - 底栏仍是“高度不小于 80 像素时 2×4 道具格，否则 1×6”，工具板仍是 网格／集合／队伍／瞄准 四个；
  - 迷宫镜头仍用 `hudBottomInset` 避开底栏；手机镜头仍固定 1.5 倍。
- 这是**源码**层面的核对，不是运行观察。压缩后的变量名没变（例如 `Oc`、`Dc`、`jc` 仍是这些名字），但行号变了，下文给的是新构建行号。

### 2. 招式特效：不是模板，是“逐招手工编排”，素材是按名字索引的帧序列

PDMN 对约 412 个招式各写了一份“编排”（下文称 choreography：这个招式先怎样蓄力，是冲过去、发射、抛出、光束还是原地，命中点放哪个特效）。编排里引用的特效素材，是按名字索引的 PNG 帧表。

**具体例子（源码）**：招式“酸液”（`acid`）的编排写着：身体动作用 `Shoot`（射击姿势）；飞行用 `StreamEmitter`（一串粒子发射器），粒子素材是 `Bubbles_Green` 的第 1、2、3、0 帧，一次射 10 个，速度 8；音效 `DUN_Toxic`；命中用 `FiniteReleaseEmitter`，在目标处向外放 3 批、每批 2 个绿泡。这些都是数据，没有一行专门为“酸液”写的代码。

动画由三层决定（源码）：

1. **逐招编排**（412 个招式：主表 393 项加追加 19 项）：飞行、命中、蓄力、音效、镜头抖动都能单独配。
2. **逐招补充**：`bf` 表 253 个招式，其中 218 个在目标身上叠一个额外特效、35 个在使用者身上叠；另有 49 个招式加“跳起／旋转／光环／着色／地震”之类的小花样。
3. **后备**：只在招式没有编排、或编排系统（`moveFx`）没有建起来时用（`n && this.moveFx` 才走编排，主分块 68245—68246），按“范围＋属性”查表决定特效。旧后备表 `Bi` 的 222 个手工特效编号，对应的招式全部也在 412 项编排里（逐键比对：222 个键全部命中），所以它只在 `moveFx` 不可用时起作用；真正没有编排的招式，实际只按属性取默认特效。

### 3. 手机布局：不是缩小底栏，而是为拇指重新排的“两角弧形布局”

手机上不显示桌面那条横栏。画面被重新分成：

- **右下角**：一个大圆形“攻击”按钮，四张招式“石”沿它左上方的一段圆弧排开；
- **左下角**：一块小面板，放 3 个道具格和“背包”宝石；
- **左上角**：生命心形和名字、经验条；
- **右上角**：三个小圆钮（菜单／等待／交谈）和一个“集合”钮；
- **中间**：消息记录夹在左下面板和右下弧之间的空档里。

手指移动有两种方式：**在地图上滑动**（出发后超过 18 个显示像素就进入“摇杆式”，8 个方向）和**点一下地图格子**（自动走过去，邻格有敌人则直接攻击）。另有可选的屏幕十字键。游戏只支持横屏；竖屏时盖一层“请把手机转过来”的提示。

### 4. 招式学习与道具栏：都是居中的模态面板；学招式是“替换哪一个”的列表，道具栏是“分类标签＋格子＋详情＋动作按钮”

- **学招式（地牢内）**：升级时弹出“新的招式”面板，顶部是学习者头像和新招式卡，下面列出现有 4 个招式（编号 1—4、名字、类别·威力、属性、PP，选中时显示说明），最后一行是“保留现有招式”。
- **道具栏**：920×536 的居中大面板，左侧队伍栏和类别标签，中间 16 格，右侧稀有度筛选和选中物品详情；动作按钮随情境变化。道具还能拖到底栏上“钉住”成快捷格。

## 二、招式特效

### 一个招式的路径（源码）

玩家在地牢里发动招式后，规则引擎先算出一份“事件”：用了哪个招式、命中哪些目标、每个目标的伤害／效果／是否暴击／是否闪避／是否倒下／能力变化。表现层才拿这份事件播动画。两条路径：

```
事件 → 地牢场景 animateMoveUse（主分块 68241）
  ├─ 有这个招式的编排，且特效素材可用
  │     → moveFxReady（按需加载素材，限时等待，主分块 68388）
  │     → animateChoreo（主分块 68310）
  │     → Fle：编排运行器（主分块 64327）
  │           蓄力前置特效 → 身体做动作，等到“出手帧” → 按招式类型飞行/冲刺/光束
  │           → 对每个目标：等飞行时间 → 命中特效 → 目标反馈 strike
  └─ 没有编排 → 后备：按“属性＋范围”查表（主分块 68250 起）
```

**数据在哪里**：编排表直接写在故事分块里，是 JS 对象，不是外部 JSON。

| 表 | 内容 | 条目数 | 位置（故事分块） |
| --- | --- | --- | --- |
| `uf` | 逐招编排的主表 | 393 | 10864 起 |
| `gf` | 追加或覆盖的编排，键名多为法语招式名（如 `bourrasque-appui`） | 19 | 23746 起 |
| `_f` | 小花样：跳起、旋转、光环、着色、命中处地震 | 49 | 24044 起 |
| `bf` | 额外叠一个特效，素材名是法语（如 `Coup_Blanc`）：218 个叠在目标身上（`Z(`206、`$(`12），35 个叠在使用者身上（`Q(`） | 253 | 24244 起 |
| `Bi` | 旧式后备表：每招手工指定特效编号，所指招式全部也在编排表里 | 222 | 1915 起 |
| `na`、`ra` | 属性→命中特效编号、属性→飞行物编号（18 个属性） | 18 + 18 | 2843、2863 |

条目数由 `grep` 统计键行得出。`uf` 与 `gf` 合并成 `Sf`，`_f` 与 `bf` 作为“小花样”并进去（故事分块 24499—24520）；`Cf(招式 id)` 取出编排（24523）。

**编排里写什么**（`uf` 里 393 项的 `kind` 分布，源码统计）：`attack` 93、`area` 75、`projectile` 73、`self` 52、`dash` 51、`throw` 33、`offset` 11、`beam` 5。每项还可含：

- `body`：身体动作名（`Shoot`、`Charge`、`Slice` 等），实际动作来自 SpriteCollab 动画表，运行器再取该动作的“出手帧”作为命中时刻；
- `fx.sound`：音效名（如 `DUN_Toxic`）；
- 发射器 `emitter`／`stream`／`tile`、`hit`（命中特效）、`explosion`、`pre`（蓄力）、`speed`、`range`、`lag`。

**发射器**是它放特效的“发生器”。种类共 20 多个（`cf` 函数的分派，故事分块 10809—10855）：`SingleEmitter`（放一个，用得最多，326 处）、`BetweenEmitter`（两点之间）、`StreamEmitter`（一串，沿飞行路线）、`FiniteReleaseEmitter`（向外爆开）、`CircleSquareAreaEmitter`（铺满范围）、`FiniteGatherEmitter`（向中心汇聚）、`AfterImageEmitter`（残影）等。（推断：这些类名与《空之探险队》自带的招式动画脚本术语一致，没有对照原作资料。）

### 素材格式（源码）

素材由 `assets/move-fx/move-fx.json` 这张索引说明，加载器按名字取三类图（故事分块 868—931）：

| 类型 | 文件 | 说明 |
| --- | --- | --- |
| 粒子 | `p-<名>.png` | 一张精灵表（逐帧网格），索引给出单格宽高 |
| 光束 | `b-<名>-head.png`、`-body.png`、`-tail.png` | 头、身、尾三张；身体沿方向拉伸 |
| 背景 | `g-<名>.png` | 整屏背景图，用 `tileSprite` 铺满并滚动，带淡入淡出和着色（故事分块 10255 起的 `Rd` 类） |

素材多方向的做法（`Rr` 函数，故事分块 933）：索引里标 `dirs`，分 `dir1`（一张图旋转 45° 的整数倍）、`dir2`、`dir5`（5 个方向，另 3 个用水平翻转）、`dir8`（8 个方向各一行）、`flip`（只翻转）。一张图复用成多个方向，省素材。

动画帧数和速度：每个动画项给 `ft`（每帧停留几个“刻”，1 刻 = 1/60 秒，`q = 60`，故事分块 9988）和 `from`／`to`（取第几帧到第几帧，同一张图可拆成多段动画，例如“酸液”把 `Bubbles_Green` 拆成四个单帧）。

另有一套更早的单图特效：`assets/effects/NNNN.png`，由 `effects.json` 给每张图的 `width`／`height`／`frames`／`fps`／`scale`／`directional`（故事分块 2829—2990）。后备路径用它，编号写在 `Bi`／`na`／`ra` 里（如 Normal 的命中是 `0147`，Feu 是 `0070`）。

**按需加载**：运行器不预载全部特效。每个编排用到的素材名由 `Tf` 收集（故事分块 24534），`Fr` 只加载还没有的，场景关闭时 `Ir` 把别的场景不再引用的素材卸掉（故事分块 903—931）。招式第一次用时若素材没到，`moveFxReady` 最多等一个固定时长再开播。

### 命中与反馈（源码）

目标每次被命中走 `strike`（主分块 68436）：

| 反馈 | 做法 |
| --- | --- |

## 三、手机布局

### 判定条件（源码）

**两个不同的判断，不要混淆**：

| 名称 | 条件 | 用途 | 位置 |
| --- | --- | --- | --- |
| “触屏模式” | 初值是 `(pointer: coarse)`（主要输入是手指）；收到手指的 `pointerdown` 置真；收到浏览器信任的 `keydown`（不在输入框里）置假；`pointer: coarse` 变化时跟随 | 决定是否显示触控按键、是否用滑动、是否锁横屏 | 故事分块 9817—9856 |
| “手机” | 触屏且 `min(窗口宽, 窗口高, screen.width, screen.height) < 540`（CSS 像素） | 决定镜头固定 1.5 倍、设置里是否出现“十字键”选项、一些版面缩放 | `phoneScreen` 72—75；主分块 66608 |

所以平板（触屏但短边不小于 540）算“触屏”不算“手机”：用触控按键，但镜头缩放仍按屏幕高度算 2—4 档整数倍。

### 画布怎样适配（源码）

`phoneScreen` 的 `b()`（87—103 行）：游戏逻辑画布的短边至少 540 逻辑像素；各场景可通过 `S(场景, 所需高度)` 申报更高的逻辑高度，但只有申报值 ≥ 580 才生效（`x = 580`，104—115 行），否则忽略。逻辑画布宽高 = 窗口 CSS 尺寸 × （所需高度 ÷ 窗口短边），并限制在 4096 以内。

**计算示例**（本页的计算，不是观察）：一台横屏窗口为 844×390 CSS 像素的手机，所需高度 540，系数 = 540 ÷ 390 ≈ 1.385，逻辑画布约 1169×540。镜头 1.5 倍时，一个图块 24 逻辑像素占 36 个逻辑像素，画面约能放下 32 × 15 个图块。

大模态面板（如道具栏 920×536）不靠拉高画布，而是自己缩放：`min(1, (宽−24)/920, (高−24)/536)`（主分块 9597—9605）。申报值各场景不同（例如 560、586、784、824，主分块 9597、37149、39178、42429），小于 580 的实际上不抬高画布，面板直接缩。

**只支持横屏**：触屏模式下进入全屏并尝试 `orientation.lock('landscape')`（主分块 51854—51875）；竖屏时盖一层全屏提示（主分块 51880—51901），提示文字是“请转动手机，游戏要横着玩，像掌机一样”的意思（法语原文在主分块 51888 行）。触控按键层也只在宽≥高时显示（主分块 28126—28129）。

### 触屏怎样移动（源码）

主分块 66990—67160，地牢场景：

1. **滑动**：手指按下后，移动超过 `18 × displayScale` 个显示像素进入“滑动操控”，之后手指相对起点的方向决定朝哪走（8 个方向）。方向判断（`sz`，主分块 27865—27870）：位移小于 `半径 × 0.5`（滑动用 0.5，屏幕十字键用 0.2）视为空；方向在原方向 ±30.5° 内不换向（“粘滞”，防抖）。换向时设备震动 6 毫秒。
2. **点按**：手指没滑动就抬起，算点按一个图块（`tapTile`，主分块 67104 起）：
   - 邻格有可见敌人：直接朝它攻击；该敌人处于“平静／被安抚”状态则改为交谈；
   - 其他格：设置 `walkTo`，让角色自动走过去（遇敌或掉血会中断，字段 `foes`、`hp`）；
   - 未探索的雷区、冰面等特殊地形有单独规则。
3. **屏幕十字键（可选）**：设置里仅“手机”才出现“十字键”（主分块 52086—52092），**默认关闭**（故事分块 24688）。开启后左下角出现一个十字键（124 像素，窗口宽度小于 720 缩到 108），并且“触摸地图不再让角色走路”（设置项说明原文）。
4. **两指拖动**：地图是大图模式时，第二根手指落下，两指一起拖动镜头（`startCamDrag`，主分块 67056—67061）。
5. **触控层是 DOM，不是 Phaser**：`pmd-pad` 是盖在画布上的一层 HTML 按钮，按下后合成键盘事件（`tz` 记录按下的键，`nz` 派发 `keydown`／`keyup`，主分块 27838—27858），所以游戏逻辑完全不用为触屏写第二套。按钮按场景切换（`wz`，主分块 27924—27940）：`dungeon`、`combe`（营地）、`menu`、`aim`（瞄准）、`none`。地牢里 `Valider`（确认）、`Attaque`、`Menu` 三个圆钮，加 `Capacités`／`Sac`／`Parler`／`Attendre` 四颗胶囊钮和“跑”开关（主分块 28100—28115）。启用手机行动栏时，攻击钮和胶囊钮被隐藏，只留“跑”（主分块 28014 的样式规则）。

### 手指怎样选招（源码）

招式“石”的触摸逻辑（`buildStone` 和 `endPress`，主分块 49924—49994）：

- 按下：开始计时 380 毫秒（`FZ`）；
- 380 毫秒内抬起：使用该招式（`useMove`）；
- 超过 380 毫秒：弹出招式说明，抬起不使用，指尖移出也取消。

“瞄准”：设置 `moveAim` 默认开（故事分块 24684）。选了招式后显示射程，再点目标格确认；进入瞄准后 180 毫秒内的点击忽略（`Sue`=180，主分块 65536），防误触。

## 对本作的建议（整理者的分析，不是决定）

**招式特效**

1. **保持“12 模板 × 18 属性”，增加一层可选的“逐招覆盖”**。PDMN 的 `pa` 函数就是这个结构：先查逐招表，没有再按范围和属性取默认。依据：本作模板数少，同模板内招式会重复；有覆盖层后，可以只给少数招牌招式单独写时间表、颜色或额外粒子，不改变其余招式。前提：覆盖项仍然只用代码画，不引入原作特效素材。
2. **命中时刻改为“动作的出手帧”**。PDMN 用角色出手动作的帧时间决定命中点，飞行时间按距离÷速度计算。本作现在是固定时间表；角色动画来自 SpriteCollab，各角色出手帧不同，固定表容易“特效到了人还没出手”。这项依赖本作能取到每个角色的出手帧；如果取不到，保持固定表。
3. **反馈参数可直接参考**：白闪 90 毫秒、击退 4／7 像素 70 毫秒往返、屏幕抖动三档（弱 0.002、普通 0.004、强 0.008）、强命中顿帧 70 毫秒、伤害数字弹出 150 毫秒再上飘 16 像素 520 毫秒淡出。数字不必照搬，但“顿帧”和“强度分档”本作的设计稿里没有。
4. **做一个“减弱动效”开关**。PDMN 多处读 `prefers-reduced-motion`（主分块 80427 等）。（推断：不影响规则，但关系无障碍。）

**手机布局**（本作手机宽度没有设计，以下是依据）

5. **“两角弧形”比“缩小桌面横栏”更适合拇指**。依据：PDMN 手机上把攻击钮放右下，招式沿它的圆弧排开，道具放左下，消息夹在中间，用同一套数据驱动，桌面横栏则只在宽屏用。本作要的是：确定手机上必须常驻的操作集合（攻击／招式／道具／菜单），再按左右拇指分区。
6. **判定分两层**：“是不是触屏”（输入方式，可随时切换）与“是不是手机尺寸”（短边 < 540）分开，平板走触控按键但不套手机版面。本作若只做网页和 Windows，仍建议保留这个拆分，因为触屏笔记本也存在。
7. **触控层用 DOM 合成键盘事件**，不为触屏另写一套输入逻辑。这对本作的好处是规则引擎和回放不需要知道输入来源；坏处是 DOM 层和画布缩放要自己对齐。
8. **滑动＋点按并存，可选十字键，十字键开时禁用地图点按**。这个互斥设计避免了误触，值得照做；默认关十字键是 PDMN 的取舍，本作可按“行动推进回合”的节奏另定。
9. **画布适配：保证逻辑短边至少 540，面板自己缩放**。本作 24 像素图块、整数倍放大的做法，与 PDMN 手机镜头固定 1.5（非整数）不同；若坚持整数倍，手机上要选 1 倍或 2 倍，逻辑画面会偏小或偏大，需要实机试。**这是需要用户拍板的取舍**（见待定事项）。
10. **只做横屏并提示旋转**，是最省事的方案；是否接受竖屏需另行决定。

**招式学习与道具栏**

11. **学招式用“替换哪一个”的列表**，附“保留现有招式”，每行显示类别、威力、属性、PP，选中显示说明。本作 G2.3 配招最多 4 招（见[游戏规则](../../../01-现行规则/游戏规则.md)），可直接参考。
12. **道具栏：类别＋稀有度双筛选、固定格数、详情区、动作按钮随情境变化；拖到行动栏钉住快捷格**。本作的“带出元素”可借鉴“持有／放下／丢弃（二次确认）”这一组动作。
