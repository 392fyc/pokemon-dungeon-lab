# 新游戏流程与界面（阶段7.1）

> **已取代**：现行内容见[游戏规则](../01-现行规则/游戏规则.md)（2026-10-31，#85）。细节公式、用户原话与当时依据仍以本页为准。

本页记录阶段7 里程碑 7.1 做了什么、做出了哪些**工作候选**、怎样验证、哪些还没验证。里程碑目标见[阶段7计划](../02-进度/计划/阶段7—可试玩EA计划.md)，可读性问题的来源见[阶段6复盘](../02-进度/自测记录/阶段6复盘.md)，基地规则见[基地与培养](基地与培养.md)。下文所有数值与选择都是工作候选，不是最终玩法裁决。

## 玩家看到的流程

1. 打开页面先到**标题画面**，有“继续”（已有存档时）和“新游戏”两个按钮。
2. 点“新游戏”：
   - 浏览器里没有存档：直接进入选角。
   - 已有存档：先弹出确认框，提示会覆盖，并提供“导出原记录”（下载原存档的原字节）、“确认覆盖”和“取消”。取消后什么都没有改变。存档无法读取时（记录损坏），必须先导出才能确认覆盖。
3. **选主控**：九种御三家（第一到第三世代）以立绘（待机动画）、中文名、属性、生命和初始招式的卡片展示，任选一只。
4. **选副手**：从其余八种里再选一只。
5. 点“开始”：写入新的基地档案并进入基地。此时才真正写存档；在此之前的任何一步取消，原存档不变。
6. 基地里整备、出发，第一次进入远征时显示一张可关闭的引导卡（移动、伙伴、撤离），关闭后不再出现。

## 工作候选与理由

| 选择 | 理由 | 待定 |
| --- | --- | --- |
| 初始档案只有主控和副手两只（不是原来的三只），第三名靠招募补充 | 用户框架提案要求“主控自选 + 初始副手”；两只让选择有分量，招募机制已能补满三人 | 是否过弱，要看7.4 平衡自测 |
| 副手只能从其余八只御三家里选，不能与主控相同 | 先用最小的“近似选择方式”；规则代码的校验也据此（`newGameProfile`） | 副手是否应来自更大范围 |
| 新游戏的覆盖确认放在选角之前，真正写入放在最后一步 | 玩家先知道后果；中途取消不留痕迹 | — |
| 开发者功能只在 `?dev=1`（或 `?fixture=`）下出现，且此时跳过标题 | 保持原有 25 组浏览器检查的入口不变，只改了页面地址 | 以后可以改成标题里的折叠菜单 |
| `?seed=` 只在开发者模式生效 | 普通玩家路径不应暴露固定种子 | — |
| 敌人信息用悬停或点击查看；敌人行为说明直接来自规则代码里的三类行为 | 点击敌人本身是普攻，所以信息面板额外支持悬停，点击也会固定显示 | 触屏上没有悬停，只靠点击 |
| 新手引导的“已看过”记在独立偏好 `trial-guide-seen`，不进存档 | 与动画偏好一样，读写都包在 try/catch 里，存储被禁用时不影响游戏 | 清除站点数据会让引导重新出现 |

“开发者模式下是什么”：固定主图、无邀请对照、旧的三人远征开局、检查初态入口、种子参数和“显示坐标”开关，都只在这里。普通玩家页面里没有这些元素（浏览器检查 7.1(a) 逐个断言它们不存在）。

## 名称

`src/data/names-zh.json` 是手写的简体中文名称表：15 种物种、18 种属性、150 个招式（名单技能表和可学清单里出现的全部招式，包括三种招式机的招式）、招式机和物品。界面上的物种名、招式名、招式机名、物品名和日志里的物种名都从这张表查；数据里的键仍是英文 id。招式显示为“撞击（强击）”：中文招式名加本作的行为类别。

来源：人工整理，依据是宝可梦系列官方简体中文译名，由代理凭记忆整理，**没有逐条对照官方图鉴库**。个别后期世代的新招式译名把握较低（`alluringvoice` 魅诱之声、`upperhand` 快手还击、`temperflare` 豁出去、`wavecrash` 波动冲、`trailblaze` 原为“开辟”、`icespinner` 冰旋、`leafage` 原为“打草”、`helpinghand` 帮助、`inferno` 炼狱）。测试只检查“每个招式都有中文名”，不检查译名对不对。（2026-10-30 主会话对上列低把握译名（另加 `chillingwater`）逐一对照神奇宝贝百科 wiki.52poke.com“招式列表”：改正 3 个——leafage 树叶、chillingwater 泼冷水、trailblaze 起草；其余核对一致。其他译名仍未逐条对照。）

## 可读性改动

- **敌人信息**：鼠标移到已揭示的敌人上（或点击固定），面板显示名称、属性、生命、伤害和行为说明（近战、远程及射程、追击）。信息只对已揭示的格子给出；未揭示的格子上的敌人没有任何信息。
- **组合草稿的执行顺序**：草稿面板显示“本轮顺序：A 小火龙 → B 杰尼龟 → 敌方”，以及每位同行本轮将做什么，默认行为会标“（默认行为）”。预演调用的是规则代码里同一个回合函数（在副本上跑，不执行）；某个动作届时不成立也会标出。
- **最近事件**：主画面始终显示最近 6 条日志（已把单位和物种换成名称）。“被谁打了”：规则日志本身只写“谁受到几点伤害”，攻击者由动画推断代码给出，所以显示“← A 小火龙（推断）”；攻击者在视野外则显示“← 视野外的敌人”。关于未揭示格子上的敌人的日志行不显示。
- **画布文字**：格子坐标默认隐藏（开发者模式可开）；单位的编号和生命值移到格子底部（脚下）一行，不再压在头部。
- **新手引导**：见上。

## 角色素材

新增的六种御三家动作图取自 SpriteCollab 的同一固定提交 `448d3af85e2cfa85a8c5ead076eddb145251b473`，每种取 Walk、Idle、Attack、Hurt、Shoot（共 12 个文件，其中 `credits.txt` 与 `AnimData.xml` 各一），清单见 `public/assets/manifest.json`，署名见 `public/THIRD-PARTY-NOTICES.txt`。六种的作者都是 CHUNSOFT（官方原图，没有授权，仅限私有构建）。六种都有 Idle、Walk、Attack、Hurt 四张表，没有缺动作，不需要替代方案。

## 验证结果

在 Windows 本机、无头 Edge 下实际运行（这不等于玩家体验验证）：

- `npm run check`、`npm test`（178 项通过，原 168 加新增 10 项）、`npm run test:acceptance`（75 项通过）、`npm run build`。
- 浏览器检查：原有 25 组继续通过（只改了页面地址：无参数的入口改为 `?dev=1`，带 `?seed=` 的入口改为 `?dev=1&seed=`），新增 3 组：7.1(a) 全新存档只用真实点击和按键走完标题、选角、基地、出发、引导、移动、重载继续；7.1(b) 已有存档时新游戏需要确认、取消后原字节不变、导出内容等于原字节、确认后才覆盖；7.1 可读性（悬停敌人信息、草稿执行顺序）。
- 原 9 种物种的数据没有变化：新测试用写死的哈希证明，哈希值是从改动前的版本在 git 里算出的，不是用新代码算的。

## 没有验证的内容

- 译名是否与官方一致（见上）。
- 触屏、小窗口下的选角界面和悬停替代方案；窗口过窄时卡片布局只看过 1280 像素宽的截图。
- 二人开局的平衡：没有长测覆盖二人档案（现有长测仍用旧的三人开局），属于 7.4。
- Windows 打包版（7.5）。
- 玩家是否看得懂引导卡和事件文字：没有真人验证。
- “推断的攻击者”在多个敌人同时可能出手时可能不准。
