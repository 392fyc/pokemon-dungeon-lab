## 安装与日常任务

安装入口为 [cloud/install.sh](https://github.com/392fyc/rea-research-lab/blob/main/cloud/install.sh)。它将 Node 安装到项目 .tools/node，核对官方 Linux 包摘要，用固定 npm 版本按锁文件安装 REA；不会自动追随最新版本。项目启动时先执行：

```bash
cd /workspace/rea-research-lab
source cloud/env.sh
```

正常解析只执行当前问题需要的步骤。相同输入和工具身份下，优先复用有效 Evidence；只有明确验收环境、输入或工具变化、出现相关失败时，才执行 `bash cloud/validate.sh`。本机 REA 日更不自动升级这份云端锁定安装。

样本放 samples/，完整证据与必要日志放 evidence/，工具安装放 .tools/，任务临时内容和缓存放 .tmp/，均被 Git 忽略。cloud/verification-latest.json 是忽略的运行状态。新增正式研究文档按当前问题交付，不把整个游戏研究库自动上传或覆盖。

官方 npm 发行包 6.7.0 与本机同版本源码的 CLI 存在差异。云端正式脚本使用已实际支持的三个 `--source-path` 和 `--format json`，将标准输出直接保存为单个完整 Evidence；不使用发行包不支持的 `--detail`／`--evidence_output`。读取时也区分单条 CLI Evidence 和 MCP 的 records 导出包。

## 普通任务的执行条件

发布后新任务核对了上述提交，检查前后工作区干净；版本、两份脚本和七份样本摘要均匹配。该任务没有重复目标分析，复用准备阶段同一源码、工具和脚本身份下的分析结果。[本机保存的新任务验收记录](../../REA_Research_Lab/.tmp/post-publish-verification.json)分别保留默认执行与单次审批结果。

MCP doctor 已在平台单次执行获批后验证：工具 **207/207**、提示 **6/6**，无缺失、意外项或重复，身份匹配，请求流程成功。默认执行的一次检查返回 Connection closed；现有证据不足以确定具体原因，也不能证明审批始终必需。普通任务遇到该错误时先保留结果，在当前工具允许的情况下，对同一官方自检命令申请正常的单次执行审批；不通过其他路径绕过限制。

发布时同时核对准备工作台的 Git 基线与执行脚本摘要。不能仅凭远端 main 已更新就断言发布快照同步；普通新任务应以实际 HEAD、工作区和脚本摘要为依据。

## 网络、账号与边界

UI 中全网访问与包管理器域名预设均关闭，保存五个自定义域名：

- registry.npmjs.org
- nodejs.org
- pokebonk.com
- github.com
- raw.githubusercontent.com

运行状态接口观测到相同自定义清单、无预设，并自动包含若干 www 别名；样本 HTTPS 请求成功。接口的策略状态仍为 **unknown**，因此只确认配置和这些实际请求，不宣称已经完成强制网络隔离验证。

没有新增用户提供的模型 API 密钥、GitHub 个人令牌或 HTTP secrets。仓库沿用现有 GitHub 连接；检出、解析与任意云端 Git 推送权限应分别判断。

安装 REA 不等于所有目标和提供方都就绪。Ghidra、IDA、Hopper、动态调试及完整游戏行为未在本次验收；后续按照具体样本与研究问题配置必要工具。当前已验证能力是公开 JavaScript 实体项目的静态解析流程。
