# REA 辅助研究路线

本技术路线维护参考项目的制作与发布研究，围绕[地牢创作目标](创作目标与地牢研究重点.md)服务于个人首版。发布经验只来自用户列出的八款浏览器游戏，研究进入试玩、版本更新、资源加载、存档恢复和反馈入口。自有 Auto Chess mod 仅用于素材、技能与系统实现参考。公开源码、发布资源和既有捕获均可使用。

当前[双云分工](../市场研究/研究范围与双云分工.md)已交付[试开发准备包](试开发准备包.md)：REA-research-lab只读核对准备仓远端来源，提出数据、保存与同步方案；pokemon-dungeon-lab整理玩法输入并核对游戏云实际只读状态。主会话整合的32931fe已审核通过，建议补充见[审核记录](../审核请求/2026-10-29-试开发准备包.md)，阶段3仍待一次开工确认；技术路线仍维护外部制作资料，环境临时任务不改变文档归属。本轮未实现、安装、同步准备仓或扩域。

2026-10-25 用户已明确：原会话以后只负责本路线；游戏审核与设计由用户另开的会话接手，两边通过文档交付。基线：[REA 范围与证据 v0.1](../审核版本/2026-10-25-v0.1/REA研究范围与证据.md)。本路线回答外部实现的具体问题，提供有版本与出处的结果，不继续承担本作玩法设计。

## 任务开始条件

有一个清楚的问题、对应作品/构建和可读取输入。游戏会话有具体问题时将其写入 `项目框架/REA研究请求.md`；本路线读取请求，交付独立结果，不直接改写请求中的本作决定。也可按用户在本会话直接给出的具体研究任务工作。先查公开文档、源码、已有解析；足够回答就停止，不为了使用工具而逆向。

PokéBonk 普通招式从数据到执行的首份静态研究已交付，入口见[普通招式路径报告](../REA辅助研究/PokéBonk—普通招式执行路径—mvnpa0xv.md)。存档与恢复研究也已交付，见[保存字段与恢复路径](../REA辅助研究/PokéBonk—存档与恢复路径—mvnpa0xv.md)；融合等低优先内容不自动加入。原作研究先选定作品和修订，公开资料能答就直接复用；没有样本时说明缺口，不把整个游戏项目标为无法继续。

## 分析方式与结论

先静态、后按具体任务决定是否需要运行观察。静态代码路径、网页观察、实际执行结果分别记录；覆盖不足时保留未知。执行目标、动态附加或新增引擎依赖，需要核对具体任务范围和工具权限，不能由“有一个文件”推断全部操作都已授权。

需要 REA 时沿实际版本的工作流，保留样本摘要和证据位置。已有 doctor 成功不证明目标受支持；没有完整执行就不宣称保存恢复、动画时序或战斗平衡已验证。普通源码阅读也可以是最终答案。

REA 自身升级、Node/npm 升级、注册修改和分析引擎安装不混入目标研究。现有日更按原授权运行；遇到真实依赖时报告所需最小处理，不自动扩成上游开发或新的维护项目。

## 向游戏路线交付什么

报告使用[审核稿中的七项格式](../审核版本/2026-10-25-v0.1/REA研究范围与证据.md)：问题、目标身份、方式与覆盖、带位置的观察、解释和未知、对本作的价值、完成或缺口。

本路线不决定本作人数、等级、成长、救援费用或首批范围，也不把代码可见误写成生产效率已知。游戏路线在自己的决策记录中说明是否采用，双方通过文件引用衔接。新会话之间的消息或任务分派由用户实际指示决定，不因写好入口就自动发送。
