# 阶段6—完整循环自测报告

这是阶段6里程碑6.6的自动化部分：让一个固定规则的“机器人玩家”把整个循环（基地、出发、远征、回基地、学招式、再出发）反复走很多遍，每一步都用程序检查。它只回答“规则和存档在长时间连续使用下会不会出错”，不回答“好不好玩”。

测试文件：`tests/core/loop-soak.test.mjs`（`npm test` 的一部分）。本报告只新增测试与文档，没有改 `src/` 下任何生产代码。

## 方法

**机器人看到什么。** 只看玩家能看到的：已揭示的地面、单位、点位、背包。不读未揭示的地形。它的固定策略：

1. 主控血量不高于 34% 且有明显更健康的同伴时，切换主控（冷却 6 轮）。
2. 同行（自己或相邻）HP 不高于一半且有橙橙果就用；有招式招 PP 用空且有 PP 补剂就用。
3. 相邻有敌人就打（优先强击，否则普攻）；同排同列 3 格内有可见敌人且有直线招就用直线；同伴受伤又有保护就保护。
4. 站在目标点上就交互；否则沿已揭示地面的最短路走向目标；路上遇同伴就换位，遇敌人就攻击；目标未揭示时走向最近的、主控没站过的已揭示格（这保证整层最终都会被看到）。
5. 目标顺序：6 步内的果实、PP 补剂（需要时的休整点）优先；然后第 1 层目标 G，下楼取第 2 层的招式机 T，回第 1 层出口撤离。
6. 邀请：同行不满就接受；已满时，奇数次拒绝，偶数次接受并让 HP 比例最低的成员回营。
7. 回基地后：对每种仓库里的招式机，依次试每只伙伴，直到学会（重复学、不兼容的会被规则拒绝）；学会后把新招式与一个行为不同的原携带招式一起携带；奇数局把最新入队的伙伴换进队伍、否则用初始三只。
8. 编号为 3 的倍数加 2 的种子（共 10 个）使用“鲁莽”变体：不吃果实、不用补剂、不切换主控，目的是增加倒下概率，检验全灭路径。

**走法与存档。** 全程用真实的 `TrialStore`（内存存储端口，接口与浏览器存储一致）。偶数号种子的第 1 局走开始页的真实首跑路径（没有档案的旧式远征，回基地时才生成初始档案），其余种子直接从初始档案的基地出发。每个种子连续 3 局。回合上限 400 轮（任务建议 300，见“发现的问题”第 3 条）。

**每一步检查什么。**

- 命令要么被接受，要么被拒绝；被拒绝时，返回的状态、存档记录、存储里的原始字节都必须与之前完全相同。机器人按候选顺序试命令，因此自然产生大量被拒绝的尝试，另外每约 9 个命令主动插入一次“此阶段本不该成功”的非法命令（例如邀请阶段发出普通回合、没有请求时发撤离完成）。基地操作同理（三招携带、空队伍、四人队伍、不存在的招式）。
- 每次保存成功后，用一个全新的 `TrialStore` 从同一存储读回，`deepEqual` 比较整份记录。
- 规则不变量：同行 1 到 3 人；所有单位 HP 在 0 到最大值之间、PP 在 0 到各自最大值之间；倒下的单位不在地图上；存活单位位置不重叠且在地面上；进行中主控存活；背包与物品计数非负；本局等级 1 到 5；档案通过 `profileProblem`；同行与回营名单不重合。
- 另有一个测试：同一种子重放两次，所有局记录和统计完全相同（确定性）。

## 覆盖范围

30 个种子、90 局，每个种子 3 局（均完成，没有一个种子少于 2 局）。覆盖：远征出发、两层之间 180 次跨层、邀请接受（含满员换人）与拒绝、本局升级、取得招式机并带回、回基地结算、学习、配招、换队伍、再出发、休整点、果实与补剂、保护与直线招、换主控、游戏中途和基地里的非法命令。

## 统计结果（本机运行，种子 30 个、每个 3 局）

| 项目 | 结果 |
| --- | --- |
| 局数 | 90（撤离 90 局，全灭 0 局，超时 0 局） |
| 每局轮数 | 平均 186.8，中位 183，最少 75，最多 319 |
| 取得第 1 层目标 G | 90 局全部取得 |
| 邀请 | 92 次：接受 28 次（全部为满员换人），拒绝 64 次 |
| 本局升级 | 共 110 次，局末平均等级 2.22 |
| 招式机 | 取得 90 次，带出 90 次，基地学会 35 次 |
| 跨层 | 180 次成功，0 次取消 |
| 道具与技能 | 果实 73、补剂 23、休整点 72、保护 2、直线 155、换主控 43 |

初版把回合上限设为 300 轮时，86 局中有 5 局（5.8%）达到上限；逐局追查两例（种子 64352 第 3 局、种子 214813 第 2 局）发现机器人一直在正常前进，只是在第 1、2 层之间来回、整层探索得太细，快到出口时耗尽回合，并非卡死。所以把上限放宽到 400，之后 90 局全部在 319 轮内结束。

## 发现的问题

长测期间**没有发现违反规则或存档的缺陷**：所有被拒命令都不改变状态，所有保存都能原样读回，所有不变量成立，没有取消的跨层，也没有机器人在局中无法继续走的局面。以下是值得主会话知道的观察（均不是崩溃或数据错误）：

1. **全灭路径没有被长测走到（严重度：低，属覆盖缺口）。** 90 局里没有一局全灭，包括 10 个“鲁莽”种子局。现象：敌人太弱，或机器人（鲁莽版也会攻击）清敌足够快。复现：任意种子，如 `loop-soak` 的 2、5、8 号（0 起算）种子。可能原因：每层只有 2 到 3 个敌人，三人同行加每局升级足够压制。全灭后的结算有 `tests/core/base.test.mjs` 的 B3 专项测试（手工构造终局）；长测不能证明全灭后连续多局的稳定。这也提示平衡上风险太低，需体验者验证。
2. **招式机在仓库里堆积、用不掉（严重度：低，设计观察）。** 现象：90 次带回招式机，只学会 35 个，最终仓库剩 55 个（旋风 28、吼叫 16、保护 11）。原因（已核实 `src/data/roster.json` 的可学清单）：每只伙伴同一招只能学一次；旋风只有飞行系小型招募（pidgey、spearow、zubat）能学，吼叫只有小火龙能学，保护几乎全员能学但学满后无处可用。仓库没有上限也没有处理办法。是否需要“出售／分解”等出口，属于后续设计决定。
3. **机器人完成“取 G、取 T、回头撤离”平均要 187 轮，最多 319 轮（严重度：信息）。** 两层小图的撤离回路较长；若体验者认为“拖”，这是数据依据。该数字取决于机器人的策略（会整层探索），不能当作玩家平均值。
4. **接受邀请全是满员换人，未出现空位接受（严重度：信息）。** 机器人的第 1 轮之后同行总是 3 人（起始就是三人），所以邀请只能在“换人或拒绝”之间选择。想要覆盖“空位接受”，需要先有倒下后换出的情形，长测没有构造。该路径是否已被现有测试覆盖，本次没有核对，列为未验证。

## 未验证项

- **玩家体验**：机器人不会觉得无聊或困惑；操作是否顺手、信息是否看得懂、188 轮一局是否合适，都未验证。
- **平衡**：全灭率为 0、升级只到平均 2 级、招式机堆积，只是机器人在当前工作候选数值下的行为，不代表真人；正式数值仍待体验者与后续决定。
- **Windows 原生与浏览器**：长测只在 Node 24.22.1（Windows 本机）里跑规则与存档层，用内存存储模拟；没有走真实浏览器存储的容量或写入失败（写入失败有 `base.test.mjs` 的 B16 专项测试）。
- **渲染与动画**：不经过 Phaser 与界面。
- 机器人没有使用“推退”招和“伙伴干预”（override）动作；这两项本次没有核对现有测试覆盖，列为未验证。
- 本报告没有更新阶段5的观察记录表（该表属于体验者观察，不由自动化填写）。
