# PAC 的宝可梦素材流水线

研究对象：[pokemonAutoChess](https://github.com/keldaanCommunity/pokemonAutoChess) 固定提交 `11446314d8d8bb0e58ff517ab50aa576dd10a3c7`。只做静态阅读，没有运行 `postinstall`、构建或任何脚本。链接都指向这个固定提交。证据分三种：**[源码]** 直接读代码；**[文件观察]** 看文件名、数量与内容统计；**[推断]** 由前两者推出，写明依据。

## 一句话结论

PAC 的宝可梦精灵和头像全部来自 **SpriteCollab**（PMD 风格精灵的社区仓库，下称 SC）。维护者在本机克隆 SC，运行一个手动脚本，脚本做四件事：

1. 读每只宝可梦的 `AnimData.xml`；
2. 把整张动作表切成单帧；
3. 用 TexturePacker 给每只宝可梦打一张图集；
4. 生成帧时长、命中延迟、可用表情和作者四份索引。

游戏运行时，Phaser 按需加载某只宝可梦的图集，用“编号/色/动作/Anim 或 Shadow/方向”这样的键播放动画。

**具体例子**：皮卡丘（编号 0025）向左下攻击时，客户端同时播放两段动画：本体 `0025/Normal/Attack/Anim/7` 和阴影 `0025/Normal/Attack/Shadow/7`。攻击动作每帧的时长是 [2,4,1,1,1,2,2,2,2,4] 个“tick”（PMD 的计时单位，1 tick＝1/36 秒），合计 21 tick。索引里存 `{"d":7,"t":21}`：d 是命中帧之前的时长之和（2＋4＋1，所以命中帧是第 4 帧），用来让伤害数字在出手的那一帧弹出。[推断，依据为按 [`edit/add-pokemon.ts#L302-L333`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L302-L333) 的算法反算]

## 1. 取得与转换（一次性、手动）

- **没有自动下载**。入口命令是 `npm run add-pokemon`（`cd edit && tsx add-pokemon.ts`）。脚本运行时，按提示输入本机 SC 仓库的路径和要加的编号。`postinstall` 只下载音乐，与精灵无关。[源码] [`package.json#L45-L55`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/package.json#L45-L55)、[`edit/README.md#L14-L27`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/README.md#L14-L27)
- **AnimData.xml** 是 SC 每只宝可梦附带的动画描述文件，记录每个动作的帧宽高、每帧时长（tick）、命中帧（HitFrame）、阴影大小，以及“复用另一个动作”（CopyOf）。脚本用 fast-xml-parser 读取它。[源码] [`edit/add-pokemon.ts#L29-L52`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L29-L52)、[`edit/add-pokemon.ts#L294-L301`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L294-L301)
- **动作**：默认切 Idle、Walk、Sleep、Eat、Hop、Hurt、Attack、SpAttack、Pose 九种；每只宝可梦可以改用别的动作名，例如皮卡丘改用 Shoot、Shock。遇到 CopyOf 时，改读被复用动作的图和时长。[源码] [`edit/add-pokemon.ts#L334-L372`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L334-L372)
- **切帧**：整张动作表按“行＝方向、列＝帧”切开，输出到 `split/<编号>/<Normal|Shiny>/<动作>/<Anim|Shadow>/<行>/<4 位帧号>.png`。[源码] [`edit/add-pokemon.ts#L406-L419`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L406-L419)
- **阴影**：SC 的阴影图用红、蓝两色标出大小两档。ShadowSize＝0 时去掉红色和蓝色，＝1 时只去蓝色，剩下的像素一律涂黑。[源码] [`edit/add-pokemon.ts#L380-L404`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L380-L404)
- **闪光与形态**：编号里的 `-` 换成 `/`，例如 `0025-0006` 对应 SC 的 `sprite/0025/0006`。闪光版按编号段数补上路径中的 `0001`；动画配置标了 `shinyUnavailable` 的跳过闪光。[源码] [`edit/add-pokemon.ts#L277-L292`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L277-L292)
- **头像**：SC 的头像目录连同其中的 `credits.txt` 原样复制到 `assets/portraits/<路径>`。[源码] [`edit/add-pokemon.ts#L534-L546`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L534-L546)。表情共 20 种（Normal、Happy…Special3）。[源码] [`app/types/enum/Emotion.ts#L1-L21`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/types/enum/Emotion.ts#L1-L21)
- **缺口扫描**：服务器有一个定时任务查询 SC 的 GraphQL 接口，只比对“SC 有、PAC 还没有”的精灵，不下载素材。[源码] [`app/services/sprite-gap-scanner.ts#L316-L318`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/services/sprite-gap-scanner.ts#L316-L318)

## 2. 打包与索引

- **一只宝可梦一张图集**：普通色与闪光色打在同一张图里。TexturePacker 参数为 `--format phaser --texture-format png8`（png8 是 256 色调色板 PNG，体积小），之后删掉 JSON 的 `meta` 字段。[源码] [`edit/add-pokemon.ts#L652-L668`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L652-L668)、[`edit/add-pokemon.ts#L473-L482`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L473-L482)
- **帧名即路径**：`Normal/Shock/Anim/0/0003` 依次是“色/动作/Anim 或 Shadow/方向行/帧号”。[文件观察]
- **构建时再压缩**：打包工具 AssetPack 的自定义插件把每帧数据压成 10 个数字的数组，输出紧凑的 `{i,s,a}` 结构，客户端再还原。[源码] [`edit/assetpack/.assetpack.js#L153-L195`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/assetpack/.assetpack.js#L153-L195)
- **全局索引**：`durations.json`（每个“编号/色/动作/类型”的帧时长）和 `delays.json`（命中延迟）。[源码] [`edit/add-pokemon.ts#L488-L507`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/edit/add-pokemon.ts#L488-L507)。`assets/pokemons` 下共 2389 个文件，其中 `0000` 是缺图用的 missingno。[文件观察]

## 3. Phaser 里的加载与播放

- **按需加载**：先放一个精灵球动画占位，再拉取压缩 JSON，还原成 Phaser 的 multiatlas（一组图集可拆成多张贴图）后加载。[源码] [`app/public/src/game/components/pokemon-sprite.ts#L1714-L1812`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/components/pokemon-sprite.ts#L1714-L1812)
- **方向**：8 个，用字符串 "0"—"7" 表示（DOWN＝0，DOWNRIGHT＝1，…，DOWNLEFT＝7），并有一张上下镜像的对应表。[源码] [`app/types/enum/Game.ts#L45-L65`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/types/enum/Game.ts#L45-L65)。“"0"—"7" 就是 SC 动作表的第 0—7 行”这一点源码没有明写，是由切帧用的行号推出的。[推断]
- **不分方向的动作**：Sleep 只有一个方向，固定用 DOWN。[源码] [`app/types/Animation.ts#L124-L127`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/types/Animation.ts#L124-L127)
- **速度**：`FPS_POKEMON_ANIMS＝36`，正好 1 帧＝1 tick（[源码] [`app/public/src/game/animation-manager.ts#L27`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/animation-manager.ts#L27)）；Idle、Sleep、Eat、Hop 循环播放（[源码] [`app/public/src/game/animation-manager.ts#L63-L141`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/animation-manager.ts#L63-L141)）。攻击动画按攻速缩放时长：`t×(0.4＋speed×0.007)/36`。[源码] [`app/public/src/game/animation-manager.ts#L425-L478`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/animation-manager.ts#L425-L478)
- **阴影**：独立的 Sprite，放在 (0, 5)、放大 2 倍、层级低于本体。[源码] [`app/public/src/game/components/pokemon-sprite.ts#L219-L235`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/components/pokemon-sprite.ts#L219-L235)
- **锚点**：没有找到读取 SC 偏移数据（Offsets）的代码。[推断] 对齐靠三件事：每帧保持 SC 原始帧尺寸；TexturePacker 裁边后用 `spriteSourceSize` 记住原位置；Phaser 默认以帧中心为原点。

## 6. 没有核实的部分

1. `PMDCollab_1`、`PMDCollab_2` 两个标签的确切条款。SC 的 README（`ca82c75`）只写了投稿默认按 CC BY-NC 4.0 授权、不接受修改 Chunsoft 原版素材，没有解释这两个标签。
2. 方向 "0"—"7" 与 SC 行序的对应，以及锚点是否完全依赖帧中心：两者都是推断。
3. TexturePacker 的版本；AssetPack 两个 fork 的 LICENSE 没有读。

## 对本作的建议（建议，不是决定）

本作已决定角色素材取自 SC、逐文件记录来源与许可，只用于私有构建（见 [CLAUDE.md](../../../../CLAUDE.md) 的当前范围）。PAC 的做法能直接回答“怎样做”，但也暴露出要避开的坑：

1. **把许可标签当成一等数据**。PAC 只记作者，不记许可。本作导入时应读 `credits.txt` 的第 4 列，逐文件写进素材清单：`Unspecified` 和作者为 CHUNSOFT 的条目单独标出，由用户决定用不用；`CC_BY-NC_4` 与 `PMDCollab_*` 按条款记署名。导入脚本发现缺标签时应拒绝导入。
2. **取 SC 时钉住提交**。PAC 在运行时从 fork 拉作者名单，名单会随远端变化。本作应在导入时把作者和许可快照进清单，并记下 SC 的提交 SHA，构建不联网。
3. **命中帧对齐值得照做**。用 AnimData 的 HitFrame 算出“出手到命中”的延迟，让伤害数字和受击动画在命中帧出现。本作是回合制，这个值可以直接决定动画队列里“受伤”一步从何时开始。
4. **方向与键名约定可以借鉴**：8 方向、“编号/色/动作/方向”的键名、Sleep 只有一个方向、1 帧＝1 tick（36 fps）。本作现有的 `facingRow`（`src/render/sprites.ts`）可以对照核实行序。
5. **缺图兜底分层**：加载中显示占位图，缺精灵用统一的缺图精灵，缺动作改用相近动作，缺表情不显示该表情。本作的 160 只阵容如果有缺动作，应在导入时就报出来，而不是运行时才兜底。
6. **代码不能照搬**：PAC 代码是 GPL-3（见 [README](README.md) 的许可边界），以上只学思路，本作要独立实现。
