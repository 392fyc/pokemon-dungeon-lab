# PAC 的地图、图块与界面素材

研究对象：[pokemonAutoChess](https://github.com/keldaanCommunity/pokemonAutoChess) 固定提交 `11446314d8d8bb0e58ff517ab50aa576dd10a3c7`（2026-10-31）。只做静态阅读，没有安装依赖、没有运行或构建。下文 链接都指向这个固定提交。证据分三种：**[源码]** 直接读代码；**[文件观察]** 看文件名、数量和图片尺寸（用 PNG 文件头读宽高）；**[推断]** 由前两者推出，写明依据。

## 一句话结论

PAC 的对战场景就是一张**原版《不可思议的迷宫》（PMD）地牢图块拼出的随机地图**。服务器先用噪声把每格分成墙、水、地面三类，再按“周围 8 格是不是同一类”选出 47 种拼接图块之一，最后交给 Phaser 的图块地图（Tilemap）显示。界面上的头像来自 SpriteCollab，道具和技能图标打成图集，属性图标是项目自己画的 SVG。

**具体例子**：一格地面，上、右、下、左四个邻居都是地面，四个角也都是地面，它的掩码就是 255，查表得到“完全被包围的内部图块”，画成一块纯地面。如果它的上方是墙，上边那一位就是 0，查到的是“上边有边缘”的图块，地面和墙之间就画出一条过渡边。

## 1. 地图怎样生成

- **随机生成，不是手画**。客户端请求 `/tilemap/<地牢名>` 时，服务器现场生成一张地图，以 Tiled 格式的 JSON 返回。Tiled 是常用的地图编辑器，Phaser 能直接读它的 JSON 格式。[源码] [`app/app.config.ts#L462-L476`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/app.config.ts#L462-L476)
- **尺寸与分类**。地图 50×32 格（[源码] [`app/core/design.ts#L49-L50`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/design.ts#L49-L50)）。对 simplex 噪声取阈值：大于 0.66 是墙，大于 0.33 是地面，其余是水（[源码] [`app/core/design.ts#L83-L163`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/design.ts#L83-L163)，阈值在第 96、98 行）。simplex 噪声是一种平滑的随机场：相邻格的值相近，所以墙、水会连成一片片，而不是零散的点。
- **强制地面**：中间的棋盘区和各种摆放位之后被改成地面，保证能下棋。[源码] [`app/core/terrain.ts#L131-L190`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/terrain.ts#L131-L190)
- **图块尺寸**：输出 JSON 的 `tilewidth`、`tileheight` 都是 24。[源码] [`app/core/design.ts#L249-L267`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/design.ts#L249-L267)
- **主题数**：`DungeonPMDO` 枚举有 143 个地牢主题（[源码] [`app/types/enum/Dungeon.ts#L160-L304`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/types/enum/Dungeon.ts#L160-L304)）；`assets/tilesets` 下有 144 个文件夹，多出的一个是城镇 `Town`。[文件观察]
- **一个小问题**：构造函数和 `initTilemap` 各调用一次 `create()`，数组被追加两次。[推断，依据为两处调用] [`app/core/design.ts#L73-L74`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/design.ts#L73-L74)、[`app/core/design.ts#L275-L276`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/design.ts#L275-L276)

## 2. 自动拼接：8 邻格位掩码，归并成 47 种

**位掩码**是用一串二进制位记录“哪些邻居和我同类”。PAC 的编码方式（[源码] [`app/core/masker.ts#L4-L16`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/masker.ts#L4-L16)）：

| 位 | 邻居 | 何时计入 |
| --- | --- | --- |
| 0、1、2、3 | 上、右、下、左 | 总是计入 |
| 4 | 右上角 | 只有上、右都同类时才看 |
| 5 | 右下角 | 只有右、下都同类时才看 |
| 6 | 左下角 | 只有下、左都同类时才看 |
| 7 | 左上角 | 只有左、上都同类时才看 |

“角只在两条相邻边都同类时才看”是关键：一个角的邻居如果两侧边已经是边缘，这个角画不画都一样。这样 256 种组合收缩成 **47 种**，也就是常说的 blob-47 方案。

- 两张表把数字变成图上坐标：`IdTable` 把掩码映射到名字（如 `A1B2C3D4`），`MaskCoordinate` 把名字映射到一个 6×8 块里的 (x, y)。[源码] [`app/config/maps/tileset.ts#L112-L160`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/config/maps/tileset.ts#L112-L160)、[`app/config/maps/tileset.ts#L5-L54`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/config/maps/tileset.ts#L5-L54)。6×8 共 48 格，47 种占满后只空 (5, 2) 一格。[推断，依据为列出全部坐标]
- **墙、水、地面三套并排**：地形编号 WALL＝0、WATER＝1、GROUND＝2（[源码] [`app/config/maps/tileset.ts#L106-L110`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/config/maps/tileset.ts#L106-L110)）。图块编号＝`y×18 + x + 地形编号×6 + firstgid`（[源码] [`app/core/tileset.ts#L160-L165`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/tileset.ts#L160-L165)）。也就是说，一张图横向 18 格，左 6 列是墙，中 6 列是水，右 6 列是地面。
- **随机变体**：80％ 的格用 `tileset_0`，20％ 从定义了这个掩码的 `tileset_0/1/2` 里随机挑一张。[源码] [`app/core/tileset.ts#L68-L87`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/core/tileset.ts#L68-L87)。变体只覆盖部分掩码，例如 TinyWoods 的 `tileset_1`：墙 38 种、水 0 种、地面 47 种。[文件观察]
- **动画**：水面等动画帧单独成图，竖着叠放。例如 `TinyWoods/tileset_0_frame0.png` 是 432×3072，即 16 帧 × 192。[文件观察]

## 3. 图集格式，与 PDMN 对照

[文件观察] `TinyWoods/tileset_0.png` 是 **432×192**，即 18×8 个 24 像素图块。这正好是一组“墙｜水｜地面”，每套 6×8。每个地牢文件夹另有 `metadata.json`，格式叫 **DTEF**（Dungeon Tile Exchange Format，地牢图块交换格式），由 [源码] [`app/config/maps/tileset.ts#L162-L197`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/config/maps/tileset.ts#L162-L197) 读取。

main 核实的 PDMN 图集是 432×1536：18 格宽、64 格高，同样分墙、水、地面三列，每列 6×8 的 47 种加 1 格空位，竖向重复 8 组。对照：

| 项目 | PAC | PDMN |
| --- | --- | --- |
| 单组布局 | 18×8：墙、水、地面各 6×8 | 同 |
| 图块尺寸 | 24 像素 | 24 像素 |
| 变体与动画 | 拆成 `tileset_1`、`tileset_2` 与帧图多个文件；变体用 `Math.random` 选 | 一张图里竖向 8 组变体；按坐标哈希选，同一格固定 |
| 来源 | PMD 原版地牢图块 | PMD 原版地牢图块 |

**已核实**（main 读 PDMN 源码并看图，见 [PDMN—场景渲染与界面源码解析](../跨项目/PDMN—场景渲染与界面源码解析—2026-11-02.md)）：两者用的是同一种单组布局（DTEF 一组＝432×192）。PDMN 按“变体数＝图高÷192”计算，1536 高就是 8 组变体竖着叠在一张图里。区别在于选变体的方式：PDMN 按坐标哈希取余，同一格每次都选到同一个变体；PAC 用 `Math.random`，每次生成都可能不同。

## 4. 客户端怎样显示

- 每张图块图按 `/assets/tilesets/<地图>/<图片>` 加载，再用 `tilemapTiledJSON` 读入地图。[源码] [`app/public/src/game/scenes/game-scene.ts#L403-L421`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/scenes/game-scene.ts#L403-L421)
- 每个图层调一次 `createLayer`，放大 2 倍，并用最近邻采样（NEAREST）保持像素清晰。[源码] [`app/public/src/game/scenes/game-scene.ts#L436-L450`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/scenes/game-scene.ts#L436-L450)
- 城镇是唯一手工绘制的 Tiled 地图。[源码] [`app/public/src/game/components/loading-manager.ts#L45-L46`](https://github.com/keldaanCommunity/pokemonAutoChess/blob/11446314d8d8bb0e58ff517ab50aa576dd10a3c7/app/public/src/game/components/loading-manager.ts#L45-L46)

## 对本作的建议（建议，不是决定）

1. **拼接算法可以照这个思路独立重写**：8 邻格位掩码、“角只在两侧边同类时才计入”、归并成 47 种。这是公开的通用方法，按原理自己写，不复制 PAC 的代码（代码为 GPL-3，见 [README](README.md) 的许可边界）。
2. **图集接口可以参照 DTEF 的布局**：一组 18×8、墙水地面三套各 6×8，加上“掩码 → 6×8 坐标”表。好处是自制部件烘焙出的图集，与社区工具的布局一致，便于检查。具体编号顺序由地形与图块规格（暂停中，等用户选定美术路线，见 [#140](https://github.com/392fyc/pokemon-dungeon-lab/issues/140)）决定。
3. **随机变体要有节制**：PAC 至少 80％ 用主图，另外 20％ 再从含主图在内的几张里随机挑，实际用到变体的比例低于 20％，画面不会显得太碎。本作宜照 PDMN 按坐标哈希选变体，同一格每次一样（PAC 用 `Math.random`，每次生成都不同）。
4. **不能用 PMD 原版图块**：PAC 和 PDMN 都直接用了原版地牢图块，本作只借鉴效果，图块要原创。
5. **噪声分区不适合本作的迷宫**：PAC 的地图只是背景，噪声阈值只保证中间能下棋；本作的通道与房间要保证连通，PAC 的生成器不能直接借鉴。
