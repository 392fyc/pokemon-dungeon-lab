# 界面设计稿

各个画面当前设计的固定位置。用户和代理讨论样式时都看这里，不用开游戏。

## 怎么看

- **网页版：** [界面设计稿](https://claude.ai/artifact/Wimv8S6LMPmif7QRr5yVFK)，地址固定，每次更新后地址不变。
- **本地：** 用浏览器打开本目录的 [index.html](index.html)。

## 维护规则

- 一个画面一页，顶部标签切换，下方写这个画面的设计要点和待确认项。
- 设计稿由 `main` 维护：改样式先改这里，用户同意后才派给 `dev` 实现。`dev` 与用户直接商定样式时，由实现 PR 同步更新这里。实现时同一个 PR 更新这里，让这份稿和游戏保持一致。
- 标“待确认”的内容不算定稿；规则以[游戏规则](../../01-现行规则/游戏规则.md)为准。
- 没有重做稿的画面放在“其他画面”，用游戏实际截图。这些截图随画面改动更新。
- 这里的改动合并后，由 `main` 把网页版重新发布到同一地址。网页版只对用户可见，含私有素材，不公开。

## 版面约定

结算页右上角保留设置齿轮，终局也能进入存档页导出。这一入口在 #194 第 1 批实现时补齐，并同步到设计稿。

经验明细按积分来源命名，不把封顶后的积分反推成伙伴或招式机的真实数量。

列表都要考虑条目放不下的情况：固定的摘要留在原位，只让列表自己滚动。标题写总数，或像结算的经验明细那样提示还有多少项。结算页的“条目溢出示例”是参照样例，其中标“示例”的奖励并不存在。
