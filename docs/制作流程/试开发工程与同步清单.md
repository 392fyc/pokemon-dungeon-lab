## 保存状态与独立重开

采用一个完整外层记录：格式版本、规则／内容／场景版本、构建身份、递增保存序号、当前试验，以及至多一份最近结束记录。底层存储应以一次一致写入替换该记录，失败保留最后成功值；具体浏览器存储选型与故障行为在阶段3实测，不把文档要求当成浏览器已保证。

| 当前试验阶段 | 保存和恢复语义 |
| --- | --- |
| 初态／普通完整轮末 | 保存完整世界；成功后可输入下一轮；恢复不重放旧动作 |
| 待邀请 | 全轮已完成，已固定邀请顺序、资源、实例、集结格和可能已成立的退出请求；恢复同一选择界面 |
| 单项邀请处理完 | 回营、入场、队列、继任、揭示、处理序号属于同一状态；成功后才处理下一项 |
| 待退出 | 所有邀请完成，请求已成立；成功保存后只执行一次终局转换，不再收行动或确认 |
| 终局 | 唯一终局ID、正常／全灭、真实同行／回营实例、目标、已取得／带出状态；恢复只展示结果 |

正常撤离将最终同行按名单归营，保留当时HP/PP；全灭保留同行倒下者及此前回营者，普通背包标未带出，不生成跨局库存。两者不创建救援／报酬／有效探险状态。无需实现正式经济字段再填假值。

保存中可以查看；普通无邀请、非终局时可编辑未提交草稿，但不能执行。写失败保留当前完整内存结果，展示最后成功点（无则明示），暂停下一动作、邀请确认、退出和重开；重试仅写这一结果，不重新结算。成功只更新提示、不自动执行输入。关闭可能丢掉最近未成功保存部分，只保证恢复最后成功点。

“开始独立试验”仅在终局成功保存后可用：把当前终局复制为最近结束记录，同时创建新runId及规格初态，作为一次一致写入；成功后才开放新地图。旧终局不会在重开时丢失；新试验不继承伙伴、培养或物资。下一次终局形成时，当前栏保存新终局，最近栏仍存上一次；再重开才以刚结束记录替换最近栏。需要更多历史证据由研究者事先归档，不增游戏历史系统。

重开写失败不能开放新试验或重写旧结果；重试同一份候选外层记录，不再生成runId。存档损坏／版本不兼容时保留原字节并停止加载，不静默迁移或清空；提供原记录导出，导出成功并明确确认重置后才能新建。它是异常恢复确认，不是每轮新增确认。开发检查用隔离存储，不能覆盖玩家记录。

同一网页来源（协议、主机、端口）下验证关闭恢复，收据记录实际来源和存储位置；不同来源不承诺共享存档。每个阶段的最后成功记录都是完整状态，不恢复半轮、半次换位或半次替换。实例回营和退出结算不能由画面重播再次触发。
