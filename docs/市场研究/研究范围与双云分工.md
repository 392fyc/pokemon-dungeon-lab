## 当前受众研究口径

核心循环与发布依据包括[核心玩法与首版范围](../玩法研究/核心玩法与首版范围.md)、[伙伴代表场景](../玩法研究/伙伴选择的代表场景.md)及[八款游戏发布经验](../REA辅助研究/八款参考游戏—发布与维护经验—2026-10-27.md)。原玩法轮次 `01a17b42-cc7a-77ae-a547-dce08f1f0e9e` 与定向补充 `01a17b49-0dd1-75b2-ba35-c80fa597bb76` 均完成；发布轮次 `01a17b43-d0fb-71e7-8c7f-82e3378e565f` 完成。发布研究使用核对摘要后的八份已有 HTML 摘录，没有扩大域名或声称完成七站新抓取。当前专项设计见文首两份新报告。

以愿意尝试、能够理解、愿意再玩和制作可完成性为主要问题。免费与开源是用户考虑中的发布方式；销量和收入仅作背景，不能替代玩家实际体验。网页与 Windows 沿用现有研究范围，不推定首发平台已定。

| 要回答的问题 | 可使用的证据 | 必须保留的限制 |
| --- | --- | --- |
| 是否愿意尝试 | 相同呈现条件下的兴趣表达、试玩开始行为 | 题材喜爱、礼貌评价与实际游玩分开；当前尚未招募或测试玩家 |
| 能否理解与操作 | 首次行动、求助、误解和行动后果的解释 | 看过教程不等于会玩；既有系列经验需单独记录 |
| 时间是否可接受 | 中断、恢复、无效重复和选择深入程度的实际观察 | 时长因玩家与内容而异，不设未经验证的统一分钟数 |
| 是否有继续游玩的理由 | 自愿再次尝试、玩家能说出的具体体验与障碍 | 一次好评不等于长期留存；不编造比例或样本代表性 |
| 能否完成并展示能力 | 有限内容的完整循环、数据/素材接入与问题定位 | 技术数量不代表作品完成度；静态代码不证明成本或运行质量 |

现有商业样本继续保留其语言、购买类型、发行年龄和平台限制，不转成统一市场份额或成功率。“自走棋没有新玩家”与“幸存者已审美疲劳”尚未获得足够证据，不作为市场定论；用户的方向偏好本身作为项目约束。

## 制作管线研究口径

模型与美术管线指资源如何从输入格式变成图集、动画或运行时模型；技能管线指技能数据如何经过目标选择、执行与表现；特殊系统研究奖励、继承、合成和持久化等真实代码路径；发布管线研究构建、托管、资源版本与兼容处理。

发布经验以用户列出的八款游戏为来源。自有 mod 只用于素材、技能和系统实现，其历史构建观察另存档，不参与本作发布建议。已经取得的八站入口捕获可作为带采样时间的文本输入交给云端分析；这不等于新抓取成功或新增域名已获准。

每项结论说明它来自公开源码、发布包静态观察、维护方说明还是运行结果。识别到 Phaser、Three.js、Rive 或某个托管域名，并不等于掌握了作者完整制作或发布流程。无法看到的建模软件、内部协作、生产成本和部署步骤保留未知。

源码样本优先固定到提交；发布包固定到采集时间、完整入口和摘要。自有 mod 使用 `pve-mode@3da223630f49893f5528e9cc7e6170befd28edec`，不把默认分支或经济肉鸽计划当作已实现模式。PokéBonk 历史 `mvnpa0xv` 报告与首页新入口 `mvpdimhl` 分别记录，不能混用函数位置。

参考入口：[八款游戏的已观察事实](../跨项目/八款浏览器游戏参考与研究优先级.md)、[自有 mod](../pokemon-autochess-mod/README.md)、[REA 历史结果](../REA辅助研究/README.md)。

## 汇总后的决策方式

先明确地牢希望提供的体验，再找会影响新玩家理解和再次游玩的主要问题，结合有限制作范围形成可检验的设计候选。没有来源支撑的市场因果、留存数字、素材许可和作者制作流程不进入结论。具体玩法与实现范围仍由后续用户决定；当前按反馈修复并准备复审，不自行宣布整体通过。
