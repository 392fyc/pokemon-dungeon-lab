# 数据导入与招式映射

阶段6 里程碑 6.2 的第一部分：把 Pokémon Showdown 的原始数据，变成本作能直接用的首批 9 种伙伴数据。本页说明数据从哪来、怎样校验、每条规则是什么、结果是什么。

**先说明什么是“工作候选”：** 名单、`maxHp` 公式、PP 换算和招式映射都是为了打通链路临时定下的数字，不是最终平衡，也不是最终名单。

## 来源与校验

- 三个文件：`pokedex.json`（物种）、`moves.json`（招式）、`learnsets.json`（谁在什么时候学会什么）。
- 下载地址：`https://play.pokemonshowdown.com/data/<name>.json`，2026-10-30 下载，对应 GitHub smogon/pokemon-showdown 的 master 提交 `ccfaa20f32af363569cd21a9d501b2bc1ded26b1`。
- 保存位置：主 checkout 被 Git 忽略的 `.artifacts/showdown/`。它们只当数据读取，不执行。
- 固定 sha256（脚本先核对，不一致就报错退出）：
  - `pokedex.json`：`e74d0364b230001fc086cefb4259e051f1d16a4730eb89f7d6336a88a0d9a47e`
  - `moves.json`：`26909a321a7e4528d14a7dffd24173aa03a6845776cf41c39cc3d76f8e14616b`
  - `learnsets.json`：`cedbe661968e2d69abe9f317e9a3f5d4f2dcf989e1f937cb0cdd72e7af29ab8f`
- 运行：`python -I tools/data/import_showdown.py`（只用标准库；`--src` 指定数据目录，`--out` 指定输出）。输出 `src/data/roster.json`（UTF-8、LF、缩进 1、按图鉴编号排序）。连续运行两次，输出逐字节相同（已核对）。
- 测试：`tests/core/roster.test.mjs`，预期值由人工对照源 JSON 手算，不调用生成脚本。

## 字段

每个物种：`id`（Showdown 标识）、`dex`（4 位编号，对应 `public/assets/characters/<dex>`）、`name`、`starter`（可选主控）、`types`、`baseStats`（原样）、`maxHp`、`kit`（初始招式）、`learnable`（本作行为可学的招式，供 6.5 招式机）、`source`。`kit` 与 `learnable` 里的每一项是 `{move, behavior, pp}`。

## 招式到本作行为的映射

本作目前有四种行为：`strong`（强击）、`line`（直线）、`guard`（保护）、`push`（推退）。按下面的顺序，先匹配到的为准：

1. **排除**：Z 招式、极巨招式，以及 `isNonstandard` 为 `CAP`、`Future`、`Gmax`、`LGPE`、`Unobtainable` 的招式。（`Past`，即后来版本移除的招式，保留，因为部分物种的时代基准较早。）
2. **guard**：覆盖表 `protect`、`detect`、`withdraw`、`defensecurl`、`harden`、`irondefense`、`helpinghand`。这是**本作改编**：Showdown 里它们大多保护自己或提升自己，本作中改为“保护相邻的另一名同行”（首次伤害减 4）。
3. **push**：Showdown 数据带 `forceSwitch` 的招式（实际为 `circlethrow`、`dragontail`、`roar`、`whirlwind`），以及覆盖表 `whirlwind`、`roar`、`dragontail`、`circlethrow`。Showdown 没有“击退”这一标记，所以这里等于那 4 个招式；如以后要把别的招式当作推退，加进覆盖表。
4. 带 `selfSwitch` 的换人类招式（`uturn`、`voltswitch`、`flipturn` 等）：**不映射**。它们让使用者离场，不是推开敌人，也不宜当作强击。
5. **strong**：`category` 为 Physical、`basePower` ≥ 40、`flags` 含 `contact`、`target` 为 `normal`。
6. **line**：`category` 不是 Status、`basePower` ≥ 20、`flags` 不含 `contact`、`target` 为 `normal` 或 `any`。
7. 其余（变化类、固定伤害 `basePower` 0、范围招式等）：未映射。

**PP 换算：** `pp = clamp(floor(showdown_pp / 10), 1, 4)`。例：撞击 35 → 3；护住 10 → 1；缩壳 40 → 4。

## 初始组合 `kit` 与 `maxHp`

- **时代**：取该物种存在升级学习（`L`）条目的最新世代。第 9 代有就用第 9 代（如 `9L1`），否则退回更早的世代（第 7 或 8 代）。各物种的结果见下表“世代”列。
- 每种行为只看升级可学的招式，取等级最低者（等级相同则按招式标识的字母序）。
- 在“守护＝强击＋保护、射手＝强击＋直线、牵制＝强击＋推退、调位＝直线＋推退”四种功能配置里，挑**两种招式都能拿到、且较晚那招等级最低**的配置（并列时看两招等级之和，再按上面的顺序）。
- 四种配置都凑不齐时，取任意两种行为中等级最低的一对；只有一种行为时只给一种。
- `kit` 内按“等级、再按 strong→line→guard→push”排序。
- `maxHp = 12 + floor(baseStats.hp / 5)`（工作候选）。
- `learnable`：该世代下**任何学习方式**（升级、招式机、教学、蛋、事件等）能学、且能映射的招式，按行为再按标识排序。

## 已知问题

- **功能配置覆盖很窄。** 只有 geodude 的初始组合满足“守护”，其余都是“射手”或单一行为；“牵制”“调位”没有一名伙伴在升级招式里拿得到推退。推退只在 `learnable` 中出现：charmander 的 `roar`、`dragontail`，pidgey、spearow、zubat 的 `whirlwind`。这是 Showdown 数据加当前映射规则的直接结果，需要在 6.5 的招式机里补，或之后调整名单、映射。
- rattata 在第 7 代升级招式里全是接触型物理攻击，没有直线攻击或保护，所以只有一种行为；spearow 的 `peck`（威力 35）低于强击的 40 门槛、目标类型也不是 `normal`，同样只剩 `pursuit`。
- 保护类招式在本作的含义与 Showdown 不同，数值（减 4）取自规格而不是数据。

## 许可与私有构建

Showdown 仓库的代码为 MIT 许可，这只覆盖代码，不覆盖宝可梦数据本身的知识产权。生成的 `src/data/roster.json` 和上游文件只用于私有构建；一旦仓库公开，已提交的生成数据即构成公开分发，必须先另行决定（见[阶段6计划](../项目框架/阶段6—完整首版最小循环计划.md)）。
