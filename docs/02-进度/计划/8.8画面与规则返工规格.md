# 8.8 画面与规则返工规格

状态：界面以 mock 为准，已固定（用户 2026-11-03 原话“先按当前来固定收束。请务必所有工作方都能参照到该 mock”）。规则改动是用户在 8.7 试玩与 mock 评审中的决定（D-20261103-01 至 -06）。实现拆分和平衡重测由 main 安排，dev 照本页和 mock 实现。

## 1. 为什么返工

8.7 用户试玩中止了：页面是“左边一块地图、右边一长列文字面板”的网页式布局，看不出怎么操作；游戏记录、队伍状态、祝福、物品都在画面外面，要滚动页面才看得到；只能上下左右走，不能斜走、斜打，走向队友会被拒绝；阴影是一格一格的方块。用户原话见第 7 节的试玩记录。

v0.1 的 8.1—8.6 只排了规则和数值，没有一个里程碑做“玩家能看懂、能顺手玩”的游戏画面。本里程碑补上这一块，并按原版探险队改正几条基础规则。

## 2. mock：所有工作方的界面依据

mock 固定在本仓库 [8.8画面返工mock](8.8画面返工mock/README.md) 目录，内容：

- `shots/`：每个画面、每种状态的截图。**先看这里**。
- `html/`：不依赖任何外部运行时的普通 HTML，浏览器直接打开就能点（标题 → 起始伙伴 → 营地 → 迷宫）。
- `source/`：用户评审时用的 Design 画布原稿（`.dc.html`），与 `html/` 视觉一致。
- `img/`：mock 用到的图片，都由仓库现有素材裁出（SpriteCollab 待机图第一帧、8.5b 苔石洞截图）。

用户评审用的在线画布只有用户能打开，不作为依据；**以仓库里的这一份为准**。mock 里的宝可梦、建筑、小地图是示意，正式实现用游戏的素材与渲染；布局、信息分区、字段和交互以 mock 为准。

## 3. 界面要求（每屏）

通用原则（用户原话：“别把画面当代码注释区”）：

- 画面里只放玩家要用的信息。不写解释性文字、括号说明、实现细节（例如“Lv5 时 HP”“拖到上面的格子里设为快捷”）。
- 游戏内的信息都在画面内，不用滚动页面。
- 招式说明在鼠标移到招式上时才显示（悬停卡）。
- 同类格子大小统一（物品格）。
- “主控”这个词不再出现在界面上（用户原话“主控这个词都不行”）；mock 用“操控中”“切换操控”，用词保持现状（D-20261107-04）。

### 3.1 标题

背景是虚化的迷宫画面；中间是游戏名；按钮：继续冒险（有存档时）、新的冒险、设置与存档；底部一排起始宝可梦。

### 3.2 选择起始伙伴

- 下方一排八只小图标，点选一只，上方显示它的详情；“就选它”确定后进营地。
- 详情：立绘、名字、属性标签；**六边图**显示六项种族值（HP、攻击、防御、特攻、特防、速度），每项一种颜色，顶点有同色圆点并标属性名和数值。
- 招式卡（每个初始招式一张），**字段各自独立**（用户原话：“技能描述范围请用范围指示器，威力，命中，描述射程，范围（作为独立字段，而不是全部塞在一个描述里）”）：
  - 左侧范围示意：5×5 格，自己在中心，面朝的一格最亮，其余可转向的 7 格较暗；
  - 名称、属性、分类（物理／特殊／变化）；
  - 威力、命中、PP、射程、范围各一栏；
  - 官方中文招式说明：悬停时显示。

### 3.3 营地（专有场景）

用户原话：“可以做一个类似原版探险队的营地场景，周围是各种建筑加一个对应的特色宝可梦。营地相当于一个专有场景。”

- 整屏是营地场景：中央营火，出发阵容站在营火边；北面是迷宫入口（进入即出发）。
- 营地是一张原创底图（`public/assets/camp/base.png`），四周四座建筑：伙伴小屋（出发阵容与名册）、仓库（招式机与碎片）、天赋石碑（探险队成长）、记录板（上一局结算与战绩）。只有两位看守，站在各自建筑门口：伙伴小屋的吉利蛋、仓库的卡比兽；天赋石碑与记录板没有看守（用户原话：“NPC只保留左上吉利蛋和右上卡比兽，左下右下去除”“更靠近各自对应建筑的门（站门口）”）。
- 点建筑或看守在画面内弹出面板，不离开营地；有看守的面板左侧是看守头像，上方一句台词。
- 左上：探险队等级、远征次数；右上：菜单。

### 3.4 迷宫画面（按 PDMN 的画面分布）

用户原话：“前面做素材我就说明过 PDMN 的基础画面内容分布已经是合理的了”。

- 地图铺满底栏以上的整个画面。
- 左上：三名队员卡片（头像、名字、血条），每张卡下面一行增益／减益（绿为增益、红为减益）；**点卡片切换操控**；正在操控的那张高亮。
- 右上：小地图、楼层、轮数。
- 右侧：委托与祝福追踪。
- 左下（底栏上方）：最近几条消息记录。
- 右下：**快捷键说明**（只列按键：WASD 移动，同时按两个键走斜向；1—4 招式；5—0 六个快捷物品；Tab 切换操控；B 背包；用户原话“移动不是wasd吗？”，具体键位是 main 的初稿），半透明小卡（用户原话：“快捷键放在右下，卡片半透明，类似 PUBG 里游戏中的操作说明一样，可以小一点”“右下是快捷键说明，不是操作说明”）。
- 底栏只放当前操控的那一只：
  - **全队共享经验条**在头像上方（“队伍 LvN”）；
  - 头像、名字、血条；
  - 4 张招式卡，**按属性着色**，只写招式名、属性、PP，不标快捷键；悬停显示招式说明卡（同 3.2 的字段）；
  - 6 个**快捷物品**格，大小统一；
  - 背包按钮。
- 背包：上面一排 6 个快捷物品格，下面是全部物品，**按分类**（标签：全部、树果、补剂、招式机、其他）；在背包里调整哪些物品放进快捷格。
- 阴影：见第 4.6 节。

## 4. 规则改动（用户决定）

| # | 改动 | 取代 | 决策 |
| --- | --- | --- | --- |
| 4.1 | **8 方向移动**；斜向相邻也算 1 格，普攻与“面前一格”类招式可以朝斜向放；斜向移动与斜向攻击**不能穿过墙角**（两侧任一是墙即不可） | G5.2 “移动只有上下左右四方向” | D-20261103-02 |
| 4.2 | 走向队友所在格时**交换位置**，占一次行动 | 走向队友被拒 | D-20261103-02 |
| 4.3 | **PP 改用官方探险队数值**（每招各自计数，每用一次扣 1），不再用 floor(本传 PP÷10) 限 1—4 的压缩 | `tools/data/import_pokedex.py` 的 `pp_for` | D-20261103-03 |
| 4.4 | **命中与附加效果按官方**：招式有命中判定；附加效果（例如火花的灼伤）按官方实现 | G5.1“全部命中，没有附带的概率状态” | D-20261103-04 |
| 4.5 | **官方中文招式说明**以神奇宝贝百科（52poke）为数据来源，私有构建内使用，逐条记来源 | 无 | D-20261103-05 |
| 4.6 | **视野按原版**：在房间里整间可见；在走廊里只看身边一圈。**阴影画法**按 PDMN 的暗度场加光源（每格暗度平滑放大成遮罩、同行身上带光圈、暗处带地形色调、视野变化平滑过渡；见 [PDMN 场景渲染与界面源码解析](../../06-研究/参考项目/pdmn/场景渲染与界面.md) 第二节） | G4.4 走廊“四方向各 4 格直线加两侧” | D-20261103-06 |
| 4.7 | 界面按 PDMN 画面分布返工，以本页 mock 为准 | 现行开发检查页式布局 | D-20261103-01 |

## 5. 影响与重测

- **敌人 AI、寻路、射程判定**都要改成 8 方向并处理墙角。
- **PP、命中、附加效果、异常状态、存档迁移**：玩家可见规则见[游戏规则](../../01-现行规则/游戏规则.md) G5.1、G5.5、G5.13、G8.2、G9.1、G9.2、G9.3、G9.4、G11.4；数据与迁移实现细节见[实现备注](../../05-制作流程/实现备注.md)第 1、5 节。
- **平衡**：8.6 的首领倍率 4 与守护折合 2 是在旧规则下校准的，以上改动后统一重测、重新校准（用 8.6 的长测机器人与并行校准方法，见[实现备注](../../05-制作流程/实现备注.md)第 8 节）。
- **长测机器人**：要会 8 方向移动、换位、处理命中失败与状态。

## 6. 待定（由用户决定）

- 营地是否可以走动（mock 是点建筑）。
- 速度：用户提出“速度高的先行动”（讨论），改动大，后置到 8.8 之后；8.8 内速度变化不生效（见[游戏规则 G5.5](../../01-现行规则/游戏规则.md)）。
- （main 待核对，非用户决定）官方招式数据里有 `cutsCorners`（能否斜向越过墙角）字段；用户的决定是“斜向不能穿过墙角”，没有例外。若要让个别招式按官方值越过墙角，需另请用户决定。
