# 创作目标与地牢研究重点

本页依据 2026-10-27 用户最新说明，作为当前创作目标与研究范围入口。目标是完成一个能体现个人设计、制作和交付能力的游戏，并让更多玩家喜欢；变现不是核心。用户已明确沿救援队式探索／肉鸽地牢继续，当前先设计核心玩法与适合个人开发的首版范围，重点研究伙伴在探索和战斗中的选择。

## 用户确定的范围

| 项目 | 当前范围 |
| --- | --- |
| 创作目的 | 通过完整作品证明自己的能力，同时争取真实玩家的喜爱；不能只以收入、品类规模或技术数量评价项目 |
| 主要方向 | 救援队式探索、肉鸽地牢；本轮形成核心循环、伙伴选择与首版范围候选 |
| 自走棋 | 不作为本作方向；自有 mod 只提供素材、技能与系统实现参考 |
| 发布经验来源 | 用户列出的八款游戏；不以自有 mod 的构建或部署配置推导本作发布方式 |
| 卡牌构筑 | 不纳入本作候选；不由此推断所有卡牌游戏都比地牢复杂 |
| 幸存者 | 不作为当前优先方向；保留有用的技能、素材和表现技术参考 |
| 时间与学习成本 | 研究新玩家上手、一次体验的时间投入和能否中断；不先写死单局分钟数 |
| 当前优先问题 | 按阶段路线收敛试开发假设、短规格与开工准备，再在获准后用可玩片段检验伙伴选择和操作负担；两个云环境分工，主会话汇总，本轮只交付计划 |
| 首版数量 | 物种、功能模板、招式与层数先作预算，不急着冻结；已定三人同行规则继续有效 |
| 免费与开源 | 用户正在考虑的发布方式，尚未选择许可证或授权公开仓库、发布游戏；不将其视为第三方知识产权许可 |

用户对自走棋竞争、学习意愿和幸存者审美疲劳的担忧，是需要验证的受众问题。当前范围直接遵守用户偏好，不需要先证明这些品类没有市场。既有商业市场报告继续作为背景，不能代替作品目标或将不愿制作的品类重新排到前面。

## 成功应怎样观察

以下是从目标导出的研究问题，不是已测结果或正式验收阈值：

1. **能完成。** 是否能让有限内容形成从开始、探索、选择到结算的完整体验，而不是靠不断增加系统维持吸引力。
2. **能上手。** 不熟悉救援队的玩家是否知道眼前要做什么，能否判断行动后果；哪些地方必须查表或依赖讲解。
3. **有自己的体验。** 玩家能否说出一个具体、值得再次尝试的玩法理由；宝可梦题材吸引和玩法吸引分别记录。
4. **尊重玩家时间。** 是否能方便地开始、暂停和继续；失败后是否理解损失与下一步，而不是承担不明原因的重复劳动。
5. **能展示制作能力。** 可以解释设计取舍、内容怎样进入游戏、遇到问题怎样定位和修复。开源或展示代码的价值来自可理解、可维护的实现，不来自技术堆叠。

“更多人喜欢”先研究如何扩大进入门槛内的受众，不承诺适合所有玩家。是否重点面向宝可梦爱好者、地牢玩家或没有相关经验的玩家，仍需通过小规模体验观察缩小范围。

## 当前设计建议

当前将伙伴价值落实到编队、选路、站位、技能使用与继续深入的具体取舍。优先让同一套能力同时用于探索和战斗，首个可玩片段用于检查选择是否成立，首版完整作品还需接通招募、撤离、失败恢复和基地培养。

现行候选见[核心玩法与首版范围](../玩法研究/核心玩法与首版范围.md)。本轮[跟随与倒下通路](../玩法研究/伙伴跟随与倒下通路.md)推荐倒下从地图退场、跨层仍可替换，所有新人共用本批固定集结格入场；[招募资源与伙伴取舍](../玩法研究/招募资源与伙伴取舍.md)容许同功能健康新人明显有利，以仍可用的配招体现旧人同行价值，不新增忠诚或招募惩罚。五种共用行为、两层迷宫和有限名单仅用于预算，不把数量估算变成必须达到或不能超过的规格。

[完整小探险](../玩法研究/一段完整探险的连续推演.md)当前用紧凑目标与成果出口，减少清场后的长赶路和回头；可取得并请求撤离，仍承受完整轮。保留旧远攻和换健康前排承伤是两条可完成的路线，无邀请也能基础退出。[探索节奏与操作简化](../玩法研究/探索节奏与操作简化.md)分开世界轮、伙伴覆盖、切主控和界面输入；[玩家操作](../玩法研究/玩家操作与中断恢复.md)采用普通单步直接执行、伙伴组合提交、保存成功无确认。当前只有纸面核算，实际误触、节奏和趣味尚未验证。

现有三人队等地牢约束继续按既有记录使用；v0.7中的细则、数值和纸面推演不因资料合并自动获批。PR #1和PR #2已复审并经用户批准合入研究基线9ca775a。当前按[阶段路线图](从研究到试开发的阶段路线图.md)组织后续工作：准备包 → 开工确认 → 运行骨架 → 单层可玩片段 → 体验复盘；本轮只交付计划。完整培养、救援经济和连续区域在试开发后另排，不阻挡当前核心验证。玩法建议见[首片段方案](../玩法研究/返程与招募的首片段方案.md)，精确规则以[规则表](../玩法研究/当前规则表.md)为准。

## 免费、开源与素材边界

2026-10-27 核查的 Pokémon Support 官方说明（页面更新于 2026-01-30）要求不要将其角色、名称和设计等知识产权用于或关联到项目，没有给予免费同人游戏的一般许可。[官方说明](https://support.pokemon.com/hc/en-us/articles/360000634094-Can-I-use-Pok%C3%A9mon-images-or-materials)

美国版权局对合理使用的说明也明确：非商业用途只是考量因素之一，并非所有非商业用途都构成合理使用。这是美国规则的说明，不能直接作为其他地区的许可或本项目合法性结论。[官方说明](https://www.copyright.gov/fair-use/more-info.html)

因此，不能把“免费开源”写成已规避版权风险。自己的代码、带有上游许可义务的代码、角色名称与形象、图片、音乐分别核查；只能授予自己有权授予的许可。技术上将内容数据和素材与核心逻辑分开，有助于维护与未来替换，但这种结构本身不提供法律许可。本轮不修改仓库可见性或许可证。

## 云端分工

- pokemon-dungeon-lab：核对纸面研究的结束条件、试开发规格与体验观察的顺序；后续实现须在开工包获准后进行。
- REA-research-lab：核对准备仓、依赖、占位内容与真实素材数据接入的阶段边界；发布研究仍以八款参考游戏为来源。
- 主会话：整合阶段路线、维护当前决定和正式入口，提交研究PR；不把计划中的检查写成已执行。

用户已授权持续研究、文档提交和更新现有 PR，常规细化、必要补例、结果整合和交付连续完成，不按每个小步骤停下来询问；以一段完整可核对的设计结果组织工作。只有影响授权、关键方向或无法合理判断的必要选择才需要澄清。网络扩域、游戏实现、公开发布及合并仍按原边界处理。研究候选无须先改写成用户裁决才能继续推演。

受众与技术适配依据见[地牢新玩家体验与制作验证](../玩法研究/地牢新玩家体验与制作验证.md)。当前没有真实玩家测试结果。
