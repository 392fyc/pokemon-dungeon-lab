# 新内容制作与发布流程

这是后续开发的候选流程。当前只整理方法与制作卡，不进入游戏实现。用户确定的目标是随机地牢和轻度撤离带出，是否采用融合等组合系统仍未决定。[[项目目标与当前决策]]

采用[分阶段范围](../项目框架/分阶段范围与扩展顺序.md)：每批交付一个能独立运行的循环或有明确用途的内容扩展。Z 晶与 Mega 延后；不为将来系统提前制作专用货币、空界面和整套适配。首批伙伴先检验基础招式、入队等级与 HP/PP，以及带回后个人招式学习的归属。

## 先判断新增内容的工作类型

| 内容类型 | 首要工作 |
| --- | --- |
| 已有行为上的角色或招式 | 配置数据、必要素材、获取与遭遇来源 |
| 参数与条件例外 | 说明覆盖项及对既有强化、AI 的影响 |
| 全新行为或系统 | 定义事件、状态、界面和存档语义 |
| 组合内容 | 明确输入、资格、消耗、继承与结果 |
| 新环境 | 同时定义地形规则、遭遇与视觉提示 |

同一批次可以包含多类工作，但不应按条目数量估计完成度。一个使用已有行为的招式，与新增一种位移或场地反应的成本不同。

## 用内容卡连接数据、素材和玩法

每项内容使用[[制作流程/内容制作卡模板]]，连接[[制作流程/数据整理与招式适配流程]]和[[制作流程/角色素材与招式特效流程]]。先让一组代表内容走完流程，再用已确认的共用能力扩展名单。

若选择融合，候选说明与实际执行应对同一组输入和资格负责。分字段写明继承规则，避免统一“保留强化”掩盖伤害、等级和槽位含义的差异。PokéBonk 的新实例会从等级 1 开始，是需要单独检查成长结果的具体例子。[[pokebonk/融合资格与强化继承]]

## 检查完整冒险中的行为

检查范围围绕新增行为与真实交互确定：

- 招式能否正确选择目标，范围、遮挡和敌我关系是否一致。
- 伙伴与敌人能否识别使用价值，是否会在明显无效时使用。
- 新效果与已有状态、地形及强化怎样组合。
- 界面说明、范围提示与实际结算是否一致。
- 获得、消耗、撤离、失败和再次出发时，伙伴与物品的含义是否明确。
- 需要保存的内容能否在相同规则版本下恢复。

这不是当前已经执行的测试清单。具体检查取决于届时批准的内容与实现。

## 更新和反馈

一批内容围绕一个明确体验组织，例如某种环境与相应的伙伴、招式和战利品，让玩家能理解新增价值。对问题记录版本、地图种子、阵容、招式、物品和关键行动，再决定修复范围。

PokéBonk 的融合上线后仍修复强化、额外弹数和显示，说明新系统的成本包括与已有内容的连接。竞技场的场地专题则说明单项能力也能形成清楚展示。发布频率与视频频率都不能代替实际生产效率。[[pokebonk/更新节奏与内容生产]]、[[pokemon-arena-2d/开发进展与内容生产]]

来源资料或规则更新时，先核对差异与存档影响，再决定采用，不自动改变已经带出的伙伴或物品。返回：[[制作流程/数据素材与内容制作总览]]。
