# 自有 mod 构建配置的历史源码观察

本页仅归档固定提交 `3da223630f49893f5528e9cc7e6170befd28edec` 的既有源码观察，证据定位见[管线索引](../../REA辅助研究/参考项目—管线证据索引—2026-10-27.md)。当前项目发布研究以用户列出的八款游戏为来源，本页不作为本作发布方式、托管或版本策略的推荐依据。

这里的“自有mod”不表示上游代码、素材或宝可梦形象归用户所有，观察构建配置也不授权复用；当前许可边界见[目录说明](README.md#许可与权利边界)。

`package.json:24–52`定义：

- 客户端由esbuild构建，服务端由tsc构建。
- 素材有独立assetpack步骤。
- postinstall包含音乐下载和素材工具依赖安装。

`esbuild.js:10–61、94–143`定义哈希命名模板、压缩、sourcemap、外部`/assets`，清理旧入口并向HTML替换实际产物名。这是配置证据，不是一次成功构建记录。

`Dockerfile:1–30`定义安装/音乐/assetpack、构建、复制dist和Node运行的容器路径，暴露9000端口。另一条PM2配置仍指向上游仓库及`origin/prod`，不能当成392fyc mod的真实部署配置。PM2解释器24.11.1与Docker基础20.18也不同，不能未经运行记录判断哪条生产生效。

运行侧有Express静态资源与Colyseus房间定义。缓存分为：

- JS/CSS哈希；
- 图集包版本；
- assetpack递增版本和Service Worker缓存名。

`app/public/dist/client/sw.js:1–80`对GET的`/assets/`或`/SpriteCollab/`使用cache-first，激活时删除旧缓存；只缓存成功且非206响应。这不能证明用户浏览器实际注册成功或CDN响应头如何配置。

静态推导的发布风险包括同版本号重打资源、旧页面引用已删除入口、旧客户端对新Schema不兼容。CI触发、实际托管、灰度、回滚和存档迁移均未核验；某个`deploy.yml`路径404不能证明没有CI。
