# 随机楼层与跨层

阶段6里程碑6.3（见[阶段6计划](../项目框架/阶段6—完整首版最小循环计划.md)）的实现说明：一个带种子的楼层生成器，一张两层的“远征”迷宫，以及楼梯跨层与返回。规则沿用[当前规则表](当前规则表.md)的R02—R11，本页不新增规则；凡规格没写、实现时必须决定的地方，都标为**工作候选**，集中列在第6节。

## 1. 一句话说明

“种子”是一个整数。同一个种子加同一个层号，生成器每次都画出同一张图；换种子就换图。第1层有出口、目标G和下楼梯，第2层有上楼梯和成果T。主控走到楼梯格点一次确认，本轮结束时还活着并站在楼梯上，就换层。回到旧层时，旧层的敌人、血量、已取得的东西和已看过的格子原样保留。

## 2. 生成器（`src/core/dungeon.ts`）

输入：种子、层号、参数（宽20、高14、总层数2）。输出：地面格、楼梯、交互点、敌人初态。不依赖引擎，不读存储，是纯函数。

做法分五步，每一步的随机数都来自同一个确定性的随机数发生器（mulberry32，由“种子＋层号”混合出起点）：

1. 在地图内放5—7个房间（宽3—6，高3—5），房间之间至少隔一格墙，不贴地图边框。
2. 每个新房间用一条L形走廊接到随机的一个更早的房间，再随机多接一条形成回路。因为是“每个房间都接到更早的房间”，整张图必然连通。
3. 从第一个房间的中心出发做一次路径距离计算，离它最远的房间放下楼梯。
4. 第1层第一个房间中心放普通出口（也是队伍的起点）；第2层第一个房间中心放上楼梯。G（第1层）和T（第2层）放进既不是第一个房间、也不是楼梯房间的房间。
5. 放敌人：第1层近战＋远程各1，第2层再加1个追击。不放进第一个房间，离所有楼梯和交互点至少2格，离入口尽量远（先试6格，不行再试4、2）。

所有层的楼梯、交互点、敌人互不重叠；一个种子下“第2层”不依赖先去过第1层，所以不管走访顺序，结果一样。这也是“返回时不重抽”的基础：未去过的层到第一次进入时才按种子生成，去过的层存在存档里，不再生成。

敌人的战斗数值沿用主图人工档：近战 HP16 伤害4；远程 HP6 伤害6 射程3；追击 HP6 伤害3。物种从`src/data/roster.json`的非首发物种中抽取（只影响显示与ID），不引入属性克制。

## 3. 远征内容

| 层 | 内容 |
| --- | --- |
| 第1层 | 起点＝普通出口；基础目标G（取得并继续／取得并撤离，规则同主图G）；下楼梯；近战1、远程1 |
| 第2层 | 上楼梯；成果T（规则同主图T）；近战1、远程1、追击1 |

“一个继续选择”＝在G处选“取得并继续”还是“取得并撤离”，以及是否下楼；“普通出口”＝起点的出口；“有限战利品”＝只有一份T。队伍沿用主图的A、B、C，C为主控；本模式没有邀请事件（引擎仍支持，规则测试里用手工敌人验证了邀请与跨层同轮发生的次序）。

## 4. 跨层与返回怎样执行

**请求。** 楼梯是新的交互点种类（`down`／`up`）。主控站在楼梯格上，只有“请求跨层”一个选项（`interact`且`exit:true`；`exit:false`被预检拒绝并说明原因）。界面上与出口一样先弹一次确认。这一轮的主控行动就此用掉。

**轮末（R09）。** 次序没变：完整执行本轮 → 全灭优先按失败处理并取消请求 → 原交互者还活着且还在楼梯格才成立，否则取消（行动不返还）→ 处理同轮邀请 → 保存“待跨层”完整处理点，再执行**一次**转场。

**转场（R10）。**

- 来源层整体收进存档的`dungeon.stored`；目标层从`stored`取出，没去过就按种子生成。
- 存活主控进入目标层“对应楼梯格”（下楼进上楼梯，上楼进下楼梯）。
- 其余存活成员按固定队列依次入场，位置见工作候选①。倒下成员不占格，只随名单。
- 不改队列、不恢复血量和PP、不增加行动、不加轮数、不插入敌方阶段；转场后下一次提交才开始正常一轮。
- 入口格被敌人占着，或任何存活成员找不到合法格：整个转场取消，只清掉请求；动作已用，留在来源层，一切原样。

## 5. 存档（R11）

`World`新增可选字段`dungeon`：`{seed,width,height,floors,level,stored}`。`stored`保存所有已去过且不是当前层的楼层：地面、已揭示格、该层全部敌人（含已被击败的）、交互点及其“已取得”标记。当前层仍用原有的`floor/seen/enemies/points`字段，所以老存档与固定主图的存档字节与语义都没变。

新增阶段`transit`（待跨层），与`exit`同类：它是保存下来的完整处理点；恢复后只执行一次`finishTransit`，不重放那一轮。界面在保存成功后自动完成这一次转场。

`src/core/save.ts`的结构校验新增：`dungeon`与`scenario:'expedition'`互为充要；种子、尺寸、层数、当前层号范围；每个存储楼层的地面、揭示、敌人、点的合法性与全局ID不重复；请求落在楼梯点上当且仅当带`to`，且`to`正好是相邻层；`transit`必须有锁定且带`to`的请求，`exit`不得带`to`。不合格的存档按原有“原字节保留、导出后明确重置”处理。

版本号：**没有提升**。新字段可选，旧存档完全可读；兼容性：固定主图存档双向兼容；旧版本程序只认识 goal、item、exit 三种交互点，读任何远征存档（每层都带楼梯点）都会当作结构损坏，保留原字节、走“导出后重置”路径。是否提升 `RULE_VERSION`，让旧程序提示“版本不兼容”而不是“结构损坏”，记为待决定项。存档校验另外拒绝楼梯与楼层不符的点：非远征不得有楼梯，第1层不得有上楼梯，最后一层不得有下楼梯，出口只在第1层（2026-10-30 审查补充）。

## 6. 工作候选清单（规格未定义，实现时的决定）

1. **跨层落点顺序。** R10只说“进入预留合法格”。实现：主控进入口格；其余存活成员按队列，各取以入口为起点、按右→下→左→上逐层向外的广度优先顺序中第一个“已揭示且无存活单位”的格。已揭示指主控站到入口后所见（四个方向各最多4格，墙遮挡，存活单位不遮）。理由：与R08的“本格→右→下→左→上”一致并向外延伸。后果：入口被敌人占着相邻格时，跟随者可能落在敌人身后（测试X3）。
2. **入口＝成对楼梯格本身。** 到达目标层时站在对面的楼梯上；第1层的起点是普通出口。因此一到达就可以再点楼梯回去（要花一个行动）。
3. **入口被敌人占着也取消。** R10只说“无合法位置”；这里把“入口被存活敌人占据”算作无合法位置。
4. **转场取消时清除请求并回到`playing`。** 没有额外惩罚。
5. **楼梯不标已用。** 楼梯可无限次使用，每次都是一个主控行动加完整一轮的风险。
6. **敌人只在所在层行动。** 被收起的层完全冻结（含追击敌人）；回到旧层时敌人在离开时的位置。
7. **迷雾。** 远征中未揭示的地面不画（主图仍画暗格）；理由：随机图若画出全貌就失去探索。
8. **地图尺寸、房间数、敌人数、敌人数值与物种。** 全是人工候选，不是平衡结论。
9. **种子来源。** 界面默认每次远征随机取种子；`?seed=整数`可固定（用于浏览器检查）。重开“独立试验”时同样按此规则再取。


补充说明（审查意见）：跟随者落点搜索没有半径上限。返回旧层时，若入口附近都被占用，跟随者可能被放到较远的已揭示格；这与 R10“返回不是免费传送”的精神有张力，后续可限定半径（例如入口周围两圈），找不到就取消转场。

## 7. 画面

远征的格子固定40像素，镜头每次重绘时居中到主控并夹在地图范围内；点击换算使用镜头偏移后的世界坐标。固定主图和所有检查初态仍用原来的整图缩放显示。楼梯暂用现有出口图标加蓝色着色并标“上／下”，没有新美术。

## 9. 未验证与已知限制

- 没有做大样本的“随机图上通关率”或平衡测试；敌人在狭窄走廊里可能堵路，浏览器检查只用了一个已确认可走通的种子。
- 追击敌人的路径不受视野限制，一进入第2层就开始逼近（沿用现有行为）。
- 没有自动化的画面截图对比，镜头和迷雾只通过浏览器检查的点击与截图人工查看过。
- 邀请事件没有放进远征的随机敌人里；邀请加跨层的次序只在规则测试中验证。
- 仅在 Windows 本机、Edge 内核浏览器上运行过；未在 Linux 或其他浏览器验证。
