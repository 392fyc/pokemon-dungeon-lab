# 项目目标与当前决策

最近更新：2026 年 10 月 29 日。当前创作目标与用户范围先读[创作目标与地牢研究重点](项目框架/创作目标与地牢研究重点.md)：沿救援队式探索／肉鸽地牢继续，以完成作品展示个人能力并争取玩家喜爱为目标，变现不是核心；不做自走棋，不考虑卡牌。三人同行是已定上限，物种、招式、层数等数量只作预算。发布经验仅以用户列出的八款游戏为来源，自有 mod 仅作素材、技能与系统参考；免费开源仍是意向，不等于取得代码、素材或宝可梦知识产权许可。

PR #1—#3已合入main，当前研究基线为06cf1c0。[试开发准备包](项目框架/试开发准备包.md)覆盖阶段1—2，PR #4已改为面向main；32931fe已审核通过，后续建议补充见[审核记录](审核请求/2026-10-29-试开发准备包.md)。精确通用候选统一到[当前规则表](玩法研究/当前规则表.md)，本试验参数与输入见[短规格](玩法研究/单层试开发短规格.md)。推荐临时采用可返回、奖励型邀请、半额资源，服务点与经济暂不启用；正常／全灭保存真实结果，之后从独立初态重开。Vite作为推荐打包工具纳入同一次开工确认。这些不等于正式整备、走失、损失比例或最终玩法裁决；阶段3仍未开工。

本页曾是v0.7冻结来源，采集时的原字节保留在固定提交中，按[来源定位](审核请求/v0.7来源定位.json)核验；当前入口更新不改写原来源清单。

当前工作授权：维护阶段1—2准备包及必要提交和PR；准备仓与云环境只读核对。PR #3合并已完成，PR #4与开工分别处理；本轮未同步快照、安装依赖或开始游戏实现。准备包集中列目标、临时基准、范围和检查方式，开工前一次确认，获准范围内连续执行。[替换、携物与回营v0.7](审核版本/2026-10-26-v0.7/审核入口.md)保留为历史候选，研究审核不自动批准最终平衡。

当前方向：[三人队当场替换与营地待机 v0.6](审核版本/2026-10-25-v0.6/审核入口.md)，人数范围沿用[首版三人队 v0.5](审核版本/2026-10-25-v0.5/审核入口.md)。用户已明确第一版以三人队为基准，局内也不扩至四人；四人队只保留为未来更新候选，不进入首版研究。成长、控制与具体数值仍为候选，按三人范围继续。已有走廊与操作证据见[v0.4](审核版本/2026-10-25-v0.4/审核入口.md)，其他框架按该范围使用。

## 已确定的方向与技术决策

- 制作能够独立运行的游戏，面向网页或 Windows；暂不考虑移动端和 macOS，正式首发端仍待决定。
- 采用二维迷宫风格，以每局随机探索的肉鸽地牢为主体，包含伙伴、招式机和特殊物品等跨局带出的轻度撤离元素。
- **第一版以三人队为设计与验证基准；四人队仅保留为未来更新候选，不进入首版研究。** 初始二人恢复能力继续保留，基地名册不因此限定为三名。三人队可当场替换成员，下场成员回营地待机并保留个人培养。具体出发配置、行动成本、携物和回营整备另行研究。
- 战斗采用行动推进回合：玩家行动后，敌人与伙伴推进，停下来可思考。速度、行动代价和顺序未定。
- **未付费走失伙伴的救援期限按后续有效探险次数计算。** 用户已明确选择；离线和停留基地不扣次数，哪些探险有效仍待决定。
- **救援队等级解锁更危险、收益更高的任务，玩家选择风险与收益，或选择低风险路线和安全撤离。** 救援费用与对应产出共同增长，占比以可承受、保留成长吸引力为目标；具体数值尚未验证。
- 可以采用 Pokémon Showdown 数据库；首批使用某个时代基准下的有限子集，优先覆盖多样种类。50% 是先前讨论例子，世代、具体数量和名单未定。
- 用户喜欢 Big Kid Nation 的 Pokémon Arena 2D 角色视觉样式；最终尺寸、视角与动作规格未定。
- 当前为初期框架构建，尚未开始游戏功能实现。按已有研究、数据和素材基础，参考 Mercury 辅助 SoT 的职责与证据组织方式，见[研究与制作运行方式](项目框架/研究与制作运行方式.md)。
- 用户允许将有效探险与基础收入方案 B 作为候选继续研究，并继续授权沿基础勘探、分段撤离、深入奖励的方向设计具体迷宫任务样例；允许长线研究、不频繁停止询问。已授权范围内的检索、比较、文档维护与必要审查自主推进；实质方向分歧集中说明。
- 已按用户授权选定 Phaser 4 + TypeScript，版本基线 4.2.1；网页用于开发验证，Windows 使用 Electron 封装。尚未创建游戏工程，依据见[引擎决策](技术选型/二维迷宫引擎决策.md)。
- 用户已授权游戏专用 Codex Cloud；环境 pokemon-dungeon-lab 的发布与复用检查、本机 REA 工具链结果记录在[工作环境说明](工作环境/REA与CodexCloud.md)。配套私有准备仓库为 392fyc/pokemon-dungeon-lab，本轮没有更改云环境。
- 继续研究 PokéBonk 与 Pokémon Arena 2D 的内容、方法、新系统和公开更新所反映的生产方式。
- **Z 晶与 Mega 延后作为扩展更新研究；首批先让招募、成长、恢复、撤离与基地培养形成完整循环。** 每阶段都应能独立成立，不先铺全部大型系统，见[分阶段范围](项目框架/分阶段范围与扩展顺序.md)。
- 日常答复直接报告发现和取舍，不反复提醒默认的 Obsidian 维护方式与当前工作阶段。
- 用户已于 2026-10-25 明确会话分工：另开新会话继续[游戏路线](项目框架/游戏项目路线.md)的审核与设计，原会话以后只负责[REA 辅助研究](项目框架/REA辅助研究路线.md)，两边通过文档交付结果。此决定确认职责和交付方式，没有批准尚待审核的玩法候选。普通源码/格式研究属于游戏路线，不把全量逆向作为首批前置。
- 研究库是 pokemon-dungeon-lab 仓库的 `docs/`，作为 Obsidian vault（2026-10-29 用户决定并入，旧研究仓库归档）。以主题目录、索引、标签和关联链接管理；文档随任务在 worktree 中修改并走 PR，不用 Computer Use。

## 用户当前框架提案

- 主控以历代御三家自选，不做性格测试；初始副手采用近似选择方式。
- 初始主控和副手不走失，但不强制出战；伙伴充足时自由编队，普通伙伴全部走失时可用二人继续探险。
- 击败非 Boss 敌方宝可梦后，均有概率愿意加入；全灭时随行普通伙伴可能走失并进入救援池。
- 未付费伙伴有期限，长期不救会永久失去；付款后立即免除永久消失风险，等待固定 X 次探险必定回归。付费救援没有再次失败。
- 玩家等待期间再次全灭，不对池内伙伴再次判走失、不取消旧救援；多只伙伴分别处理。
- 没钱时靠基础收入；收入来源、条件和数额还需设计。
- 救援队等级与任务、产出、风险的关系按上述已明确方向展开；等级成长、任务档位、救援费率和具体走失率继续设计。
- 全灭丢失大部分物资，仅保留一小部分受保护物品，参考保险箱概念。
- 迷宫内可以有类似变隐龙商店的商店，以及伙伴交换机：让某名队友提前安全撤回并带少量物资，该成员不再参加本局后续战斗。用户已明确装置出现概率不高、主要为了防止该伙伴走失；继续探索的队伍会因此少一份战力，补位必须再次击败合格敌人并实际触发概率邀请。具体概率、载量和使用次数仍未定稿。
- 用户提出按招式、道具强化材料、宝可梦培养材料等探索方向设置不同迷宫类型；Z 晶主题保留为后续扩展候选，具体材料在形成用途后分批研究。
- 用户提出无尽迷宫，每若干层是一类区域、有 Boss 守关；十层一区域是举例，具体层数、奖励和跨区规则保留为候选。

细则与来源归属见[伙伴招募与委托救援框架](玩法研究/伙伴招募与委托救援框架.md)、[救援队等级与失败成本](玩法研究/救援队等级与失败成本.md)。

## 代理建议的归属

用户允许保留的 B 候选包括：完成目标才发一次基础报酬，达标后失败仍发；目标完成或保留新增跨局成果才计有效；免费短基础路线提供恢复入口。中止、最后付款窗口、报价锁定、身份保护与共享保护袋等细则继续研究。**候选保留不等于数值或实装定稿。** 方案与恢复推演见[有效探险与基础收入](玩法研究/有效探险与基础收入.md)。

沿用户允许的方向，候选让基础目标兼容普通冒险前段，保留零资产二人的最低配置；每段保证出口，继续不额外发工资或推进救援，深段提供伙伴生态、招式用途和战术变化。细化见[三组迷宫样例](玩法研究/迷宫与任务样例推演.md)。

[商店与伙伴交换机](玩法研究/迷宫商店与伙伴交换机.md)以用户明确的低概率保伙伴定位为前提，优先比较每局至多一个生成机会和一次使用、送回一人、最多两份物资、至少留一名可行动成员、同局不召回、无额外现金收费。装置立即安全保存所选成员和物品，普通出口不自动存货；整局结束再统一发报酬与推进 L/X。商店使用局内钱袋且不透支工资。这些限制与保存顺序均为代理候选。

[队伍人数与满员招募](玩法研究/队伍人数与满员招募.md)按首版三人范围继续。当前用户已明确可当场替换成员，下场回营地待机，个人实例和培养保留；已有伙伴和本局新伙伴的去向都按这一方向衔接。具体行动与物资细则另行设计，不能自动把营地远程调入、整队恢复或携物安全运输一并视为已批准。

[伙伴探索价值](玩法研究/伙伴探索价值与迷宫分工.md)通过射程、保护、控制、恢复、机动和信息改变探索决定；按奖励分型不要求某个物种才能开门。[无尽迷宫](玩法研究/无尽迷宫分区与守关规则.md)以十层一区域展开纸面例子，Boss 守继续入口、战前保留普通出口，跨区不增加基础工资或 L/X 次数；区域数量不刷新装置机会。

[新伙伴与基地培养](玩法研究/新伙伴入队状态与基地培养.md)优先研究共享本局等级、个人永久招式库：新人不必单独补等级，老伙伴保留已学配招；永久个体等级仍是重要对照。约 60% 生命、三招部分 PP、基地消耗招式机后永久学习与免费重配，都只是纸面起点。[无尽恢复](玩法研究/无尽迷宫恢复与局内成长.md)比较有限补给与每区一次小额休整，成长、恢复和最终救援计数分别处理。首批不同时引入饥饿、疲劳、熟练度和多套材料链。

[费用与等待](玩法研究/救援费用与等待次数推演.md)以最低净收入 100、单只费用 40/60/80、L=4、统一 X=1 作低负担起点，并保留 C=60/100、X=1/2 的对照；不是已批准费表。继续记录短局恢复更快、多人集中到期和连续走失的限制，不保证任何损失都能全部救回。

“付费必定回归”“再次全灭不影响旧救援”“普通伙伴全失仍能两人出发”“基础收入”和“自由编队”来自用户当前提案。不得再将它们作为代理新发明的待授权功能。按有效探险计期限是用户已选项；目标门槛、成果判定与基础路线目前作为 B 候选继续细化，不视作已实现或已验证。

L = 4、X = 2、费用 100、完成基础目标后净收入 100 等仍保留为[规则顺序与较重负担对照](玩法研究/有效探险与基础收入.md)，不是正式数值；只保留新成果而未达标的有效局不会自动领这笔收入。公开游戏案例支持局部参照，不能证明本作经济与体验已经成立。

招式共享行为、按进化系挑选阵容、配方化组合等制作选项见[内容生产方法](跨项目/内容生产方法与开发启示.md)。后续实现前须将最新裁决同步到云端研究副本；当前没有自动同步、实装或运行验收结论。
