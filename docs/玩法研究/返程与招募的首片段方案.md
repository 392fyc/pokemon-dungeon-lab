# 返程与招募的首片段方案

本轮建议：**出口可以返回，招募可以是一份明确奖励，选择集中在谁继续同行、怎样接近威胁，以及现在是否值得深入。**首个验证片段先不依赖交换机、商店或完整救援经济，用一张短地图和少数共同输入验证这些关系。

这是在已合并研究基线之后形成的新候选，不是用户已经批准的玩法，也不是开始实现。三人上限继续有效，其余数量只是本次研究预算。完整首版仍需要更广的探索、培养、失败恢复与交付工作。

## 从目标推导出的取舍

用户希望个人能完成、能展示能力，并让玩家喜欢。当前优先减少需要记忆的规则和没有新信息的操作，同时保留能解释的选择。由此本轮先回答几个直接问题：

| 问题 | 推荐 | 具体依据与限制 |
| --- | --- | --- |
| 要不要用单向门强迫深入 | 保留可返回旧出口，保持状态 | 首见R后只用1轮返程纯移动；继续到第8轮受伤后，B已在G上，可原地请求撤离，1轮结束且无新增伤害。独立的出口被敌占用例限制安全性，未验证所有地图 |
| 每次招募都要纠结吗 | 不要求；招募主要是实例奖励 | 同功能新人和撤离前邀请有明确收益，不能靠费用或培养损失强造选择 |
| 旧人价值来自什么 | 眼前可用的配招、资源和位置；回营保留另计 | 保留远攻可一轮处理；也能接受新人而替别人，两轮处理并保留远攻。不是只剩接受/拒绝二选一 |
| 交换机必须在首片段吗 | 后置，长期保人/运货研究保留 | 有邀请时保人职责重叠；无邀请或运货是独立价值，但需额外状态与用例 |
| 新人资源用哪套算 | 现行纸面输入统一半额；60%只作敏感性对照 | 10与12HP在两次5伤害后结果不同，比例尚无真实平衡依据 |
| 免费整备怎样处理 | 明示为比较假设，不新增出发治疗费 | 不夸大终局残血的长期代价；不治疗当前探险，不解救救援池成员 |

可返回、邀请定位、交换机完整首版去留和整备方式仍需用户最终采纳。本轮已足够给出推荐和反例，无需先把候选写成裁决才能继续研究。

## 玩家经历与首片段边界

建议以后先验证以下一段闭环：看清队伍用途与基础目标 → 处理入口遭遇 → 比较真实邀请 → 在正常出口决定结束或探看 → 根据新见威胁改变计划 → 带回结果。招式机属于哪名实例、换下者是否保留，须在结果中可解释。实际学习并再次出发是后续接通培养闭环的工作，本轮没有完成其运行验证。

| 范围 | 首片段建议 | 本轮已有证据 |
| --- | --- | --- |
| 控制与战斗 | 三人、现有普攻与少量特殊行为；一主控加一次伙伴干预 | 规则表及已复审路线，不增加智能战术 |
| 探索 | 一张短通道，基础出口与成果出口；统一揭示，不靠门槛封回头 | [6/9/11轮对照](可返回出口的探险对照.md)；地图和视野是研究输入 |
| 招募 | 固定已知实例与确定邀请/无邀请对照；并排显示资源、配招、落点 | [五类输入](招募奖励与服务点取舍.md)及同图同打法对照；固定邀请不是自然招募率 |
| 正常与失败结果 | 区分同行、已回营、倒下、物资与未保存结果 | 规则表定义倒下者仍随同行名单正常归营；本图返回路线没有成员倒下，不作为倒下归营验证；不填入未定救援价格和走失率 |
| 保存 | 需要验证时按完整处理点恢复，不重抽或重复结算 | 结果要求已整理，尚无实现或平台测试 |
| 服务与经济 | 首片段不启用交换机、商店、旧救援订单计时 | 单独保留经济反例；不把简化片段叫作完整首版 |
| 内容规模 | 只用足以检验当前问题的实例、敌人和地图 | 不冻结最终名单、房间数或层数 |

一张地图先检验同层返回。跨层替换、旧层入口与保存仍保留规则和纸面案例，但不为了让首片段看起来完整，直接加入第二层、随机生成或服务点。若实现阶段选择只做其中一部分，须明确哪些尚未交付。

## 本轮能支撑的结论

1. **回头不必是一段长赶路。**新图三条路线分别为6轮结束、9轮探看后结束、11轮取物结束；首见R后返回有一次切主控和1轮返程移动。继续到第8轮受伤后也可切B原地使用G，第9轮结束，后续不再受伤；该布局保留了便宜的退出方式。
2. **有新信息不代表探看必然值得。**已知地图且确定不拿物品时，直接退出更省3轮。观察价值必须来自改变计划，不能给探看额外工资来维护表面选择。
3. **招募不会自动创造原队没有的解法。**保留C与N替C都能让B承伤；接受增加实例、改变资源和配招。应该用同一打法对照，不能把B原有能力算给新人。
4. **保留旧人的功能与接纳新人可以同时成立。**独有远攻局面中，接受Q并替A/B可以保留C，两轮处理射手；拒绝一轮处理更快。这是有明确成本的不同结果，不是必须拒绝才能保留旧价值。
5. **部分邀请可以严格有利，经济却有例外。**撤离前接受有收集收益；但目标前的新成果可能推进旧救援期限。后者是结算候选的后果，不应藏在招募说明里。

这些结论限于列明输入与现行规则。没有穷举所有策略，也没有证明真实玩家喜欢、自然邀请密度合适或首版经济成立。

## 下一轮应验证什么

| 可证伪的问题 | 观察或检查方式 | 不能冒充的结论 |
| --- | --- | --- |
| 玩家能区分已知与未知后段吗 | 让其在G及首见R时说明当前信息和选择理由 | 文案写了“不确定”不等于理解 |
| 返回是不是又一段无效劳动 | 分开探看、纯移动、交互、干预和切主控；记录求助与重复安排 | 世界轮少不等于更有趣 |
| 玩家理解新人与旧人的区别吗 | 记录资源、功能、保人、收集四种理由；是否误以为新人成长复制 | 一次接受不等于喜欢系统 |
| 一重要路线是否始终只耗新人 | 同一地图下比较实际连续邀请与无邀请，不假定未来一定招到 | 少量邀请上限或概率低不自动解决滚动补给 |
| 草稿与直接动作会混淆吗 | 检查先安排伙伴、切主控清草稿、非法输入不推进 | 语义计数不是实测误触率 |
| 目标前成果推进旧期限是否好解释 | 独立列目标、实例、现金、有效次数与旧订单，不先扩建完整经济 | 不把收集奖励暗改为无副作用定理 |

本轮先完成纸面推导；未来真人观察不预设比例或分钟阈值。没有因为尚未试玩就回避已有算术和规则矛盾，也没有用算术代替试玩。
